## 0. 开发方法论与纪律（贯穿全系列）

### 0.1 开发节奏（每任务四步 TDD）
① 写失败测试 → ② 跑通失败 → ③ 实现 → ④ 跑通 + commit。提交用 Conventional Commits + 版本前缀（如 `v5.1 (5.1.0-1): feat(research): 研究历史持久化`）。

### 0.2 硬性纪律
- **版本纪律**：APP_VERSION 单一来源（backend/main_new.py）；tag v5.1.N.M ↔ APP_VERSION 由 CI gate 守护；前端 dist 产物入库（`npm run build` 后提交）。
- **改动纪律**：每任务改动文件 ≤3 个/次，修改后立即验证；前端冒烟 0 pageerror 为金标准。
- **令牌纪律**：新 UI 一律 var(--...)；运行时代码 getCSSVar()||'#hex' 兜底并标注 qc-allow-hardcode。
- **数值纪律**：全站数值最多保留 2 位小数（研究页新指标统一走 `fmtNum`，禁止裸浮点插值）。
- **术语纪律**：全站统一术语（「评估/策略研究/复盘」），新文案不得回退（测试守护）。
- **依赖纪律**：只改 requirements.in → uv pip compile；锁文件不漂移（CI 校验）。
- **安全纪律**：新端点 deny-by-default；新存储字段纳入备份兼容；AI 生成 PTrade 代码保持沙箱校验。
- **独立运行**：每版本结束 = 全量测试绿 + 双端（dev/ops）冒烟 0 pageerror + Docker 可构建 + 文档同步。

### 0.3 开发流程（每版本）
1. 版本分支（直接 master + tag，沿用现有模式）→ 2. 任务按序开发（TDD）→ 3. 全量回归 + 门禁 → 4. tag v5.1.N.M 推送（触发 CI + Docker）→ 5. ops 同步 + 重启 + 健康检查 → 6. 归档报告 + 更新 skill/README。

### 0.4 估时口径
- 以 V5.0 节奏（8-10 天/版）为基准，5.1 研究域任务偏重研究逻辑与测试，估 **6-9 天/版**，总计约 **40-50 天**（含测试与发布）。
