## 0. 一句话结论

**工程化程度很高，视觉方向也对，但"品牌金"被当成了底色而不是点缀色**——这是当前几乎所有具体问题的共同根因。
设计 token 体系（321 个 token、0 悬空引用、阴影只用 2 个值、过渡 77 处统一 0.2s）已经达到中上水平；
真正拖后腿的是：**品牌色面积失控、中性色族混用、次级字号下沉到 12px、移动端多处元素重叠、以及少量遗留的历史蓝色**。

## 1. 配色系统

### 1.1 【P0】品牌色面积失控——页面底色就是品牌渐变

`css/themes.css` (body 规则)：

```css
body { background: var(--gradient); }   /* 品牌三档渐变铺满整个视口 */
```

实测各页"品牌金色像素占比"（HSV S>0.15 且色相 ±40° 内）：

| 页面 | 中性色占比 | 品牌色占比 | 平均饱和度 |
|---|---|---|---|
| 策略总览（今日一屏） | 60.4% | **38.1%** | 29.5 |
| 智能评估总览 | 52.6% | **45.7%** | 34.8 |
| 短线复盘 | 55.8% | **40.9%** | 33.7 |
| 系统状态 | 63.9% | **35.0%** | 25.2 |
| 系统配置（内容少） | 38.8% | **60.3%** | 44.7 |
| 美林时钟 | 74.0% | 13.6% | 17.4 |
| **登录页** | — | **~100%** | — |

`ui-visual-design` 规范：中性 70% / 主色 20% / 功能色 10%。当前主色在多数页面**超配 2–3 倍**。

**视觉后果**：白色卡片漂浮在深金色场地上，卡片要么"亮得刺眼"要么"融进背景"；
内容少时（系统配置、登录页）露出大片纯色渐变，呈现"色块屏"而非"界面"。

**建议**
1. `body` 底色改用中性表面 token：`background: var(--qc-background);`（#fcfaf7 / 暗色 #0b1220）。
   —— 该 token 已存在，但全项目**只在 nav.css 用了 1 次**，语义表面被绕过。
2. 品牌渐变只保留给"需要被强调的小面积"：主按钮、激活页签、徽标、进度条填充、AI 悬浮球。
3. 登录页改为：中性/极浅底色 + 品牌渐变作为**局部装饰**（如左侧品牌区或顶部一条 4px 品牌条），而不是整屏铺色。

### 1.2 【P0】历史蓝色残留：`--primary-color-dark`

`tokens.css:201` 定义 `--primary-color-dark: #2563eb`（Tailwind blue-600），且 **themes.js 从不覆盖它**（暗色块覆盖成 #3b82f6）。
被 3 处引用：
- `themes.css:3937` `.ai-fab { background: linear-gradient(135deg, var(--primary-color), var(--primary-color-dark)) }` → **右下角 AI 悬浮球渲染成"金→蓝"渐变**（截图为证：`fab-light.png`），在整站金色语境里像一个异物。
- `layout.css:731 / 736` `border-color: var(--primary-color-dark)` → 两处蓝色描边。

**建议**：删除该 token（或令其 = `--primary-color` 的更深档），把 FAB 改成单色品牌渐变；暗色块的 #3b82f6 同步清理。

### 1.3 【P1】两套中性色族混用

实测同一亮色页面里同时存在：

| 暖中性（当前设计意图） | 冷中性（遗留） |
|---|---|
| `#f7f4ee` ×61、`#fcfaf7`、`#efe9df` | `#f1f5f9` ×29、`#f5f7fa` ×26 |

典型：`.focus-action-bar`（#f1f5f9）、`.focus-row-dir` 方向标签（#f1f5f9）压在暖色卡片上，肉眼可辨"灰得不一样"。

暗色同理：自定义海军蓝 `#101a2e` ×113 / `#16233b` ×96 **与** Tailwind 灰 `#111827` ×31 / `#1f2937` ×29 并存
（`.detail-split-list`、`.focus-row` 用 #111827，卡片用 #101a2e，明暗与色相都不同）。

**建议**：统一到 `--qc-neutral-*` 一套暖中性（暗色用同族冷海军蓝），把 `#f1f5f9/#f5f7fa/#111827/#1f2937` 全部替换为 token。

### 1.4 【P1】功能色缺乏语义一致性（装饰性用色）

统计卡片实测：左边缘 4 种颜色（蓝/绿/琥珀/橙）+ 4 个同色系图标底：
`650 交易日总数`(蓝)、`2605 覆盖股票数`(绿)、`4 选股策略数`(琥珀)、`0 当前在池股票`(橙)。
——"覆盖股票数"用绿色并不传达"成功"，只是换个颜色。功能色被当装饰用，稀释了真正语义色（涨红跌绿、警告、错误）的信号强度。

**建议**：卡片图标统一用品牌色或中性色；功能色只保留给"涨/跌/警告/错误/信息"五类。

### 1.5 【P2】状态点 `.qc-status-dot.is-info` 固定 #2563eb

金色主题下满屏蓝色信息点（每页 12 个）。属于语义色，可接受；但建议把"信息"色改为中性蓝灰，与暖色主色更融洽。

## 2. 明暗主题与对比度

### 2.1 亮色 `--gradient` + 白字：不达 AA（默认金色主题命中）

16 处使用 `background: var(--gradient)`（body / .nav-item.active / .user-avatar / .badge / .login-icon / .hold-days / .kline-tab.active / .ma-toggle-btn.active / .status-tab.active / .stat-icon / .time-bar-fill / .progress-bar / .consensus-badge / .record-number / .sub-nav-tab.active / .user-menu-avatar）。

三档白字对比度（计算值）：

| 色相 | 三档白字对比度 | 最差档 |
|---|---|---|
| **45 金（默认）** | 5.58 / 4.16 / **2.74** | ✗ |
| 220 蓝 | 11.50 / 9.34 / 6.66 | ✓ |
| 0 红 | 10.49 / 8.49 / 6.06 | ✓ |
| **140 绿** | 4.99 / 3.71 / **2.43** | ✗ |
| 270 紫 | 12.74 / 10.65 / 7.86 | ✓ |
| 320 粉 | 9.80 / 7.83 / 5.51 | ✓ |

**实测渲染像素对比度**（文字居中，落在渐变中段）：
- `.status-tab.active` 322×36，白字 14px → **4.03:1**
- `.kline-tab.active` 62×38，白字 → **3.60:1**
→ 均**未达 AA 4.5:1**（正文级）。默认金主题 + 绿色主题是重灾区。

**建议**（任一，建议组合）：
- 把渐变整体压深一档（如 `hsl(h,80,22) → hsl(h,74,30) → hsl(h,68,38)`，成本最低、影响面最大）；
- 或让这 16 处改用**实色**品牌 700 档 + 白字；
- 或把文字从"白"改成按背景明度自适应（复用 V5.29 的 `_panelL` 求解器思路）。

### 2.2 暗色渐变端点风险

暗色 `--gradient` 三档 + 深字最差档：紫 1.72 / 蓝 1.89 / 红 2.18 / 粉 2.34 / 金 3.97 / 绿 4.47。
文字多数居中落在中段（实测 7.86–8.57:1，通过），**但任何靠左/靠右对齐或大面积的渐变元素，文字会落到暗端而失效**。
另外暗色下 `.ai-fab` 实测最差 **2.68:1**（浅色图标压在金色端）。

**建议**：暗色渐变改为"深端浅、浅端中"的双档（避开与深字冲突的暗端），或暗色下渐变元素一律用浅底 + 深字（与 V5.29 面板同策略）。

### 2.3 表面分界线对比不足

| 元素 | 对比度 | WCAG 1.4.11 期望 |
|---|---|---|
| 亮色卡片描边 `--card-border` hsl(45,55,82) on #fff | **1.34:1** | ≥3:1 |
| 暗色边框 `#2c4060` on 卡片 #101a2e | **1.66:1** | ≥3:1 |

亮色卡片目前靠"金底 vs 白卡"区分，一旦底色改中性，卡片将**失去边界**。
**建议**：把卡片描边提到 ≥3:1 的暖中性（如 `--qc-neutral-300` #ded5c6 = 1.6:1 仍不足，需再加一档或改用极浅阴影 + 8px 圆角统一）。

### 2.4 已经做得好的部分（保持）

- 暗色 **不是**用透明度糊弄：`--text-primary #e6f1ff` / `--qc-card #101a2e` / 独立边框色，对比度 15.2:1 / 7.8:1，达标。
- `prefers-reduced-motion` 有处理（1 处）。
- 主题过渡统一 0.2s（77 处），换主题不突兀。

## 3. 排版

### 3.1 字号：主字号下沉

实测可见文本节点字号直方图（亮/暗一致）：

| 字号 | 节点数 |
|---|---|
| **12px** | 64 |
| **13px** | 53 |
| 16px | 27 |
| 14px | 18 |
| 15px | 8 |
| 18px | 2 |
| 22px | 2 |

- 全场只有 **7 级**（规范建议 ≤4 级）。
- **12px + 13px 合计 117 个节点**，是出现最多的两档 —— 中文在 12px 下发虚，长时间阅读（复盘、持仓列表）吃力。
- 14px（base）反而只有 18 个节点，说明"基准字号"形同虚设。

### 3.2 15px 越标尺

标尺为 12/13/14/16/18/22/28/36，但 CSS 里有 **6 处 `font-size: 15px` 字面量**：
`header.css:211,246`（顶部页签）、`nav.css:98,275,341,358`（导航/子导航）。
即"一级导航"和"顶部页签"用的是标尺外的字号 —— 恰恰是最该标准化的两处。

### 3.3 行高与字距

- `line-height` 出现 **7 种**值（1 / 1.2 / 1.3 / 1.4 / 1.5 / 1.6 / 1.7），未走 `--lh-*` token。
- `letter-spacing` 出现 7 种（0.01em / .5px / .2px / 1px / .3px / .02em）——**中文不应加正字距**。

**建议**：收敛为 `12 / 14 / 16 / 20 / 28` 五档（辅助 12、正文 14、强调 16、区块 20、页面 28），
导航/页签从 15 → 14，行高只留 1.3（标题）/1.6（正文）两档，中文全部 `letter-spacing: normal`。

## 4. 布局与栅格

- 结构清晰：侧栏 220px + 内容区（子导航条 + 卡片流），桌面端**重叠检测 0–2 处**（且均为 svg 与文字的正常包含关系）。
- 间距基本在 4px 网格：非网格字面量仅 31 处（2px×13、6px×5、10px×2、11px×2、18px×1…），占比很低 —— **这是优点**。
- 断点以 768px 为主（26 处），但散落 767 / 480 / 1024 / 1279 / 1100 五个杂散值，建议统一为 480 / 768 / 1024 / 1280。
- 页面级"孤儿文本"：如"最新交易日: 2026-09-18 0秒前刷新"直接压在金色渐变上（无卡片承载），实测 4.69:1，勉强达标但观感游离。

## 5. 组件一致性与设计 token

### 5.1 圆角：9 种取值（最该收敛的一项）

| 圆角 | 出现次数 | 来源 |
|---|---|---|
| 8px | 234 | token medium |
| 9999px | 184 | 胶囊 |
| 4px | 153 | **Element Plus 默认** |
| 6px | 130 | token small |
| 16px | 98 | token xl |
| 12px | 90 | token large |
| **3px** | 90 | **EP/硬编码** |
| 50% | 78 | 圆形 |
| 999px | 2 | 遗留 |

问题：卡片 16px、按钮 3–4px、输入 4px、卡片内小组件 6–8px —— 视觉语言不统一；
且 9999px 与 999px、50% 三种"圆形写法"并存。

**实测主按钮**：`60×24px, border-radius 3px, font-size 12px`（`.el-button--primary`）—— 又小又方，与 16px 圆角卡片同屏出现时明显是两个时代的设计。

**建议**：只保留 3 档 —— 小组件 6px、卡片/容器 12px、胶囊 9999px；EP 默认 3/4px 统一覆盖为 6px；删除 999px。

### 5.2 阴影：已经统一（保持）

实测只有两个值：`0 2px 8px rgba(31,29,26,.05)`(38) 与 `0 4px 16px rgba(31,29,26,.05)`(20) —— 克制、专业，符合"静态卡片用描边、浮层才用阴影"。

### 5.3 毛玻璃 17 处

`backdrop-filter` 在 layout/themes/responsive 共 17 处。侧栏、头部叠在金色渐变上做磨砂，性能与"廉价感"风险都偏高。
**建议**：保留弹层类（对话框/下拉），移除结构性区域（侧栏、头部）的毛玻璃，直接给实色表面。

### 5.4 token 体系审计

| 指标 | 数值 |
|---|---|
| 定义 token | 321 |
| CSS 引用 / JS 引用 | 218 / 40 |
| **引用但未定义** | **0** ✅ |
| **定义但从未引用（死 token）** | **59** |
| 双层 token（`--qc-*` 与 legacy `--*` 并存） | 是 |
| `!important` | **228**（themes.css） |
| CSS 硬编码 hex | **295** |
| JS 内联硬编码色 | 14 |

死 token 示例：`--qc-card-foreground` `--qc-popover-foreground` `--qc-neutral-400/500/700/800` `--qc-primary-900` `--qc-shadow-xs` `--r-sm/md/lg/xl/full` `--card-padding` `--dialog-radius` `--header-height` `--nav-item-height` `--chart-bg` `--chart-axis`（后两者本该用于 ECharts 但没接上）。
零悬空引用是**很强的工程信号**；但 59 个死 token + 228 个 `!important` 说明"加规则容易、删规则难"。

**建议**：一次性清理死 token（保留 3 个月归档记录），并把 `--el-*` 覆盖集中到一个 `element-overrides.css`，避免 EP 覆盖散落 228 处。

## 6. 交互与可达性

- **点击目标**：564 个可交互元素中 **56.4% 高度 <32px**；高度分布峰值在 20px(144)、24px(90)、16px(36)、13px(8)。
  桌面鼠标场景可接受，但触碰场景（平板/移动）不合规，且 13–16px 的元素（图标按钮、小标签）过密。
- **键盘**：有 Ctrl+K 命令面板（好），但移动端该提示与铃铛图标重叠（见 §7）。
- **主按钮**：`60×24px / 12px 字` —— 主操作过小，与"每页一个视觉焦点"冲突。
- **无意义动效**：未发现；过渡统一 200ms —— 良好。

**建议**：桌面主操作按钮 ≥32px 高、次级 ≥28px；移动端所有可点元素 ≥44×44；图标按钮统一 32×32 命中区（视觉 18–20px + padding）。

## 7. 响应式 / 移动端【最需要修的部分】

自动重叠检测（同一页面内两个可见元素交叠面积 >28% 且 >60px²）：

| 页面 | 桌面 | 移动 390×844 |

移动端典型重叠（实测）：

2. `qc-mobile-tab` ∩ `qc-stock-code-num(600036.SH)` / `card-title(开放 API)` / `cell(资产)` —— 二级导航条**压住内容**（内容顶部内边距不足）。
3. `focus-row-name(普冉股份)` ∩ `color-secondary((688766.SH))`，`el-tag__content(新入池)` ∩ `focus-row-score(评分 78.8)` —— 重点跟踪行在窄屏**挤成一团**。
4. 量化日历移动端工具栏出现浮空残留文字（"02:40:12"/"已收盘"叠在金色背景上，半透明），按钮"刷新/导出/上一天/下一天"错位换行。

**建议**：
- 移动端头部改为两行（品牌 + 操作），搜索改为图标点开全宽输入；
- 二级导航条 `.qc-mobile-tab` 加 `position: sticky; z-index` 并为内容区预留等高 padding；
- 重点跟踪行窄屏改两行网格（代码/名称一行、标签/评分一行），而非压缩；
- 工具栏改 `flex-wrap` + `gap: 8px` 并固定按钮尺寸。

## 8. 优化路线图（建议顺序）

### P0 — 低风险、高收益（约 1–2 天）
1. `body` 底色 → `var(--qc-background)`；品牌渐变只留强调元素（**单项收益最大**）
2. 修 `--primary-color-dark` 蓝色泄漏（AI 悬浮球、2 处边框）
3. 亮色渐变白字对比：渐变整体压深一档（16 处一次性达标）
4. 移动端三处重叠（头部搜索、二级导航压内容、重点跟踪行）
5. 圆角收敛：EP 3/4px → 6px，删除 999px

## 附录：测量口径

- 对比度：WCAG 2.1 相对亮度公式，渐变端点按 sRGB 插值计算；另用"截图像素回采"验证渲染真值。
- 品牌色占比：截图等距采样（每 7 像素 1 个），HSV 饱和度 >0.15 且色相与品牌色相 ±40° 记一次。
- 重叠：DOM 叶子文本节点两两求交，交叠面积 / 较小面积 > 0.28 且 > 60px² 判为重叠（排除父子包含）。
- 字号/圆角/阴影/背景色分布：`getComputedStyle` 全量遍历 + 计数（亮/暗 × 4–10 页）。
