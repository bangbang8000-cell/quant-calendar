## 0. 系列总纲

### 0.1 定位与目标

V5 系列是 V4「广度与规范」之上的「**深度与可靠**」升级。七个产品目标在本系列的分工：

| 目标 | 主打版本 | 说明 |
|---|---|---|
| 更稳定 | 5.0 / 5.9 | 自愈、守护、故障演练、迁移/回滚 |
| 更准确 | 5.1 | 数据中台、质量门禁、PIT、字典 |
| 更专业 | 5.2 / 5.3 / 5.5 | 回测严谨性、风险度量、专业报告 |
| 更高效 | 5.4 / 5.7 | 事件通知、缓存、任务队列 |
| 更好用 | 5.6 | 引导、空态、命令面板、无障碍 |
| 更美观 | 5.5 / 5.6 | 图表规范、信息密度、动效统一 |
| 更便捷 | 5.8 / 5.9 | RBAC2.0、API/SDK、升级回滚、观测性 |

### 0.2 版本矩阵总览（按需求重要 × 紧急度排序）

| 版本 | 主题（一类功能） | 主打 | 排序理由 | 规模（估） |
|---|---|---|---|---|
| **5.0** | 稳定性与数据可靠基座 | 稳定 | 最紧急：4.9 连续事故，稳定是信任地基 | 6-8 天 |
| **5.1** | 数据中台与准确性 | 准确 | 最重要：一切量化结论的前提 | 8-10 天 |
| **5.2** | 专业回测与研究台 | 专业 | 核心价值：让"回测可信" | 7-9 天 |
| **5.3** | 风险与组合管理 | 专业 | 决策辅助：从"选股"到"仓位" | 6-8 天 |
| **5.4** | 实时行情与事件通知中心 | 高效 | 日常效率：被动接收信号 | 6-8 天 |
| **5.5** | 报表中心与可视化 | 专业/美观 | 交付物：投研记录沉淀 | 6-8 天 |
| **5.6** | 用户体验与引导 | 好用/美观 | 留存：降低上手与犯错成本 | 6-8 天 |
| **5.7** | 性能与规模化 | 高效 | 规模：大盘/批量不再卡 | 6-8 天 |
| **5.8** | 多用户协作与开放平台 2.0 | 便捷 | 开放：多角色协作与生态 | 7-9 天 |
| **5.9** | 架构现代化与工程化 | 稳定/便捷 | 收口：偿清技术债，一键工程化 | 8-10 天 |

### 0.3 依赖关系与独立运行原则

- **依赖为"逻辑前置"而非"硬阻塞"**：每个中版本都是一个**可独立运行、可独立 tag 发布、可独立部署**的完整版本（全量测试绿 + dev/ops 双端可跑 + Docker 可构建）。
- 逻辑依赖：5.1（数据质量）为 5.2（回测严谨性）供数；5.0（告警链路）为 5.4（通知中心）复用；5.2/5.3（指标产出）为 5.5（报表）供数；5.1（缓存/访问层雏形）为 5.7（性能）奠基。
- 发布节奏：每版本 3-4 个点版本（如 5.0.0 → 5.0.1 → …），出口 = 全量测试绿 + 双端冒烟 0 pageerror；tag v5.N.M 触发 CI + Docker。
- 版本纪律：APP_VERSION 单一来源（backend/main_new.py），tag ↔ APP_VERSION 由 CI gate 守护；前端 dist 产物入库。

### 0.4 通用需求基线（每版本必须满足）

1. **可运行**：新版本在无任何其他 V5 版本配合时独立可运行、可发布。
2. **不回归**：既有 1124 测试全绿（新增门禁不得放宽既有门禁）；令牌/术语/版本/锁文件纪律持续守护。
3. **双端一致**：dev/ops 同步；Docker 镜像可构建。
4. **文档同步**：每版本更新 README/DEPLOYMENT/对应 PRD 状态。
5. **安全底线**：新端点走 deny-by-default 门禁；新存储字段走备份兼容。

## 1. V5.0.0 稳定性与数据可靠基座（主打：更稳定）

### 1.1 背景与目标

V4.9 系列连续 5 个点版本均为可靠性修复（评估串股、日视图为空、日历不可用、持仓读不到、按钮不可见）。根因是"数据新鲜度/可用性缺监控、缺自愈、依赖人工"。目标：**让系统在无人值守下自检、自愈、可告警，把"今天日历能不能用"从问题变成指标**。

### 1.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.0.1 | 数据新鲜度监控：各数据资产（策略持仓/日历视图/行情/K线）记录最后更新时间与期望新鲜度 | P0 | 过期数据在健康面板标红 + 触发告警 |
| FR-5.0.2 | 自愈闭环增强：health_check 定时巡检 → 检出异常 → 自动修复（补拉/重建/重算）→ 记录自愈日志 | P0 | 故障注入后自动恢复且留痕 |
| FR-5.0.3 | 进程守护与启动自检：启动时校验依赖/目录/DB 完整性/关键配置，输出启动报告 | P0 | 缺配置时明确报错而非半启动 |
| FR-5.0.4 | 故障注入测试套件（reliability suite）：数据源全挂/DB 损坏/文件缺失/并发写/时间异常 | P0 | CI 独立 job 必过 |
| FR-5.0.5 | 数据原子性与一致性审计：写路径统一原子写（tmp+rename），关键文件加锁 | P1 | 并发写测试无脏读 |
| FR-5.0.6 | 可用性指标面板：数据新鲜度/自愈次数/故障时长/健康分（首页/健康面板展示） | P1 | 指标可视化 + 导出 |
| FR-5.0.7 | 告警分级与飞书送达：P0 故障必达、P1 每日汇总、去重与静默窗口 | P1 | 分级投递可配置 |

### 1.3 关键设计

- 新增 backend/reliability/ 模块（monitor.py / heal.py / checks.py），独立于 scheduler 的可插拔巡检，避免继续膨胀 scheduler.py。
- 新鲜度规则表：{数据资产, 来源, 期望新鲜度(如 1 交易日/5 分钟), 过期策略(告警/自愈)}，存 meta 表 + JSON。
- 自愈动作注册表：每个异常类型 → 一个可重入的修复动作（幂等），全部有日志与审计。
- 前端健康面板新增"数据新鲜度"分区与自愈时间线。

### 1.4 明确不做

- 不做分布式/多机部署（保持单机定位）。
- 不做数据源新接入（属 5.1）。
- 不做自动回滚（属 5.9）。

### 1.5 验收标准

1. 注入 5 类故障（三源全挂/DB 只读/持仓缺失/日历空/时间回拨）后系统自动恢复或明确降级，无静默错误。
2. 健康面板实时反映数据新鲜度与自愈记录。
3. 全量既有测试绿 + 新增 reliability suite 全绿。
4. 双端可独立运行、可 tag 发布。

## 2. V5.0.1 数据中台与准确性（主打：更准确）

### 2.1 背景与目标

数据质量无自动门禁、口径分散、无字典、成本模型不完整。目标：**建立统一、可校验、口径一致、时间点正确的数据中台，让"结果可信"**。

### 2.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.1.1 | 统一数据访问层 DataPortal 2.0：三源 + 缓存 + 限流 + 重试 + 一致口径，收敛 data_sources/market_data/DataPortal 取数 | P0 | 各模块经统一层取数，接口契约测试 |
| FR-5.1.2 | 数据质量校验门禁：缺数率/异常值/复权一致性/停牌处理/交易日对齐，输出质量分 | P0 | 质量分进健康面板，跌破阈值告警 |
| FR-5.1.3 | 时间点数据（PIT）治理：评估/回测/因子取数一律 end<=as_of，PIT 断言测试扩展 | P0 | 全路径无前视（测试守护） |
| FR-5.1.4 | 数据字典：字段口径/复权方式/因子定义/来源/更新频率，随代码维护 + API 可查 | P1 | 字典页可浏览检索 |
| FR-5.1.5 | 幸存者偏差治理：历史股票（退市/改名）纳入取数与日历 | P1 | 全市场含退市回溯测试 |
| FR-5.1.6 | 数据血缘与版本：数据刷新批次号、刷新审计、可追溯 | P1 | 每笔数据可查来源与时间 |

### 2.3 关键设计

- DataPortal 2.0 为纯新增抽象层 + 逐步迁移（先接入评估/回测/日历主链路，再清扫长尾），避免一次性重写。
- 质量规则声明式（YAML/常量），每条规则独立可测。
- 数据字典以结构化 YAML 为单一事实源，渲染页面 + 生成 API。

### 2.4 明确不做

- 不做数据仓库/列存（SQLite+JSON 够用）。
- 不做多数据源新供应商接入（保持三源）。
- 不改动既有外部接口（兼容为先）。

### 2.5 验收标准

1. 主链路（评估/回测/日历/因子）全部经 DataPortal 2.0 取数，契约测试覆盖。
2. 质量门禁能检出人为注入的缺数/异常值并告警。
3. PIT 断言测试覆盖评估、回测、因子、日历四条路径。
4. 数据字典页可浏览。

## 3. V5.0.2 专业回测与研究台（主打：更专业）

### 3.1 背景与目标

现有回测仅佣金(0.0003)+滑点(0.001)固定值，缺印花税/可配置成本/基准对比/样本外纪律/归因。目标：**让回测结果可信、可比、可归因、可导出**。

### 3.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.2.1 | 成本模型 2.0：印花税（卖出 0.05%）+ 佣金 + 滑点 + 可配置冲击成本 | P0 | 成本敏感度测试 + 与 PTrade 对拍 |
| FR-5.2.2 | 基准对比：沪深300/中证500/中证1000/自定义，超额收益与信息比率 | P0 | 基准线入图 + 指标 |
| FR-5.2.3 | 样本内外划分 + walk-forward 滚动回测 | P0 | 样本外指标独立展示 |
| FR-5.2.4 | 参数稳定性分析：参数高原可视化 + 过拟合诊断（已有 SENSITIVITY_SPREAD_RATIO 复用） | P1 | 稳定性热力图 |
| FR-5.2.5 | 绩效归因：行业/风格因子归因 | P1 | 归因瀑布图 |
| FR-5.2.6 | 回测报告导出：PDF/Excel（含净值/回撤/月度收益/基准对比） | P1 | 导出文件可打开校验 |

### 3.3 关键设计

- 成本模型可插拔（flat/stamp+impact 两档预设 + 自定义）。
- walk-forward 不重写 SDK 回测，基于现有"防前视"契约扩展（样本内 fit、样本外 evaluate 分段）。
- 回测结果对象增加 benchmark/out_of_sample 字段，前端图表联动。

### 3.4 明确不做

- 不做多标的组合回测（属 5.3 组合层面）。
- 不做逐笔撮合仿真（回测近似即可，文档化假设）。
- 不改动既有 /api/backtest 兼容路径（新增参数可选）。

### 3.5 验收标准

1. 加印花税后回测收益合理下降，成本敏感度测试通过。
2. 基准对比线 + 超额收益/IR 展示正确。
3. 样本内外指标分离展示，walk-forward 结果可复现。
4. 全量测试绿 + PTrade 对拍无回归。

## 4. V5.0.3 风险与组合管理（主打：更专业）

### 4.1 背景与目标

组合模块有持仓/买卖/净值，但**无风险度量**（无 VaR/回撤/夏普/Beta/集中度/仓位建议）。目标：**从"记账组合"升级为"可度量、可控风险、有仓位建议"的决策辅助**。

### 4.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.3.1 | 组合风险指标：波动率/VaR(95,99)/最大回撤/夏普/Calmar/Beta | P0 | 指标计算测试 + 与基准对比 |
| FR-5.3.2 | 仓位建议：Kelly 修正 + 风险平价参考，给出建议仓位区间 | P0 | 与实盘约束（单票上限）联动 |
| FR-5.3.3 | 风控规则引擎：个股集中度/行业集中度/止损止盈/回撤熔断，可配置触发动作（提醒/强平建议） | P0 | 规则触发测试 |
| FR-5.3.4 | 组合再平衡建议：偏离目标权重提示 | P1 | 偏离度可视化 |
| FR-5.3.5 | 回撤/风险预警：接入 5.0 告警链路与通知中心（5.4） | P1 | 预警事件发出 |

### 4.3 关键设计

- 新增 backend/risk.py（指标）+ backend/rules.py（规则引擎），纯函数可测。
- 规则引擎事件进 5.0 的可靠性事件总线（为 5.4 通知中心复用）。
- 前端组合页新增"风险"Tab：指标卡 + 风险仪表盘 + 规则列表。

### 4.4 明确不做

- 不做真实下单/券商对接（模拟组合定位）。
- 不做期权/衍生品风险（股票组合）。
- 指标口径先做"持仓市值口径"（后续可扩展资金口径）。

### 4.5 验收标准

1. VaR/回撤/夏普等指标与独立计算核对一致（对拍测试）。
2. 风控规则按预设触发提醒/强平建议。
3. 仓位建议考虑单票/行业上限，输出区间而非单点。
4. 全量测试绿。

## 5. V5.0.4 实时行情与事件通知中心（主打：更高效）

### 5.1 背景与目标

通知仅飞书 + Webhook，无统一通道；实时行情 WS 已存在但无订阅管理与断线重连治理；无自定义预警规则。目标：**一个统一通知中心 + 事件引擎，让用户"被动接收信号"**。

### 5.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.4.1 | 通知中心：通道抽象（飞书/企微/钉钉/邮件/Telegram/Webhook），统一投递、重试、去重 | P0 | 多通道发送测试 + 失败重试 |
| FR-5.4.2 | 事件引擎 2.0：事件（策略入池/异动/风控/报告/数据新鲜度）→ 订阅规则 → 通道 | P0 | 端到端投递闭环测试 |
| FR-5.4.3 | 自定义预警规则：价格/涨跌幅/异动/入池条件触发 | P1 | 条件触发 + 命中通知 |
| FR-5.4.4 | WS 行情 2.0：订阅管理、增量推送、心跳、断线重连、多客户端 | P1 | 断线重连测试 |
| FR-5.4.5 | 通知历史与静默设置 | P1 | 历史可查可静默 |

### 5.3 关键设计

- 新增 backend/notify.py（通道注册 + 投递）+ backend/events.py（事件总线），复用 5.0 的可靠性事件。
- 通道以"适配器"注册，新增通道只需实现 send() 契约（测试用 FakeChannel）。
- 前端新增"通知中心"页（规则管理 + 历史 + 通道状态）。

### 5.4 明确不做

- 不做短信/电话通道（成本高，按需扩展）。
- 不做邮件模板市场（模板内建）。
- 不改变既有 feishu/webhook 既有行为（兼容迁移）。

### 5.5 验收标准

1. 一个事件可配置投递到多个通道，失败自动重试。
2. 自定义预警规则命中后正确触发通知。
3. WS 断线后自动重连且不重复推送。
4. 既有飞书/Webhook 行为不回归。

## 6. V5.0.5 报表中心与可视化（主打：更专业 / 更美观）

### 6.1 背景与目标

日报/周报为 Markdown 文本、无模板化/导出；图表深度有限。目标：**模板化、可导出、可订阅的投研报表 + 更有专业感的可视化**。

### 6.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.5.1 | 报表中心：日报/周报/月报模板化（区块可编排），历史报表列表与回放 | P0 | 模板渲染快照测试 |
| FR-5.5.2 | 报表导出：PDF（专业排版）/Excel（多 sheet 数据） | P0 | 导出文件结构校验 |
| FR-5.5.3 | 报表订阅：定时生成 + 通知中心投递（5.4） | P1 | 定时任务 + 投递闭环 |
| FR-5.5.4 | 图表规范与增强：ECharts 主题令牌联动、涨跌/风险语义配色、K 线指标扩展 | P1 | 视觉回归 + 令牌门禁 |
| FR-5.5.5 | 数据仪表盘：今日要点（周期/共识/异动/风控/评估摘要）一屏聚合 | P1 | 关键指标卡片 |

### 6.3 关键设计

- 报表以"区块数据源 + 模板"定义：区块（周期/策略/异动/评估/风控/组合）各自独立渲染，可增删排序。
- PDF 用 HTML→PDF（reportlab 或 wkhtmltopdf 降级方案），Excel 复用现有 openpyxl 能力。
- 首页新增"今日要点"聚合卡（复用 5.3 风控 + 5.4 事件摘要）。

### 6.4 明确不做

- 不做可视化拖拽搭建（仪表盘固定布局 + 可配字段）。
- 不做 Word 导出（PDF/Excel/Markdown 三档够用）。

### 6.5 验收标准

1. 日报/周报/月报可配置区块并正确渲染。
2. PDF/Excel 导出打开校验通过。
3. 订阅投递到通知中心成功。
4. 图表暗色/亮色与主题联动，令牌门禁全绿。

## 7. V5.0.6 用户体验与引导（主打：更好用 / 更美观）

### 7.1 背景与目标

## 8. V5.0.7 性能与规模化（主打：更高效）

### 8.1 背景与目标

单进程无任务队列，批量评估/同步/回测可能阻塞事件循环；无统一缓存；大盘数据（全市场 K 线/因子）偏慢。目标：**批量任务后台化、重读缓存化、大盘数据可跑**。

### 8.2 需求列表

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.7.1 | 两级缓存：内存（TTL）+ 磁盘（SQLite/JSON 持久缓存），统一失效中心 | P0 | 命中率/失效正确性测试 |
| FR-5.7.2 | 异步任务队列：批量评估/回测/数据同步/报告生成后台化，任务状态/进度/取消/结果持久化 | P0 | 任务提交→进度→结果闭环测试 |
| FR-5.7.3 | 大数据量优化：全市场 K 线/因子计算分块 + 降采样；年视图维持 32 倍提速基准 | P1 | 性能基准对比 |
| FR-5.7.4 | 前端虚拟滚动：长列表（评估历史/股票池）虚拟化 | P1 | 万行滚动流畅 |
| FR-5.7.5 | 性能基准门禁：P50/P95 延迟与首屏指标入 CI（有阈值） | P1 | 退化即红 |

### 8.3 关键设计

- 任务队列用 SQLite 任务表 + 单 worker 后台循环（保持零外部依赖，不引入 Redis/RabbitMQ；可选 Redis 后端预留）。
- 缓存键 = 数据资产 + 参数 + 数据版本（5.1 血缘批次），失效由写入/刷新触发。
- 前端长列表复用 virtual-list-core.js。

### 8.4 明确不做

- 不做多进程/多机横向扩展（单机 + 异步足够）。
- 不做 WebSocket 集群。

### 8.5 验收标准

1. 批量评估 50 只票提交后台任务，期间页面不阻塞。
2. 缓存命中率报告可见，失效正确。
3. 全市场回测/因子在阈值时间内完成。
4. 性能门禁进 CI。

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.9.1 | 巨型文件拆分：ai_evaluator/scheduler/data_sources/merrill_clock 按职责拆分（行为不变） | P0 | 拆前拆后全量对拍 + 门禁 |
| FR-5.9.2 | schema 版本化迁移框架：版本号 + 顺序迁移 + 回滚 + 校验 | P0 | 升级/回滚演练测试 |

| FR-5.9.4 | 观测性 2.0：结构化日志、请求 trace、SLO 指标（可用性/延迟/成功率）与告警 | P1 | SLO 仪表盘 |

### 10.5 验收标准

1. 四大巨型文件拆分后全量测试绿、覆盖率不降。
2. 迁移框架可顺序升级 + 回滚（演练通过）。
3. 一键升级在 DryRun 与真演练两种模式通过。
4. SLO 仪表盘展示可用性/延迟/成功率。

## 11. 优先级排序依据汇总

1. **5.0 稳定**：事故频发（紧急） + 信任地基（重要）→ 最前。
2. **5.1 数据准确**：量化结论的前提（重要） → 其次。
3. **5.2 回测严谨**：核心价值（重要） → 依赖 5.1 数据。
4. **5.3 风控**：决策辅助闭环（重要） → 依赖 5.0 告警/5.2 指标。
5. **5.4 通知**：日常效率（较紧急） → 复用 5.0 事件。
6. **5.5 报表**：专业交付物（中） → 依赖 5.2/5.3 产出。
7. **5.6 UX**：留存与上手（中） → 稳定后做体验最安全。
8. **5.7 性能**：规模化（中） → 依赖 5.1 缓存雏形。
9. **5.8 协作开放**：多角色与生态（中低）。
10. **5.9 架构**：技术债偿清（长期） → 收官最稳。

> 独立运行原则：上述依赖均为"逻辑前置"，任何版本都可跳过前置单独发布。

## 12. 术语

- **PIT**：point-in-time，时间点数据（取数不晚于评估日，防前视）。
- **walk-forward**：滚动样本外回测（样本内拟合、样本外评估）。
- **VaR / Calmar**：在险价值 / 年化收益-最大回撤比。
- **RBAC**：基于角色的访问控制。
- **reliability suite**：故障注入可靠性测试套件。
- **两级缓存**：内存 TTL 缓存 + 磁盘持久缓存。
