## 1 概述

### 1.1 背景

产品已完成 V6.0–V6.6 连续六轮迭代：V6.0 导航与菜单系统重构打地基，V6.1 三栏式布局与视觉统一，V6.2 细节收口，V6.3 导航形态配置化，V6.4 用户七项建议落地与数据源接通，V6.5/V6.6 界面美术打磨收尾（emoji 清理、token 迁移、暗色收尾）。

V6.6.0 已定版（`APP_VERSION = "6.6.0"`），美术收尾仍在进行。产品功能面已非常庞大（30+ 后端模块路由、6 个一级菜单、40 个二级子页、约 3124 项测试），进入「存量功能优化打磨」阶段。本阶段不再以新增功能为主线，而是围绕六个目标持续打磨：**易用性、实用性、界面美观度、操作便捷性、运行效率、智能化水平**。

评估发现的主要问题（详见 §2、§3、§4）：

- **信息架构层面**：组合持仓（重要功能）无菜单入口；量化日历日/周/月/年视图与页内切换器功能重复；执行看板分组归属错误；市场行情与市场复盘命名混淆；系统配置 12 个子页存在大量内容重复与错位（用量统计重复渲染、通知中心大子系统无独立入口、个性化设置混入系统状态）。
- **视觉层面**：V6.6 仍在清理的 emoji 残留、旧 token、暗色语义色双轨、响应式旧类名。
- **性能层面**：全市场策略执行约 12 分钟（Tushare 积分限频），V6.4 评估建议的本地缓存/增量拉取（目标 <3 分钟）至今未承接。
- **测试层面**：e2e 视觉回归为信息性（不阻塞发布），无自动化 a11y 全量门禁，菜单结构无契约测试。
- **智能化层面**：AI 评估/问股/复盘已就位，但评估结果与真实涨跌的校准分析、历史复盘检索式问答、基于用户持仓的个性化智能推荐尚未成体系。

### 1.2 目标

| # | 目标 | 可量化判据（验收导向） |
|---|---|---|
| G1 | 信息架构收敛，导航无「看不见的功能」 | 组合持仓、通知中心等关键功能均有菜单入口；冗余视图入口消除；§3/§4 评估结论全部落地 |
| G2 | 界面美观度收尾 | 装饰性 emoji 清零、内联动态色 token 化、暗色对比度 ≥4.5:1（muted）、旧 token 引用下降 ≥60%（高频文件） |
| G3 | 操作便捷性提升 | 高频任务（评估/回测/复盘/导出/通知配置）≤3 步可达；快捷键覆盖高频动作；关键路径无「双入口割裂」 |
| G4 | 运行效率提升 | 全市场策略执行 ≤3 分钟（当前约 12 分钟）；首屏与列表滚动性能不劣化（体积门禁保持） |

## 2 多维度现状评估

> 评估方法：代码定位 + 文档交叉验证 + 既有评估报告引用。数据以 2026-09-11 工作区实测为准。

### 2.1 系统架构

**现状**：

- 后端为单进程 FastAPI 模块化单体（`main_new.py` 入口 + `api/v1/router.py` 聚合 30+ 模块路由 + `api/v3` 分页过滤信封），SQLite（WAL 模式 + 全局 RLock）为主、JSON 为辅的存储，双层迁移机制（幂等增量 + 版本化框架失败拒绝启动）。
- 前端为 Vue 3 SPA（Vite 构建、dist 入库、PWA 离线），**SFC 组件与遗留 JS 页面组件并存**：导航层已 SFC 化（Sidebar/SubNav/Header/TopTabs/MobileNav），但 30+ 个 `js/components/*-page.js` 仍为 options JS 组件。
- 数据源三源热备（sxsc→tushare→akshare，连续失败 3 次冷却 300s，429 不计失败），AI 为厂商卡 + 模型两级配置（OpenAI 兼容）。

**问题与优化方向**：

| # | 问题 | 影响 | 优先级 |
|---|---|---|---|
| A1 | 前端组件形态双轨（SFC + 遗留 options JS），`app-logic.js` 单体巨大（qcState 约 486 键） | 维护成本、新人上手门槛、测试与类型化困难 | P1（分阶段，非一次性重写） |
| A2 | 全市场策略执行约 12 分钟，受 Tushare 积分限频，无本地行情缓存 | 数据新鲜度与用户体验 | P0（6.8.X 承接） |
| A3 | 部分业务逻辑与表现逻辑耦合在 `*-page.js` 组件内（服务端返回实时色 → 内联 `:style`） | 主题/暗色一致性难保障 | P1（6.6.X 部分承接） |
| A4 | `SUB_ICONS` 在 `SubNav.vue` 与 `TopTabs.vue` 双份维护 | 改一处漏一处 | P2 |
| A5 | 前后端契约靠契约测试守护但缺 schema 共享 | 接口变更需双端同步 | P3 |

### 3.2 评估结论（逐项，已定稿）

#### 结论一：组合持仓无菜单入口 —— 修复（P0）

模拟组合（持仓/买卖调仓/实时盈亏/收益曲线/审计）+ 组合构建 + 风险报告是产品核心功能之一，但 `allMenuDefs` 中 `ai.subPages` **不含 `portfolio`**，仅 AI 概览 stat-card 与 Ctrl+G 可达，刷新/深链即丢失状态。**判定**：功能存在但「看不见」，属信息架构缺陷。

**落地**：6.6.X 将 `portfolio` 加入智能评估二级菜单（置于 `evaluation-analysis` 之后、`chat_history` 之前），补齐 i18n（`sub.portfolio` 已有）与图标映射、URL hash 深链。

#### 结论二：量化日历 4 个视图入口冗余 —— 合并（P1）

`daily/weekly/monthly/yearly` 作为 4 个独立二级菜单，同时日历页内部又有「日/周/月/年」视图切换器（`app-logic/nav.js` switchView），两条切换通道并存。**判定**：同一维度被建模为 4 个导航项，属冗余，应降为页面内切换。

**落地**：合并为单一「量化日历」子页 +「股票池」共 2 项；`#calendar/daily` 等旧 hash 重定向到 `#calendar`。

#### 结论三：执行看板分组归属错误 —— 归位（P1）

`execution`（今日执行计划/实时进展/执行结果/执行追溯）是**策略执行监控**，被放在系统配置「组织管理」组。**判定**：语义错位。

**落地**：移入「运行监控」组（与 status/health/schedule 同组；方案 A 下 guard 亦入组）。不提升为一级。

#### 结论四：「市场行情」与「市场复盘」命名混淆 —— 消歧（P2）

`market`（指数/情绪/交易状态）与 `market-review`（AI 每日复盘）名称相近易混，且 market 行情内容与量化日历域重叠。**判定**：命名易混淆，不涉及删除。

**落地**：`market` 更名「大盘行情」；`market-review` 更名「每日复盘」；key 不变，i18n 五语同步。

#### 结论五：「策略编写」与「全新策略」语义重叠 —— 合并（P2）

`strategy-write`（模板编辑）与 `custom-write`（自定义新建）均为策略编辑入口，区分度低。**判定**：语义重叠。

**落地**：合并为「策略管理」子页（内部提供「基于模板编辑 / 全新创建」两态）；`#research/strategy-write`、`#research/custom-write` 重定向至 `#research/strategy-manage`。

#### 结论六：短线复盘 7 个二级偏多 —— 分组展示（P2）

**判定**：功能域内聚度高，无需删除或提升，但平铺密度影响查找效率。**落地**：6.7.X 中栏视觉分组（复盘/数据/盘后核验），不改 key 与路由。

#### 结论七：移动端「短线复盘」不可直达 —— 补齐可达性（P2）

**判定**：高频功能在移动端被折叠，属导航缺口；不调整一级菜单数量。**落地**：6.7.X 默认方案为抽屉内短线复盘二级默认展开（低风险）`[待确认，见 §7.1]`。

#### 结论八：股票池归属（P3，观察项）

`pool` 内容本质是策略输出，与策略总览域更近。**本轮不动**，6.9.X 综合评估时再定。

## 6 全局规则与约束

1. **菜单 key 兼容**：任何子页合并/重命名，旧 `#hash` 深链与用户组 `visible_sub_pages` 键均需迁移映射，不得出现死链。
2. **i18n 五语同步**：新增/修改文案必须五语（zh-CN/en/ja/ko/zh-TW）一一对应，i18n 缺词守卫通过。
3. **向后兼容**：不改变既有 API 响应契约；后端新增字段仅 additive；`visible_menus`/`visible_sub_pages` 组配置语义不变。
4. **AI 内容护栏**：所有 AI 生成/摘要内容沿用诚实性护栏与事实校验，标注来源与「仅供参考」。
5. **性能预算**：前端体积门禁（主逻辑 ≤80KB、JS 总量 ≤1.3MB）与性能基线在全部迭代中保持。
6. **测试基线**：每迭代结束跑对应门禁 + 全量关键集，不得引入新失败（除已声明不修的 pre-existing）。
7. **版本纪律**：`APP_VERSION` 单一来源 bump；tag 版本与 `APP_VERSION` 一致（CI 版本纪律门禁）。
