# v3.22 界面体验优化 (UI/UX Refinement) — 产品需求文档 (PRD)

> 版本: 3.22.0 | 前置: v3.21 (策略纳管/持仓矩阵) | 状态: 评审待定
> 定位: 在 v3.21 功能完整基础上, 收敛界面体验问题(滚动/卡片化/可理解性/数据可视化), 不新增业务能力

## 0. 需求背景与动机

v3.21 已实现 P0-8 全部业务功能(策略纳管/持仓矩阵/审计/调度)。用户在使用过程中反馈 5 处**界面体验**问题, 集中在:

| # | 反馈 | 本质 | 现状(实测) |
|---|---|---|---|
| 1 | 量化日历有 2 个滚动条且不在最右 | 滚动模型不统一 | document 滚动(852>757) + 卡片内 stock-list 滚动(507>500) + sub-nav 横向(386>349) 三处并存 |
| 2 | 用量统计信息分散不都在卡片上 | 信息架构碎片化 | 8 个 section-block(资源/数据源/AI/护栏/调度/备份), 部分裸露 |
| 3 | 量化研究难理解, 策略编写应是新建/复制/AI优化 | 交互模型缺失 | strategy-write 子页是"敬请期待"空壳 |
| 4 | 美林时钟要历史周期串联视图 | 数据未可视化 | 后端 13 条历史转换(第1-4轮) 完整, 前端只展示当前阶段 |
| 5 | 评估以上需求合理性 + 方案 | 本 PRD | — |

## 1. 需求评估 (合理性 + 优先级)

### 1.1 需求1: 滚动条统一 — ✅ 合理, P0
- **合理性**: 双滚动条(页面级+卡片内)是典型滚动模型混乱, 且 stock-list 滚动条不在最右(因卡片有 margin-left), 确属缺陷
- **方案**: 统一为**单滚动模型**——主内容区(main-content)固定高度 `height: calc(100vh - header)`, `overflow-y: auto`, 页面级滚动收敛到 main-content; stock-list 保留卡片内滚动(它是虚拟列表, 需内部滚动); sub-nav 保留横向(信息多)。目标: 任何时刻**最多 1 个垂直滚动条可见**
- **风险**: 低(纯 CSS, 不动 JS 逻辑)。需在桌面/平板/移动三端回归

### 1.2 需求2: 用量统计卡片化 + 合并聚合 — ✅ 合理, P1
- **合理性**: 8 个区块是历史迭代叠加, 无统一卡片容器; 部分指标(如错误率/平均延迟)裸奔在面板外
- **方案**: 统一为**卡片网格(2-3 列)**, 4 个功能卡: ①资源监控 ②数据源健康 ③AI 用量 ④系统健康(护栏+调度+备份合并为"运维状态")。每个卡: 标题 + 3-6 个关键指标(大数字+徽标) + 明细可展开
- **风险**: 中(需重构模板, 但纯前端, 数据源不变)

### 1.3 需求3: 量化研究/策略编写增强 — ✅ 合理, P1
- **合理性**: strategy-write 是空壳, 用户明确要"新建/复制微调/AI优化", 且已有 clone(复制副本)与 profiles(参数持久化)基础, 值得补齐
- **方案**: 三能力落地在**策略编写页**(而非研究主页): ①**新建策略**(基于模板/从零, 生成 JSON 定义) ②**从已有策略复制并微调**(参数向导 + 差异高亮) ③**AI 优化**(调用现有 LLM 链路, 分析当前策略表现+给出参数建议, 一键应用)。策略定义存 strategy_defs(已有表)
- **风险**: 中(需新后端端点: 策略创建/保存/复制/AI 建议; 复用 ai_evaluator._call_llm 链路)

### 1.4 需求4: 美林时钟历史周期串联视图 — ✅ 合理, P0
- **合理性**: 数据(13 条转换/4 轮)已完整存在, 只缺可视化; 这是"决策复盘"的核心价值, 用户明确要"最近 4 轮 + 可点击详情"
- **方案**: 新增**周期时间轴视图**(在美林时钟页): 横向时间轴 2009→至今, 按轮次着色(4 色), 每轮显示阶段序列(衰退→复苏→过热→滞胀), 每阶段可点击查看详情(时长/触发/关键指标, 复用 stage detail 端点); 默认展示最近 4 轮
- **风险**: 低(数据已有; 新增前端视图 + 1 个聚合端点)

### 1.5 需求5: 评估 — ✅ 本 PRD 即评估输出
- 4 项需求全部合理, 无重复开发; 数据/能力基础均已具备(滚动 CSS 可改/8区块纯前端/LLM 链路已有/历史转换数据已有)
- 按"价值/成本"排序: **需求1(P0,低成本高感知) → 需求4(P0,数据已有) → 需求2/3(P1)**

## 2. 方案设计

### 2.1 滚动条统一 (I1)

**现状**(实测):
- `main-content` 无 height/overflow → 滚动在 document 层
- stock-list 卡片内滚动 (qc-virtual-list h-calc-250)
- sub-nav-wrapper 横向滚动

**目标布局**:
```
┌────────┬───────────────────────┐
│ sidebar │ header (固定)          │
│ (fixed) ├───────────────────────┤
│         │ main-content (overflow-y:auto) │
│         │   └ 页面内容           │
└────────┴───────────────────────┘
```

**改动** (纯 CSS, frontend/css/layout.css + responsive.css):
- `body { height: 100vh; overflow: hidden; }` (页面级滚动禁掉)
- `.main-content { height: calc(100vh - <header_h>); overflow-y: auto; }` (主滚动收敛)
- header 固定, sidebar 已有 fixed
- 移动端(<768px) 保留 body 滚动(无固定 header, 更自然)
- 验收: 桌面任意页**仅 1 个垂直滚动条**(在 main-content 最右); 无页面级 + 卡片级叠加

### 2.2 用量统计卡片化 (I2)

**目标**: usage 子页重构为 4 卡片网格:
```
┌─ 资源监控 ─────┐ ┌─ 数据源健康 ─────┐
│ CPU 45%  ███   │ │ sxsc 98% 12ms  │
│ 内存 62% ████  │ │ tushare 95% 18ms│
│ 磁盘 38%  ██   │ │ akshare 88% 40ms│
│ 运行 12.4h     │ │                 │
└──────────────┘ └──────────────────┘
┌─ AI 用量 ───────┐ ┌─ 运维状态 ──────┐
│ 今日 34 次      │ │ 护栏通过率 92%  │
│ 模型Top: deepseek│ │ 调度任务 3 正常 │
│ 峰值 8次/时     │ │ 最近备份 今天   │
└──────────────┘ └──────────────────┘
```

**改动**: system-page.js usage 子页重构(纯前端) + layout.css 补卡片类; 数据源不变

### 2.3 策略编写页增强 (I3)

**目标**: strategy-write 子页从"敬请期待" → 三能力:
1. **新建策略**: 模板选择(4 内置模板) → 填参数 → 保存为自定义策略(strategy_defs)
2. **复制并微调**: 选已有策略 → 复制 → 参数向导(与 I3 profiles 复用) → 保存为"<原名>-副本"
3. **AI 优化**: 选策略 → 点击"AI 优化建议" → 后端调用 LLM(复用 ai_evaluator._call_llm)分析策略参数/表现 → 返回参数建议 JSON → 一键应用(写回 param_values)

**后端新增**:
- `POST /api/strategies/custom` (保存自定义策略 JSON 定义到 strategy_defs, type=custom)
- `POST /api/strategies/{sid}/copy` (复制策略 → 新 sid)
- `POST /api/strategies/{sid}/ai-optimize` (LLM 参数建议)

**前端**: strategy-write 子页 3 个 tab(新建/复制/AI优化)

### 2.4 美林时钟历史周期视图 (I4)

**目标**: 美林时钟页新增**周期时间轴**(默认显示最近 4 轮):
```
2009 ──── 2012 ──── 2016 ──── 2020 ──── 2024 ──── 今
 [第1轮]  [第2轮]  [第3轮]  [第4轮]
 衰→复→过→滞  衰→复→过→衰   ...
 ── 每阶段点击 → 详情弹窗(时长/触发/指标)
```

**后端**: `GET /api/merrill-clock/timeline` (聚合 HISTORICAL_TRANSITIONS 为 {cycles: [{label, stages:[{stage, from, to, duration, trigger, indicators}]}]})
**前端**: merrill.js 新增时间轴渲染(纯 CSS/ECharts 横向柱), 点击弹详情(复用 stage detail)

| 阶段 | 内容 | 优先级 | 预计规模 |

## 4. 非目标 (Out of Scope)

- 不新增业务功能(选股/回测逻辑不变)
- 不动数据源/调度器/审计核心
- 不做按需加载重构(维持 P2 技术债)
- 不改移动端布局骨架(仅滚动收敛)

## 5. 验收标准

1. 桌面端任意页面滚动条 ≤1 个垂直(在 main-content 最右), 与一级菜单视觉一致
2. 用量统计 4 卡片, 信息全部入卡, 无裸露指标
3. 策略编写页可新建/复制微调/AI优化(保存后出现在策略列表)
4. 美林时钟页展示最近 4 轮历史时间轴, 每阶段点击可看详情
5. 全量测试绿(当前 907+新增) + 覆盖率 ≥40 + 前端一致性 103+ 绿

## 6. 风险与依赖

- **滚动改动**: 需三端回归(桌面/平板/移动); 若发现破坏, 回退为"仅隐藏页面级滚动条"方案
- **策略编写**: 自定义策略仅 JSON 定义(参数), 不支持 Python 代码编辑(零构建约束); AI 优化建议为参考, 需用户确认应用
- **AI 优化**: 依赖 AI key 配置; 无 key 时优雅降级(提示未配置)
