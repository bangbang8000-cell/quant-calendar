# v3.22 界面体验优化 (UI/UX Refinement) — 产品需求文档 (PRD)

> 版本: 3.22.0 | 前置: v3.21 (策略纳管/持仓矩阵) | 状态: 评审调整版 v2
> 定位: 在 v3.21 功能完整基础上, 收敛界面体验问题(滚动/卡片化/可理解性/数据可视化) + 新增 PTrade 代码策略能力

## 0. 需求背景与动机

v3.21 已实现 P0-8 全部业务功能(策略纳管/持仓矩阵/审计/调度)。用户反馈 5 处问题, 其中第 3 项在评审后明确为**新策略用 Python/PTrade 代码 + AI 代写迭代**。

| # | 反馈 | 本质 | 现状(实测) |
|---|---|---|---|
| 1 | 量化日历有 2 个滚动条且不在最右 | 滚动模型不统一 | document 滚动(852>757) + 卡片内 stock-list 滚动(507>500) + sub-nav 横向(386>349) 三处并存 |
| 2 | 用量统计信息分散不都在卡片上 | 信息架构碎片化 | 8 个 section-block(资源/数据源/AI/护栏/调度/备份), 部分裸露 |
| 3 | 策略编写应支持 Python/PTrade + AI 代写 | 策略创作能力缺失 | strategy-write 子页是"敬请期待"空壳; PTrade 兼容层(模板/校验/导出)已具备 |
| 4 | 美林时钟要历史周期串联视图 | 数据未可视化 | 后端 13 条历史转换(第1-4轮) 完整, 前端只展示当前阶段 |
| 5 | 评估以上需求合理性 + 方案 | 本 PRD | — |

## 1. 需求评估 (合理性 + 优先级)

### 1.1 需求1: 滚动条统一 — 合理, P0
- 双滚动条(页面级+卡片内)是滚动模型混乱, stock-list 滚动条不在最右(卡片 margin-left)
- 方案: 主内容区固定高度 + overflow-y:auto; body 禁滚动。目标: 最多 1 个垂直滚动条(在内容区最右)
- 风险: 低(纯 CSS); 需三端回归

### 1.2 需求2: 用量统计卡片化 + 合并聚合 — 合理, P1
- 方案: 8 区块到 4 卡片网格(资源监控/数据源健康/AI 用量/运维状态)
- 风险: 中(模板重构, 纯前端)

### 1.3 需求3: 策略编写(Python/PTrade + AI 代写) — 合理, P1, 评审后升级
- strategy-write 是空壳; 用户明确"4 基础策略保持现状, 新策略用 Python 写(PTrade 兼容, 可在 PTrade 直接回测/使用), AI 代写迭代"
- 已具备: PTrade 模板(_ALLOWED_APIS 校验/render_ptrade_code/4 模板) + 导出功能 + LLM 链路 + strategy_defs 表
- 缺口: 自定义策略存储(code 列) + backtest 识别 custom + AI 生成/优化端点 + 前端编辑区
- 风险: 中(需 PTrade 兼容回测适配层)

### 1.4 需求4: 美林时钟历史周期串联视图 — 合理, P0
- 方案: 新增周期时间轴(最近 4 轮, 阶段点击看详情); 后端 1 聚合端点
- 风险: 低(数据已有)

### 1.5 需求5: 评估 — 本 PRD 即评估输出
- 4 项全部合理; 排序 I1(P0) 到 I4(P0) 到 I2(P1) 到 I3(P1, 评审后工作量最大)

## 2. 方案设计

### 2.1 滚动条统一 (I1)

现状(实测): main-content 无 height/overflow, 滚动在 document; stock-list/sub-nav 卡片内滚动

目标布局:
```
┌────────┬───────────────────────┐
│ sidebar │ header (固定)          │
│ (fixed) ├───────────────────────┤
│         │ main-content (overflow-y:auto) │
│         │   └ 页面内容           │
└────────┴───────────────────────┘
```

改动 (layout.css + responsive.css):
- body { height: 100vh; overflow: hidden; }
- .main-content { height: calc(100vh - header); overflow-y: auto; }
- 移动端(<768px) 保留 body 滚动
- 验收: 桌面任意页仅 1 垂直滚动条(在 main-content 最右)
### 2.2 用量统计卡片化 (I2)

目标: usage 子页重构为 4 卡片网格:
```
┌─ 资源监控 ─────┐ ┌─ 数据源健康 ─────┐
│ CPU 45% ███    │ │ sxsc 98% 12ms  │
│ 内存 62% ████  │ │ tushare 95% 18ms│
│ 磁盘 38% ██    │ │ akshare 88% 40ms│
│ 运行 12.4h     │ │                 │
└──────────────┘ └──────────────────┘
┌─ AI 用量 ───────┐ ┌─ 运维状态 ──────┐
│ 今日 34 次      │ │ 护栏通过率 92%  │
│ 模型Top: deepseek│ │ 调度任务 3 正常 │
│ 峰值 8次/时     │ │ 最近备份 今天   │
└──────────────┘ └──────────────────┘
```

改动: system-page.js usage 子页重构(纯前端) + layout.css 补卡片类; 数据源不变

### 2.3 策略编写页增强 (I3) — 评审调整: PTrade 代码策略 + AI 代写迭代

**策略形态分层**:
- **4 基础策略**(多因子/行业轮动/资金流/指数增强): 保持现状(内置参数化), 可复制微调
- **新策略**: 一律 Python 代码(PTrade 兼容), 存 strategy_defs(type=custom, code 列), 可系统内回测 + 导出/在 PTrade 使用

**三能力**:
1. **新建(AI 代写)**: 用户输入思路(如"小市值+低换手+高股息") → LLM 生成 PTrade 兼容代码(initialize/handle_data/get_history/order) → _ALLOWED_APIS 静态校验 → 保存
2. **复制微调**: 选已有(内置/自定义) → 复制 → AI 协助改代码/参数 或 手动 → 保存"<原名>-副本"
3. **AI 优化迭代**: 选自定义 → LLM 分析代码/回测表现 → 改进版代码 → 确认覆盖/另存 → 再回测 → 多轮迭代

**后端新增**:
- strategy_defs 加 code 列
- POST /api/strategies/custom (AI 代写: prompt → LLM → 校验 → 保存)
- POST /api/strategies/{sid}/copy (复制 → 新 sid)
- POST /api/strategies/{sid}/ai-optimize (LLM 代码建议)
- backtest_engine 识别 custom(strategy_defs 加载 code → PTrade 兼容执行层 → 持仓)

**PTrade 兼容基础**(复用): ptrade.py(_ALLOWED_APIS/render) + templates.py(4 模板) + 导出按钮

**前端**: strategy-write 子页 3 tab(AI 新建/复制微调/AI 优化) + 代码编辑区(语法高亮/校验提示/一键导出)

### 2.4 美林时钟历史周期视图 (I4)

目标: 美林时钟页新增周期时间轴(默认最近 4 轮):
```
2009 ──── 2012 ──── 2016 ──── 2020 ──── 2024 ──── 今
 [第1轮]  [第2轮]  [第3轮]  [第4轮]
 衰→复→过→滞  衰→复→过→衰   ...
 ── 每阶段点击 → 详情弹窗(时长/触发/指标)
```

后端: GET /api/merrill-clock/timeline (聚合 HISTORICAL_TRANSITIONS → {cycles:[{label,stages:[...]}], 最近 4 轮)
前端: merrill.js 新增时间轴渲染(纯 CSS 横向), 点击弹详情(复用 stage detail)

## 3. 需求优先级与排期

| 阶段 | 内容 | 优先级 | 预计规模 |
|---|---|---|---|
| I1 | 滚动条统一 | P0 | 0.5d (纯CSS) |
| I4 | 美林历史视图 | P0 | 1d (后端聚合+前端时间轴) |
| I2 | 用量统计卡片化 | P1 | 1d (纯前端) |
| I3 | 策略编写(Python/PTrade+AI代写) | P1 | 3d (后端4端点+回测适配+前端3tab+AI迭代) |

## 4. 非目标 (Out of Scope)

- 不新增选股/回测业务逻辑(仅适配自定义策略接入)
- 自定义策略不支持 Python 编辑器断点调试(以回测驱动迭代)
- 不做按需加载重构(维持 P2)
- 不改移动端布局骨架(仅滚动收敛)

## 5. 验收标准

1. 桌面端任意页滚动条 <=1 个垂直(在 main-content 最右)
2. 用量统计 4 卡片, 信息全部入卡, 无裸露指标
3. **AI 代写**: 输入策略思路 → 生成 PTrade 兼容代码 → 校验通过 → 保存 → 系统内回测 → 可导出 PTrade 使用; 复制微调/AI 优化迭代可用
4. 美林时钟页展示最近 4 轮历史时间轴, 每阶段点击可看详情
5. 全量测试绿(907+新增) + 覆盖率 >=40 + 前端一致性 103+ 绿

## 6. 风险与依赖

- **滚动改动**: 三端回归; 若破坏回退"仅隐藏页面级滚动条"
- **自定义策略回测**: PTrade 兼容执行层需覆盖常用 API(get_history/order 等); 不支持的 API 返回明确错误提示
- **AI 代写**: 依赖 AI key; 无 key 降级(提示未配置); 生成代码需静态校验防非法 API/注入
- **AI 迭代**: 建议为参考, 用户确认后应用
