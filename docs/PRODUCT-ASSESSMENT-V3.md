## 第一部分: 八维现状评估

### 1. 产品经历 (Product Journey)

**演进史**:
```
v1.0~1.4  [原型]     单用户数据展示, 日历 + 策略 CSV 读取
v1.5~1.8  [功能]     回测引擎 + 视图聚合 + 安全加固
v1.9      [体验]     全局搜索 + CSV 导出 + 多主题雏形
v2.0      [AI 起点]  智能评股升级: 决策仪表盘 + 策略预设
v2.1~2.2  [安全+部署] 密钥加密 + 52测试 + Docker + CI
v2.3~2.4  [产品化]   设计 Token 体系 + 7 主题 + AI 问股 + 初始化向导
v3.0~3.1  [架构]     美林时钟解耦 + 历史周期 + 骨架屏
```

**评估**:
- ✅ 演进主线清晰: 工具 → 单用户 → 多用户 → 产品化, 每代有明确主题
- ✅ 安全/测试/部署意识超前 (v2.1 就建立基线)
- ⚠️ v2.4.0 规划 Vue SFC 迁移失败 → 教训是"小步渐进"而非"全量手术"
- ⚠️ 无用户反馈闭环: 所有迭代方向来自开发者主观判断
- ⚠️ 无数据驱动: 不知道用户最常用哪个页面、哪个功能

**评分**: ★★★☆☆ (有清晰演进但缺用户视角)

### 2. 系统架构 (System Architecture)

**现状**:
```
浏览器 (PWA)
   │ HTTP + JWT
FastAPI (main_new.py, :8000)
   ├── api/v1/          16 个路由模块, ~90 端点
   ├── 业务层           data_parser / views_aggregator / merrill_clock
   │                    ai_evaluator / backtest / market_data
   ├── 调度层           scheduler.py (5 asyncio 任务)
   ├── 存储层           data/*.json (21M) + qresult/*.csv (21M)
   └── 静态             frontend/ (单文件 SPA 6653 行)
```

**评估**:
- ✅ 分层清晰, 模块职责单一, 依赖简单 (15 个)
- ✅ 单进程部署简单, Docker 化完成
- ⚠️ JSON 文件存储: 无事务、无并发控制、无 schema 校验
- ⚠️ ai_evaluator.py 1491 行 + merrill_clock.py 982 行 = 巨型模块
- ⚠️ 前端 3973 行 setup() 单体, 6 个 JS 模块是 10 行占位壳
- ⚠️ 无缓存分层 (市场数据全量内存, 重启全丢)
- ⚠️ 无消息队列/异步任务队列 (长任务阻塞请求线程)

**评分**: ★★★☆☆ (简单可靠, 但扩展性受限)

## 第二部分: 未来产品长远发展建议

### 战略判断

量化选股日历的**独特价值**不是数据展示, 而是:
1. **美林时钟 × 策略选股 × AI 评估** 的三层决策链 (竞品极少具备)
2. **完全自部署** (数据不出本地, 适合对隐私敏感的投资者)
3. **多模型 AI 中立** (不绑定单一供应商)

长期定位: **个人/小团队的 A 股决策操作系统** (Decision OS for A-shares)

### 三阶段发展战略

```
阶段 1 (v3.x): 产品化     当前 → 2027Q1
  把"能用"打磨成"可靠好用": 数据可靠、可运维、体验达标、AI 自动

阶段 2 (v4.x): 平台化     2027Q1 → 2027Q4
  从工具到平台: 开放 API、插件生态、多数据源接入、策略市场

阶段 3 (v5.x): 生态化     2028+
  从平台到生态: 策略分享社区、组合跟投、机构版 (多租户/风控)
```

### 阶段 1 关键建议 (指导当前 v3.x 三文档)

|---|------|------|----------|
| S1 | 数据管线自动化 (tushare 定时拉取 → 自动生成 qresult) | 目前依赖手动 CSV, 产品化的最大短板 | v3.3.0 扩展 |

## 第三部分: 未来模板产品定义 (重点)

### 3.1 产品定义

**名称**: 量化选股日历 (Quant Calendar) — A 股决策操作系统
**一句话**: 基于美林时钟的 AI 驱动 A 股选股决策平台, 自部署、数据私有、模型中立。

### 3.2 目标用户与场景

| 用户 | 场景 | 核心需求 |
|------|------|----------|
| 个人量化投资者 (主) | 每日 10 分钟看信号 + AI 决策 | 数据新鲜、判断可信、操作快 |
| 小团队/工作室 (次) | 多人协作选股研究 | 权限隔离、审计、共享自选 |
| 技术发烧友 (长尾) | 自建数据管线/策略 | 开放 API、插件、文档 |

### 3.3 核心价值主张

```
感知 (美林时钟) → 信号 (策略选股) → 决策 (AI 评估) → 验证 (回测) → 执行 (推送提醒)
  ↑______ 数据层 (多源自动更新) ______↓
        ↑______ 协作层 (多用户/审计) ______↓
```

### 3.4 产品模块蓝图 (目标形态)

| 层 | 模块 | 目标能力 | 现状 |
|----|------|----------|------|
| 数据层 | 数据管线 | tushare/akshare 定时自动拉取, 增量更新, 质量监控 | ⚠️ 手动 CSV |
| 数据层 | 存储 | SQLite 事务 + 每日备份 + 一键恢复 | ⚠️ JSON 无备份 |
| 感知层 | 美林时钟 | 五维评分 + 历史周期 + 阶段预警 | ✅ v3.1 |
| 信号层 | 策略引擎 | 4 策略 + 共识榜 + 自定义策略 (远期) | ✅ 基础 |
| 决策层 | AI 评股 | 多模型 + 流式 + 指标注入 | ✅ v2.4 |
| 决策层 | AI 问股 | RAG 多轮 + 历史记忆 + 组合级分析 | ⚠️ 单轮 |
| 验证层 | 回测 | 前端可视化 + 参数化 + 对比 | ⚠️ 后端有前端无 |
| 执行层 | 推送 | 飞书/企微/钉钉/邮件 + Webhook | ⚠️ 仅飞书 |
| 报告层 | 日报/周报 | 自动生成 + 多渠道分发 | ❌ 无 |
| 协作层 | 用户/组 | 三组权限 + 审计日志 | ⚠️ 无审计 |
| 开放层 | API/插件 | OpenAPI 文档 + API Token + 插件 | ❌ 无 |

### 3.5 非功能目标 (模板产品的硬标准)

| 维度 | 目标 |
|------|------|
| 可靠性 | 数据零丢失, 恢复 ≤ 15 分钟 |
| 可运维 | 5 项监控指标 + 3 渠道告警 |
| 性能 | 常规 API P95 < 500ms, 首屏 < 3s |
| 安全 | CSP/HSTS/限流/密钥加密 持续保持 |
| 可扩展 | 数据源/通知渠道可插拔 |
| 可移植 | Docker 单命令部署, 数据可导出 |

### 3.6 商业模式 (远期参考)

- **免费**: 自部署社区版 (现状延续, 全功能)
- **付费**: 托管版 (SaaS, 免运维) + 专业版 (多租户/风控/团队审计)
- **生态**: 策略市场抽成 (远期 v5)

## 第五部分: 结论

**现状定位**: 量化选股日历已是一个**功能完整的个人级产品** (8/10 功能模块就绪),
但**产品化硬伤**集中在: 数据手动更新、无备份、无监控、回测前端缺失、用户洞察缺失。

**未来方向**: 以"决策操作系统"为长期定位, 三阶段演进;
当前 v3.x 系列聚焦"产品化打磨", 把评估中发现的 5 个关键建议 (S1~S5) 纳入三文档。

**执行建议**: 按修正后的三文档推进 v3.2.0, 每版本发布后回到本文档核对产品目标是否推进。
