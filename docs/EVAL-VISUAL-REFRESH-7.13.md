## 0. 结论摘要

**一句话结论：工程基建是健康的（运行期求解器 + 对比度门禁 + 双模式双色相），但美术表达停在"能用"层面——亮色偏米黄厚重复古，深色偏无彩灰蒙；两者共同的病根是「层级全部由描边承担、品牌色被压成暗色、缺少中间饱和度的过渡色」。**

### 0.1 定性评分（基于运行期 token 与代码审计，非像素统计）

| 维度 | 亮色 | 深色 | 判断 |
|---|---|---|---|
| 面层层级与明度梯度 | 7.5 | 7.0 | 亮度比均 ≥1.18，但亮色靠白卡+米底、深色靠四级近黑灰，都缺"质感差" |
| 中性色相与色温 | 6.0 | **4.5** | 亮色 S16% 米黄偏旧；深色 S10–12% 几乎无彩，色相选择看不出来 |
| 描边与分隔 | **5.0** | **5.0** | 明暗两侧容器描边均按 ≥2.8:1 求解，全站形成"灰线框" |
| 品牌色使用 | 6.0 | 5.5 | 亮色暗金 `#806410`、深色实底 `#907a37`，均无高饱和焦点 |
| 文字层级 | 7.0 | 6.5 | 对比度达标，但 secondary / tertiary / muted 明度差过小 |
| 组件质感（圆角/阴影/玻璃） | 6.0 | 5.5 | 亮色 raised = card 且阴影 alpha 0.05；深色纯黑阴影在近黑底上不可见 |
| 图表与数据语言 | 6.0 | 6.0 | 分类色板为同色相明度阶梯，跨序列区分度弱；涨跌填充/文字档已分离 |
| **综合** | **6.4** | **5.7** | 亮色主要问题是"旧"，深色主要问题是"灰" |

### 0.2 不要破坏的既有能力

- `applyTheme(mode, hue)` 单一入口、切主题清理内联残留、7 色相 + 中性无色相档。
- 4 个求解器：`_lumL`（感知亮度归一）、`_gradL`（渐变/焦点/边界反解）、`_panelL`（浅底面板）、`_borderL`/`_neutralRamp`（跨色相边界与中性族）。
- 明暗同名 token 契约、EP 变量桥、涨跌填充档/文字档分离、14 套配置 × 36 项对比度门禁。
- A 股**红涨绿跌**语义固定，不随品牌色相变化（用户约定，不得改动）。

## 1. 亮色模式现状诊断

### 1.1 运行期真实色值（金色相 45 / 蓝色相 220 / 中性）

| 语义 token | gold(45) | blue(220) | neutral | 说明 |
|---|---|---|---|---|
| `--surface-canvas` | `#eceae4` hsl(45,16,91) | `#e4e7ec` | `#e8e8e8` | 页面底色，暖米黄 |
| `--surface-card` / `raised` / `input` | `#ffffff` | `#ffffff` | `#ffffff` | 三档同值，凸起靠阴影承载 |
| `--surface-sunken` | `#eae8e1` | `#e1e4ea` | `#e6e6e6` | 凹陷面 |
| `--surface-hover` | `#f4f2ec` | `#eceef4` | `#f0f0f0` | 悬浮态 |
| `--qc-border` | `#a09883`（2.86:1 vs 白卡） | `#9199aa` | `#878787` | 容器描边 |
| `--border-control` | `#8b8165` | `#73809a` | `#818181` | 控件边界，≥3:1 |
| `--text-primary/secondary/tertiary` | `#22201b` / `#5b5648` / `#6c6551` | 同明度冷色阶 | 灰阶 | 对比度 12.4 / 7.3 / 5.8 |
| `--qc-muted-foreground` | `#6a6558` | `#585e6a` | `#616161` | 表头/标签 |
| `--primary-color` / `--primary-text` | `#917215` / `#806410` | `#3871e3` / `#1b5cdc` | 灰 | 品牌文字对白卡 5.64:1，对页底仅 **4.65:1** |
| `--brand-soft-bg` / `--brand-soft-text` | `#fcf3d9` / `#80630e` | `#d9e5fc` / `#154cbc` | 灰 | 激活底饱和度 85% |
| `--qc-shadow-md` | `rgba(31,29,26,0.05)` | 同值 | 同值 | 结构层阴影极淡 |

### 1.2 问题清单

- **L1（P1）米黄面层 + 高饱和浅黄激活底，饱和度为两极分布**：面层 S16%、激活底 S85%，缺少 20–40% 的中间过渡档。视觉上是"旧纸底 + 荧光黄选中"，而非现代专业终端的克制暖灰。
- **L2（P0）容器描边过强**：`#a09883` 对白卡 2.86:1（门禁 `tests/test_dark_residue.py::BORDER_MIN = 2.8` 强制），每张卡片一圈明显灰线；与"卡片靠阴影浮起"的设计意图冲突，屏幕像线框图。
- **L3（P1）层级只靠线，不靠影**：`--surface-raised = --surface-card = #fff`，`--qc-shadow-*` alpha 仅 0.05；弹层/浮起卡片与内容卡难以区分。`--glass-sheen` 为白→透明高光，在白卡上几乎不可见。
- **L4（P1）品牌文字余量过薄**：`--primary-text` 对白卡 5.64:1，但对画布仅 4.65:1，距 AA 门槛 0.15。任何画布色相/明度微调都可能使链接、标签、数字破线。
- **L5（P2）文字三级层次挤在 32–38% 明度**：secondary `#5b5648`(L32)、tertiary `#6c6551`(L37)、muted `#6a6558`(L38)，三级与 muted 几乎同色，信息层级靠字号而非颜色拉开。
- **L6（P1）图表定性色板区分度弱**：历史实测（`EVAL-UI-COLOR-SYSTEM.md §2.7`）分类色为同一色相 6 个明度档，多序列图接近同色；涨跌填充/文字档已分离，但图表 tooltip、轴线尚未与整体 token 语言统一。

### 1.3 亮色模式判断

**不是对比度不合格，而是审美过期**：文本 0 处低于 AA、面层比 1.20:1 达标，问题集中在色温、饱和度分布、描边强度与浮起感。优化应以"减线、降黄、补阴影、加中间饱和档"为主，而不是继续调对比度。

## 2. 深色模式现状诊断

### 2.1 运行期真实色值（金色相 45 / 蓝色相 220 / 中性）

| 语义 token | gold(45) | blue(220) | neutral |
|---|---|---|---|
| `--surface-canvas` | `#11100e` hsl(45,10,6) | `#0e0f11` | `#0f0f0f` |
| `--surface-card` | `#282620` hsl(45,11,14) | `#202228` | `#242424` |
| `--surface-raised` | `#39362d` hsl(45,12,20) | `#2d3139` | `#333333` |
| `--surface-sunken` | `#0b0b09` | `#090a0b` | `#0a0a0a` |
| `--qc-border` | `#746d57`（2.77:1 vs 卡） | `#5f6a7e` | `#6c6c6c` |
| `--text-primary/secondary/tertiary` | `#efeeec` / `#bdbab2` / `#a6a296` | 同明度冷色阶 | 灰阶 |
| `--primary-solid` / `--brand-soft-bg` / `--brand-soft-text` | `#907a37` / `#574819` / `#f1ca53` | `#375590` / `#192e57` / `#77a0f4` | 灰 |
| `--market-up-fill` / `--market-down-fill` | `#ff6b6b` / `#4ade80` | 同值（语义固定） | 同值 |

### 2.2 问题清单

- **D1（P0）面层彩度 10–12%，色相形同虚设**：四级面层 `#11100e / #191815 / #282620 / #39362d` 全是近无彩暖灰，用户切换色相几乎看不出底色变化；屏幕整体读成"灰蒙蒙"。
- **D2（P0）无高饱和焦点**：实底品牌色被刻意压到 `hsl(h,45,39%)`（`#907a37`）、激活底 `#574819`，只有涨跌色是亮色。整屏缺少一个可追随的强调点。
- **D3（P1）容器描边同样过强**：`#746d57` 对卡片 2.77:1，亮灰线铺满深色屏幕，强化灰线框感。
- **D4（P1）文字三级集中在 62–72% 明度**：`#bdbab2 / #a6a296 / #aba79c` 三种灰差异小；同时 `--qc-foreground`(93%) 与实际 `--text-primary` 同值但不同名，存在双源认知成本。
- **D5（P2）纯黑阴影在近黑底上不可见**：深色阴影 rgba(0,0,0,.45–.55) 对 `#11100e` 无层次贡献，浮层只能靠 `--surface-raised` 明度差区分。

### 2.3 深色模式判断

**亮度阶梯工程上达标（1.20–1.30:1），但感知层级弱**：层级仅由亮度差承载，且全部挤在无彩灰区间。解法不是继续拉大明度差（会变"纯黑+亮灰"刺眼），而是**给面层适度染色 + 弱化描边 + 单点高饱和强调**。

| token | 现状 | 候选 | 验证 |
|---|---|---|---|
| `--surface-canvas` | `hsl(45,16,91)` `#eceae4` | `hsl(45,10,91)` `#eae9e6` | 画布/白卡 **1.21:1**（门禁 ≥1.18） |

| `--qc-border`（装饰线） | `#a09883` 2.86:1 | `hsl(45,12,70)` `#bcb7a9` **2.00:1** | 与深色共用 BORDER_MIN=2.0 |
| `--text-tertiary` | `#6c6551` 5.82:1 | `hsl(45,10,40)` `#706b5c` **5.31:1** | 拉开 secondary(L32)/tertiary(L40) |
| `--qc-shadow-md` | `rgba(31,29,26,.05)` | `rgba(31,29,26,.10–.14)` | 凸起面重新靠阴影承载 |
| 品牌文字求解基准 | 对白卡 5.64 / 对画布 4.65 | **双基准取严**，对画布 ≥4.8:1 | 留出 0.3 安全余量 |

亮色方案**不提高**激活底饱和度（维持 ≤60% 并配浅底彩字），避免回到"荧光黄选中块"。

### 4.3 整体美术原则（不仅配色）

1. **60/30/10 面积律**：中性面 60–70%、辅助面 25–30%、品牌与功能点缀 ≤10%；品牌色只出现在选中条、焦点、关键数字、主 CTA。
2. **层级三通道**：亮色 = 白卡 + 阴影 + 留白；深色 = 染色面层 + 内高光 + 少量描边。描边不再单独承担层级。
3. **饱和度假梯**：面层 10–20% → 辅助面 20–40% → 强调 60–85%，消除两极分布。
4. **文字角色化**：primary 93%(暗)/12%(亮)，secondary 与 tertiary 明度差 ≥8 个百分点；图表轴标签沿用 tertiary。
5. **数据可视化语言**：定性色板改为跨色相（保留红涨绿跌语义），涨跌文字强制走 `-text` 档，tooltip 跟随 `--surface-raised`。
6. **质感收敛**：圆角只用 6/8/12/16；阴影分浮层三档；毛玻璃仅用于浮层，结构层用顶部 1px 高光。
7. **状态完整**：hover/focus/active/disabled/loading 五态在明暗两侧一致；过渡 0.2s 且尊重 `prefers-reduced-motion`（已有，不回退）。

## 5. 门禁、约束与风险

| 约束 | 现状 | 调整需求 |
|---|---|---|
| `test_surface_ladder.py` MIN_RATIO=1.18 | 明暗均达标 | 候选方案仍达标，无需改门禁 |
| `test_dark_residue.py` BORDER_MIN=2.8 | 明暗描边 ≥2.8:1 | **需下调至 2.0** 并注明"装饰线弱于控件边界" |
| `test_theme_contrast.py` 文本 4.5 / 非文本 3.0 | 14 套全通过 | `--border-control` 保持 3:1 不动；品牌文字求解基准改为双取严 |
| `test_color_tokens.py` 双源 ≤98 / 语义对称 / 禁硬编码 | 通过 | 不新增双源令牌；值只在三个 token 源文件改动 |
| `_neutralizeTokens` / hue drift ≤25° | 中性档纯灰、暖中性族 | 保持色相联动，避免回到固定海军蓝 |
| dev / ops 双目录 | 前端 CSS/JS 当前一致 | 实施阶段需同步两份（文档暂只在 dev） |

**主要风险**：① 降描边后弱边框控件在密集表格中与背景融合 —— 用控件边界 3:1 与 hover 面兜底；② 亮色加阴影后浮层在浅底上出现"脏边" —— 限定 alpha ≤0.14 并用中性色而非纯黑；③ 品牌文字余量不足 —— 求解基准改为双取严并加回归断言。

## 6. 建议优先级（供 PRD 裁剪）

- **P0**：深色面层染色（D1/D2）、明暗描边弱化（L2/D3，含门禁调整）、品牌文字双基准求解（L4）。
- **P1**：亮色画布去黄 + 阴影层级（L1/L3）、文字三级拉开（L5/D4）、图表定性色板与 tooltip（L6/X5）。
- **P2**：组件质感与圆角/阴影收敛、浮层内高光、中性档质感（X1/X2 的细节）。
