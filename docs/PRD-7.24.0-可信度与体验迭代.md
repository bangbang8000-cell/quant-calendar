# PRD-7.24.0：可信度重建与体验迭代

> 状态：**待批准**（2026-11-28 提交）
> 基线：`APP_VERSION = 7.23.0`
> 前置调研：`QuantCalendar-v7.23-全面评估报告.md`
> 编写规则：本 PRD 只描述「做什么」与验收口径，不描述「怎么做」，不含任务拆分与排期。
> **阶段门**：本 PRD 批准 → 编写《开发与测试计划》→ 用户再次批准 → 才允许编码与测试执行。

---

## 1. 背景与问题陈述

v7.23.0 已具备完整的信息架构、45 万行级前端资产、450 个测试文件与 GitLab 四阶段流水线，但**结果可信度**与**运行闭环**存在结构性缺陷。本次评估确认：

1. **回测结果不可信**：绩效年化使用"日收益算术和"指数放大，叠加实际只有 5–8 个持仓日期，可稳定产出 `+4.97e12%` 量级；旧回测通道仍用随机数模拟收益；回测面板取不复权价；涨跌停/ST/停牌/T+1/整手/流动性均未进入成交链路。
2. **数据闭环断档**：线上 2026-11-26 12:22 至 11-28 09:21 服务中断，周五收盘任务未触发；调度器无补跑、无错过告警；持仓产物只按"信号日"落盘，"下一交易日持仓"依赖前向填充且截止到今天。
3. **行情时效不足**：大盘页只在"进入页面时恰处交易时段"才挂 10 分钟定时器；收盘后缓存直接钉到次日 9:25，可能把旧收盘价锁一整晚；数据源失败时静默返回随机 mock。
4. **既有能力被埋没**：自选股等权均分建仓（总资金、100 股整手、尾差现金）已实现，但入口藏在二级页按钮里，缺少"一键同步/自动同步/差异提示"。
5. **视觉与配置语言不统一**：股票列表策略区被 `1fr` 无限拉宽；择时"持有"与"观望"同为灰色；研究域混用三套列表/容器语言；设置页 9 个主题色 + 8 个 legacy 主题并存；AI 与数据源配置全展开。
6. **加载与工程效率**：2.4MB 构建产物、780KB 业务总包、464KB 单文件 CSS；重计算仍在点击时发生；GitLab 无 deploy，GitHub Actions 与 GitLab 双流水线口径未分工。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 可测判据 |
|---|---|---|
| G1 | 回测结果可信 | 单一引擎；T 收盘信号 → T+1 09:30 开盘成交；约束完整；年化仅在样本 ≥18 个月时输出 |
| G2 | 数据闭环不断档 | 收盘后自动生成下一交易日持仓；停机/错过可补跑并留痕；日历可选到下一交易日 |
| G3 | 行情时效达标 | 交易时段数据延迟 ≤30 秒；收盘终值当日确认；模拟数据不得伪装真实数据 |
| G4 | 既有能力可达 | 自选股一键/自动同步进组合，总金额等权均分且满足整手 |
| G5 | 视觉语言统一 | 三处列表同一栅格；信号四档配色；研究域同一页面骨架；主题色收敛到 6 个 |
| G6 | 性能与工程闭环 | 主要页面命中预计算缓存；首屏 JS 下降 ≥30%；GitLab 负责迭代、GitHub 负责发布 |

### 2.2 非目标

- 不改一级/二级信息架构，不改导航形态三档机制，不重写组件库，不引入新 UI 框架。
- 不改变 A 股"红涨绿跌"语义，不改主题模型（mode × hue）。
- 不做移动端新功能，不做权限模型改造。
- 不新增外部行情付费源；复用现有 tushare / akshare / DWH / 腾讯行情降级链。
- 本轮不含任务拆分、工时与排期。

## 3. 用户与场景

- **主要用户**：量化研究员、交易员、策略开发者。
- **典型场景**：
  1. 收盘后查看"明天该持有什么"并据此执行；
  2. 对策略做回测，判断能否上线；
  3. 盘中盯大盘与自选股；
  4. 从自选股一键生成等权组合；
  5. 调整主题与 AI/数据源配置。
- **核心诉求**：数字可信、收盘后一定有结果、盘中数据是新的、常用能力一步可达。

## 4. 统一口径定义（本迭代的硬约束）

> 以下口径对回测、日历、策略执行、展示层同时生效，任何模块不得自行另立一套。

| 项 | 口径 |
|---|---|
| 信号时点 | T 日收盘后计算，仅使用 T 日及之前数据 |
| 成交时点 | **T+1 交易日 09:30 开盘价成交**（用户决策） |
| 成交失败 | T+1 停牌/一字涨停（买入）或一字跌停（卖出）→ 顺延至下一可交易开盘；连续 5 个交易日无法成交则放弃该笔并记录原因 |
| 收益起算 | 自 T+1 开盘成交后起算，T+1 开盘前不享受该持仓收益 |
| 复权 | 统一**前复权（qfq）**，信号、成交、收益同口径；不复权数据禁止进入回测 |
| 成本 | 佣金万 3（单笔最低 5 元，双边）+ 印花税万 5（仅卖出）+ 滑点（默认 0.05%）+ 冲击成本（默认 0.03%） |
| 涨跌停 | 主板 ±10%、创业板/科创板 ±20%、ST ±5%；触及涨停不可买、跌停不可卖；一字板按不可成交处理 |
| 停牌 | 停牌日不可交易；复牌日收益按停牌前后可交易价差累计，不得压缩成单日异常收益 |
| 交易单位 | 买入 100 股整数倍；科创板 688/689 单笔不少于 200 股；资金不足向下取整，余款留现金 |
| T+1 | 当日买入不可当日卖出 |
| 年化 | 仅当回测区间**数据跨度 ≥18 个自然月且有效交易日 ≥360** 时输出；否则 `annual_return = null`，前端显示「样本不足（<18 个月）」 |
| 累计收益 | 以复利净值计算，`total_return = 期末净值 / 期初净值 - 1`；禁止使用日收益算术和 |
| 持仓产物日期 | 收盘 T 日计算，落盘到 **T+1（下一交易日）** 目录，即"生效日" |
| 行情时效 | 交易时段 ≤30 秒；午休/收盘各补刷一次；收盘后 15:05 起短 TTL 重试直至确认当日 `trade_date` |
| 模拟数据 | 不得写入持久缓存；响应必须带 `is_mock=true`，前端显著标识，不得与真实行情混排 |

## 5. 需求清单

优先级：P0 = 必须；P1 = 强烈建议；P2 = 视评审取舍。

### 批次一：可信度重建（P0）

#### FR-1（P0）回测引擎统一与绩效口径修正

**范围**
- 退役 `BacktestEngine.run_backtest` 的随机模拟路径；`/api/backtest/*` 与策略研究入口全部委托统一回测器。
- 统一结果契约：`total_return / annual_return / max_drawdown / sharpe / win_rate / total_days / sample_months / engine_version / cost_model_version / adjust_mode / execution_mode / warnings[]`。
- 绩效改为复利口径；年化使用实际净值与区间跨度，并受第 4 章样本门槛约束。
- 历史回测记录新增口径字段；旧记录只读归档，不与新结果混排。

**验收**
- 同一策略在"回测工作台""策略研究→回测""策略管理→回测"任入口，输入相同参数得到逐字段一致的结果。
- 构造 5 个交易日的样本：`annual_return` 必须为 `null`，并返回 `warnings=["样本不足（<18个月）"]`。
- 任意结果不再出现 `|annual_return| > 1000%` 且无警告的情况；超出阈值必须带异常诊断码。
- 结果字段中 `execution_mode = "T+1_open"`、`adjust_mode = "qfq"` 可被前端读取展示。

#### FR-2（P0）撮合层与交易约束

**范围**
- 新增独立撮合语义：信号目标权重 → 可成交权重 → 成交价 → 收益。策略不得直接乘收益。
- 严格执行第 4 章：T+1 09:30 开盘成交、涨跌停/ST/一字板不可成交、停牌顺延、T+1 限制、100 股整手、资金不足、成本四项。
- 回测收益面板统一取 `v_daily_qfq`；成交价取前复权开盘价。
- 流动性上限（成交额占比/换手率）作为 P1 子项，先做固定阈值拦截，再评估动态阈值。

**验收**
- 用例 A：全仓买入一只 T+1 一字涨停股 → 无成交、无收益，原因可查。
- 用例 B：持有股票 T+1 停牌 → 顺延至复牌开盘成交，收益不出现单日 -20% 级别跳变。
- 用例 C：ST 股票 ±5% 之外的价格被拒绝成交。
- 用例 D：10 万元买 3 只 100 元股票 → 每只 300 股（整手），余款留现金，现金 ≥0。
- 用例 E：买卖双边成本均被扣除，卖出额外扣印花税，佣金不足 5 元按 5 元计。
- 用例 F：同日买入的股票当日不可卖出（T+1）。

#### FR-3（P0）未来函数与过拟合门禁

**范围**
- 策略注册与回测前强制执行未来函数检查：对 T 日之后数据做扰动/截断，信号不得变化。
- 内置 17 个策略全部纳入检查；未通过者禁止上线/禁止展示回测结论。
- 强制样本外检查（样本内/外切分 + walk-forward 至少一种）。
- `credibility_guard` 从"提示"升级为"阻断展示"：样本不足、成本缺失、无基准、未过未来函数检查时，结论标记为不可信。

**验收**
- 17 个内置策略全部产出检查报告（通过/不通过 + 原因）。
- 人为注入一个 `shift` 缺失策略 → 门禁必须拦截并给出定位信息。
- 不可信结果的年化与净值曲线在页面上显示为"不可信/样本不足"，不得以正常样式展示。

#### FR-4（P0）历史数据回补与最小样本保障

**范围**
- 行情与持仓历史回补至 ≥18 个月；DWH 缺失时给出明确的构建入口与进度。
- 回测默认窗口保持 18 个月；若用户自定义区间不足 18 个月，按 FR-1 输出"样本不足"。
- 前端在回测表单显式展示"实际生效区间 / 数据跨度 / 有效交易日 / 是否满足 18 个月"。

**验收**
- 默认参数回测时，`sample_months ≥ 18` 且 `total_days ≥ 360`（数据可用时）。
- 数据不足时，表单与结果页均展示缺口原因与修复入口，不静默降级。
- 持仓目录连续覆盖最近 18 个月交易日（允许节假日缺口，不允许整月缺失）。

#### FR-5（P0）收盘计算、次日生效与调度补跑

**范围**
- 每个交易日 T 收盘后（沿用 20:00 计划）计算 T+1 持仓，产物落盘 `data/holdings/{T+1}`；信号日为 T。
- 服务启动时若"今日为交易日、已过计划时间、今日任务未执行"，自动补跑一次（幂等）。
- 错过任务、执行失败、产物 0 行均写入调度历史并进入通知铃铛。
- 日历读取兼容历史"信号日"目录；新产物按"生效日"读取。
- 日历页空态区分：非交易日 / 尚未生成 / 生成失败，并提供"立即生成今日持仓"。

**验收**
- 交易日 20:00 后（或服务 20:00 后启动）10 分钟内，`data/holdings/{下一交易日}` 存在且日历可选。
- 连续两次触发同一日期任务，不产生重复目录/重复持仓（幂等）。
- 停机跨过计划时间后重启，调度历史出现"补跑成功"记录。
- 非交易日不生成目录，前端提示为"非交易日"。

### 批次二：核心体验与工程闭环（P1）

#### FR-6（P1）行情时效与模拟数据治理

**范围**
- 交易时段 15–30 秒刷新（优先复用现有实时通道）；午休、收盘后各补刷一次；页面重新可见时立即刷新。
- 收盘后 15:05 起以短 TTL 重试，确认 `trade_date == 今日` 后转长 TTL；交易日判断统一走交易日历，覆盖法定节假日。
- 数据源不可达时返回明确失败或 `is_mock=true`，mock 不写缓存，前端显著标识。
- 页面展示"数据时间 / 下次刷新时间 / 数据源"。

**验收**
- 交易时段连续观察 5 分钟，页面数据时间与当前时间差 ≤30 秒。
- 15:05 后首次打开页面，能在一个刷新周期内拿到当日终盘。
- 数据源断开时页面出现"模拟数据/不可用"标识，恢复后自动回到真实数据。
- 国庆/春节等节假日不出现"缓存到错误日期"。

#### FR-7（P1）持仓组网：自选同步、一键与总金额均分

**范围**
- 在「智能评估 → 组合持仓」提供"持仓组网"操作区，并支持从自选页一键进入。
- 三个动作：「同步自选股（差集加入）」「按总资金重新均分」「自动同步（开关）」。
- 自动同步规则：**只增不删**；自选删除时提示"仍在组合中"，由用户确认是否剔除。
- 复用现有等权算法：总资金等权、100 股整手（科创板 200 股）、尾差留现金；已有持仓保留成本价。
- 常驻摘要：总资金 / 已投入 / 剩余现金 / 标的数 / 整手规则；预览表展示"手数 × 100 × 现价 = 金额"。
- 幂等：同一计划重复确认不重复加仓（沿用计划指纹）。

**验收**
- 新增 1 只自选股后点"同步"，该股进入组合，金额按最新总资金重新均分且仍满足整手。
- 100 万 / 10 只自选 → 每只约 10 万向下取整到 100 股，剩余现金 ≥0 并在摘要展示。
- 删除自选股后组合不变，页面出现差异提示。
- 重复点击"确认建仓"不产生重复持仓。

#### FR-8（P1）收盘后预计算与前端加载性能

**范围**
- 新增收盘后预计算流水线（**分批执行，用户已确认**）：15:30 行情类（大盘指数终值、日历日/周/月/年视图）、18:00 研究类（共识 TopN、策略概览指标、自选择时矩阵）、20:00 策略类（默认参数因子 IC/分层、默认形态基线分）。
- 每项写入缓存并记录数据版本；提供 `/api/precompute/status` 展示"预计算于 xx:xx / 完成项 / 数据版本"。
- 前端：页面级懒加载 + 二级导航 hover 预取；请求层先渲染缓存再后台刷新；列表统一虚拟滚动。
- 体积目标：`vendor-ep` < 500KB，首屏 JS 总量下降 ≥30%，并接入体积预算门禁。

**验收**
- 收盘预计算完成后，次日首次打开概览/日历/策略概览，接口 P95 < 300ms（命中缓存）。
- 页面顶部可见"数据预计算于 …"角标；未完成时展示进行中状态。
- 首屏 JS 体积达标，构建门禁在超预算时失败。
- 弱网下先出骨架/缓存数据，不出现整页空白。

#### FR-9（P1）策略研究界面统一

**范围**
- 研究域 8 个二级页统一为同一页面骨架：页面头（标题 + 说明 + 主操作）→ 筛选工具条 → 内容面板（统一面板头/工具条/空态/错误态）。
- 列表统一优先 `el-table`；禁止新增原生 `<table>`；对比小表必须套统一外壳。
- 清理一次性别名类；内联样式收敛到 ≤5 处且仅限主题派生色；容器统一一套。
- 新增研究域样式门禁：禁止内联色值、禁止新增 `bt-*` 原生表、限制工具类别名数量。

**验收**
- 8 个页面容器圆角/内边距/标题字号一致（截图对比）。
- 研究域内联 `style` 数量 ≤5；无新增硬编码色值。
- 新增页面模板通过门禁。

#### FR-10（P1）工程流程：GitLab 迭代、GitHub 发布

**范围**
- **GitLab = 迭代开发流水线**：功能分支/MR 与 master 合并前跑全量门禁（lint、单测、覆盖率、对拍、PIT、性能、前端构建、体积预算）。
- **GitHub Actions = 正式发布流水线**：仅在发布 tag 时执行打包、签名、制品归档与发布说明生成；日常提交不跑全量。
- 本地新增一键预检（`verify`），覆盖 ruff + 单测 + 前端构建 + 关键门禁，失败即阻断提交。
- 版本号单一来源：`APP_VERSION` 为权威，构建注入前端与制品名；CI 校验 `main_new.py` / `package.json` / tag 三处一致。
- 部署：GitLab 新增 manual deploy 阶段（制品解包），排除 `.env / data / .venv`，执行迁移 + 健康检查 + 失败回滚；禁止自动直发生产。

**验收**
- 本地一条命令完成提交前预检。
- GitLab 在 master 合并/MR 时跑迭代门禁；GitHub 仅在 `v*` tag 触发发布流水线，日常 push 不触发发布。
- 部署使用制品而非手工复制源码，敏感/环境文件默认排除，失败可回滚。
- 三处版本号一致，门禁可拦截不一致。

#### FR-16（P1）回测结果可删除

> 编号按评审追加顺序编排，归属批次二（见 §6）。

**范围**
- 现状基线：研究历史页已有单条删除（`DELETE /api/strategies/research-history/{eid}` 直接委托 `research_store.delete_experiment`），但回测工作台与策略管理回测记录无删除入口，且无批量、无审计、确认与跨页一致性不足；本 FR 补齐这些缺口。
- 三个入口同时提供删除能力：回测工作台历史列表、策略研究→实验面板、策略管理→回测记录。
- 数据仍以 `research_experiments(type=backtest)` 为唯一源，不新增第二套存储；legacy `backtest_history.json` 只读记录仅标注"旧版记录"，不提供删除入口。
- 支持单条删除与批量删除（勾选，单次上限 50 条）；行内操作与顶部批量操作并存。
- 二次确认：弹窗展示"将删除 N 条回测结果"及策略名/创建时间/区间摘要；批量删除需额外勾选确认框。
- 权限沿用现有"非游客可操作"；每次删除写审计（操作者、来源入口、被删记录 id/subject/created_at/summary 摘要、成功或失败）。多用户归属隔离不在本轮范围。
- 删除为硬删除，不提供回收站（列入后续版本）。
- 一致性：删除后列表、条数、概览统计与"对比"选择器即时刷新；若详情页/对比页引用了被删记录，提示"记录已删除"并返回列表。
- 边界：删除回测结果不影响策略定义、启停状态、持仓产物、日历与实盘执行记录。
- 接口契约：单条删除不存在返回 404；批量删除返回 `{deleted: n, not_found: [ids]}`，部分 id 不存在不视为整体失败。

**验收**
- 三个入口均可删除单条；删除后刷新页面不再出现，条数同步减少。
- 勾选 3 条批量删除 → 一次确认后全部消失，审计中可查到对应 3 条记录（或 1 条含 3 个 id 的批量记录）。
- 取消二次确认 → 不删除、无审计写入。
- 删除后策略本身仍可正常运行与再次回测；日历/持仓不受影响。
- 重复删除同一 id：第二次返回 404 / not_found，不出现 500。
- 游客调用删除接口 → 401/403。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 回测口径变更导致历史结果不可比 | 结果新增 `engine_version / execution_mode / adjust_mode`，旧记录只读归档 |
| 前复权切换改变曲线形状 | 发布说明明确为"纠错"；提供旧口径归档查询 |
| T+1 开盘成交需要开盘价面板 | 先确认 DWH 开盘价完整性；缺失时降级为当日收盘并显式标注 |
| 持仓产物从信号日改为生效日 | 读取层兼容两种目录；迁移脚本 + 回归用例 |
| 停机补跑重复执行 | 计划指纹 + 当日执行标记，幂等 |
| 预计算与实时刷新冲突 | 预计算结果带数据版本，实时接口命中新版即失效 |
| 主题色收敛影响用户偏好 | 建立旧 hue → 新 hue 映射（粉/橙/靛映射到最近预设） |
| GitHub/GitLab 双流水线口径漂移 | 明确分工：GitLab 迭代门禁、GitHub tag 发布；日常 push 不触发发布 |
| CSS 合并产物漏重建 | CI 校验 `app.css` 与源文件哈希；本地预检包含 `build_css` |
| 回测结果误删 | 二次确认 + 批量上限 + 审计留痕；删除不触碰策略与持仓；回收站列入后续 |

## 10. 未决事项与假设

- `[Assumption-1]` 目标版本命名采用 **7.24.0 / 7.25.0 / 7.26.0**；若与版本治理口径冲突，以 `APP_VERSION` 单一来源为准。
- `[Assumption-2]` "18 个月最小样本"解释为：数据跨度 ≥18 个自然月且有效交易日 ≥360；不足时不出年化、只出区间收益与净值曲线。
- `[Assumption-3]` T+1 09:30 成交价取"前复权开盘价"；若数据源只提供不复权开盘价，按当天复权因子换算后使用。
- `[Assumption-4]` 流动性上限首版采用固定阈值（如单票成交额占当日成交额 ≤5%），动态阈值列入后续版本。
- `[Decision-1]` 收盘后预计算采用**分批时点（用户已确认）**：15:30 行情、18:00 研究、20:00 策略；时点允许通过配置调整，但默认口径固定为此三批。
- `[Assumption-6]` 6 个主题色为 金/蓝/红/绿/紫/青；粉 320、橙 25、靛 250 彻底移除并做偏好映射。
- `[Assumption-7]` 回测结果删除沿用"非游客即可操作"（现有 experiments 表无归属字段）；删除为硬删除并写审计，回收站与多用户归属隔离列入后续版本。
