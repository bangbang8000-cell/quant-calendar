# 量化选股日历 UI/UX 提质评估报告

> **文档版本**: v1.0 | **日期**: 2026-08-11 | **基线**: v3.8.2
> **定位**: 评估文档（非需求文档）—— 识别现状问题、机会分层、给出实施建议与版本规划
> **背景**: 用户要求"界面 UI 质的提升 + 交互逻辑优化"，让软件更好用、更智能、更便捷、更高效；评估完成后数据自动化（原 v3.11 主题）顺延至本版本之后

---

## 1. 现状基线（前端架构快照）

### 1.1 技术栈与文件分布

| 类别 | 文件 | 规模 | 说明 |
|------|------|:--:|------|
| 模板 | `frontend/index.html` | 1118 行 | 登录页 + 主界面骨架 + **13 个 el-dialog** 全部内联 |
| 逻辑 | `frontend/js/app-logic.js` | 4124 行 | 巨型 `setup()`：全部状态 + 全部 API 调用 + 全部业务逻辑 |
| 页面组件 | `js/components/*.js` 7 个 | ~1700 行 | sidebar/global-header/strategies/calendar/ai/research/system |
| stub 模块 | `js/{calendar,strategies,ai,system,users}.js` | 各 10 行 | **空壳**，声明"新逻辑写此文件"，实际未迁移 |
| 设计令牌 | `css/tokens.css` | 64 行 | 间距/圆角/字号/阴影/语义色已定义 |
| 主题 | `css/themes.css` | 3489 行 | 多主题（含 Element Plus 覆盖） |
| 布局/动画/响应式 | `layout.css` / `animations.css` / `responsive.css` | ~500 行 | 已有基础 |
| 图标/图表 | `icons.js` / `echarts-theme.js` / `charts.js` | ~250 行 | ECharts 已集成 |

**模式**: Vue3 + Element Plus + ECharts，**零构建**（CDN 直接引用），组件经 `window.__quantComponents` 注册，状态经 `provide/inject` 共享。

## 2. 问题诊断

### 2.1 架构层（P0，制约后续所有 UI 工作）

| # | 问题 | 影响 | 证据 |
|---|------|------|------|
| A1 | `app-logic.js` 4124 行单文件，全部状态与逻辑耦合 | 任何 UI 改动都要在大文件中精确定位；无法单元测试 | `setup()` 内 4000+ 行 |
| A2 | 5 个 stub 模块声明模块化但未落地 | "模块化"名存实亡，新功能仍写回 app-logic | `calendar.js` 等 10 行空壳 |
| A3 | 13 个 dialog 全部内联在 index.html | 模板无法复用、难以维护；与组件化路线矛盾 | index.html 413-1032 行 |
| A4 | 股票列表全量 DOM 渲染（无虚拟滚动/分页） | 2472 只 × 多个列表 → 首屏卡顿、内存高 | consensus-item v-for 无限制 |

### 2.2 交互层（P1，直接影响"好用/便捷/高效"）

| # | 问题 | 影响 | 证据 |
|---|------|------|------|
| I1 | **命令面板是未完成功能**：只有 `commandPaletteVisible` state，模板无对应 UI | `Ctrl+K` 按下无反应；"便捷"目标最大缺口 | app-logic.js:534 有 state，index.html 无模板 |
| I2 | 全局搜索只能搜股票，不能搜功能/菜单/指令 | 功能发现性差 | header 仅 el-autocomplete 搜股票 |
| I3 | 数据加载无缓存、无后台静默刷新 | 每次刷新全量重拉，用户等待 | `refreshCalendarData` 全量 |
| I4 | 移动端是桌面版降级（底部导航 + 同结构） | 375px 体验差，未针对性设计 | responsive.css 235 行 |
| I5 | 空状态/加载失败/错误提示风格不统一 | 视觉噪音 | empty-state/Error 各页面不一致 |

### 2.3 视觉层（P2，"质的提升"主战场）

| # | 问题 | 影响 |
|---|------|------|
| V1 | 设计令牌已定义但**落地不彻底**：模板大量硬编码 `rgba(...)`、`font-size: var(--font-sm)`、`#E63946` 等 | 一致性靠人肉，主题切换有遗漏 |
| V2 | 信息密度过高：卡片内多行内联样式堆叠 | 扫读困难，重点不突出 |
| V3 | 图表交互浅：仅周期切换 + 缩放，无联动/十字线/多图联排 | 专业度不足 |

### 2.4 智能化机会（P2，结合 v3.10 已有成果）

| # | 机会 | 依据 |
|---|------|------|
| S1 | 数据源健康度可视化面板 | v3.10 已建 `/api/system/metrics` data_sources 健康指标，前端未消费 |
| S2 | "今日一屏"智能首页：聚合美林时钟 + 市场情绪 + 池变动 + 健康度 | 各数据已有 API，缺聚合视图 |
| S3 | 智能指令面板：Ctrl+K 内做股票/功能/操作一体搜索 | 命令面板基础设施缺失（I1） |
| S4 | 智能提示：AI 评估结果一键加自选/对比历史 | 已有 aiResult 结构，缺快捷动作 |

## 4. 实施建议与版本规划

### 4.1 版本定位

用户明确 **UI/UX 提质优先于数据自动化**。建议将本优化作为 **v3.11（UI/UX 提质）**，原 v3.11 数据自动化顺延为 v3.12，后续版本依次顺延：

| 版本 | 原计划主题 | 新计划主题 | 说明 |
|------|-----------|-----------|------|
| v3.10 | 可靠性加固 | 可靠性加固 | ✅ 已完成 |
| **v3.11** | ~~数据自动化~~ | **UI/UX 提质** | 本评估落地 |
| v3.12 | 可观测与部署 | 数据自动化 | 原 v3.11 顺延 |
| v3.13 | AI 深化与通知矩阵 | 可观测与部署 | 顺延 |
| v3.14 | — | AI 深化与通知矩阵 | 顺延 |
| v4.0 | 开放平台 | 开放平台 | 不变 |

### 4.2 推荐任务序列（v3.11 UI/UX 提质）

**第一批（架构，6-8 天）**：A-1 命令面板 → A-4 虚拟滚动 → A-2 模块拆分 → A-3 Dialog 组件化
**第二批（交互，5-6 天）**：I-1 搜索升级 → I-2 缓存静默刷新 → I-3 键盘 → I-4 四态组件 → I-5 移动端
**第三批（视觉，6-7 天）**：V-1 令牌落地 → V-2 今日一屏 → V-3 图表增强 → V-4 视觉规范
**第四批（智能，4-5 天）**：S-1 健康面板 → S-2 AI 快捷动作 → S-3 问股增强

> 每批自洽、可独立发布验收；保守合计约 **3 周**。若需压缩，A-2/A-3 可合并进行，V-2/S-1 可合并为"智能首页"一个任务。

## 5. 风险与注意事项

| 风险 | 应对 |
|------|------|
| app-logic 拆分可能引入回归 | 每拆一个域跑一次完整 pytest + 手动冒烟；组件化已降低整体风险 |
| 零构建模式限制组件复用 | 维持现有 `window.__quantComponents` 注册模式，不做打包器迁移（范围控制） |
| 虚拟滚动与既有交互（点击/收藏/信号）冲突 | 保留滚动容器事件委托，逐列表验证 |
| 主题切换遗漏（硬编码色值） | V-1 用脚本扫描 `#[0-9a-f]{6}` 与 `rgba(` 出现位置，逐处替换 |
| 移动端专项工作量被低估 | 以 375px 基准优先改造高频页（日历/自选/详情） |

---

## 6. 结论

当前前端**已有不错基础**（令牌、组件化骨架、快捷键、引导、搜索、多主题），核心瓶颈是 **app-logic.js 巨型单文件 + 命令面板未完成 + 列表无虚拟滚动** 三个架构债，以及设计令牌落地不彻底。按"架构 → 交互 → 视觉 → 智能"四层推进，可作为 **v3.11 UI/UX 提质** 版本落地，数据自动化顺延至 v3.12。预计 3 周（可分批压缩），每层独立可验收。
