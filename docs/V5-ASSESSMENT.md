## 3. 八维度交叉评估

### 3.1 产品经理视角

**现状与亮点**
- 定位一句话能说清（宏观周期 × 多策略 × AI 评估 → 日历），入口单一、心智清晰。
- 三大主线交付完整：策略选股（4+ 策略、SDK、扫描、共识榜）、宏观研判（美林时钟 14 条历史）、AI 评估（多模型、体检、胜率追踪、复盘）。
- 有"价值闭环"意识：从选股 → 回测 → 组合 → 复盘 → 胜率追踪成链。

**问题与短板**
1. **专业深度不足**：回测缺印花税/可配置成本/基准对比/样本外纪律；组合无风险度量（VaR/回撤/仓位建议）；评估缺"对错归因"闭环（为什么模型 A 对 B 错）。
2. **决策辅助弱**：产品呈现"结果"，但"该怎么做"的决策建议（仓位、风险、再平衡）缺失——这是与专业投研工具的最大差距。
3. **可发现性弱**：功能很多（4 域 30+ 模块小类），但新手不知道"第一步做什么、每天该看什么"。
4. **报告能力弱**：日报/周报为 Markdown 文本，无模板化/导出/美观排版，不满足"专业交付物"诉求。

**机会与建议**
- 5.2/5.3/5.5 分别补回测严谨性、风险度量、报告交付，把产品从"工具"升为"决策辅助 + 投研记录"。
- 5.6 做"新手任务流 + 每日首屏引导"，降低 30 天留存门槛。

### 3.2 系统架构视角

**现状与亮点**
- 前后端职责清晰：FastAPI 异步后端 + Vite 构建 SPA（dist 入库，部署免 Node）。
- 零外部依赖（SQLite+JSON）使其可一键 Docker 部署，适合个人/小团队自托管。
- 三源热备（sxsc→tushare→akshare）自动降级，是架构上最扎实的设计之一。
- 策略层已抽象 SDK（DataPortal/SelectionSpec/回测/PTrade 模板），具备可扩展骨架。

**问题与短板**
1. **巨型文件**：ai_evaluator.py 1896 行（90KB）、scheduler.py 1163 行、data_sources.py 1132 行、merrill_clock.py 1023 行——单一文件承载多职责，评审/测试/演进都难。
2. **单进程阻塞面**：批量评估用 asyncio.gather、扫描用 ThreadPoolExecutor，无统一后台任务抽象（进度/取消/重试/持久化），重任务会拖慢事件循环。
3. **数据层口径分散**：data_sources / market_data / DataPortal / views_aggregator 各有取数逻辑，缺统一数据访问层与缓存失效中心。
4. **无 schema 迁移框架**：DB 变更靠 db.py 内 ad-hoc ALTER TABLE，多版本叠加后升级路径脆弱。
5. **调度器与业务耦合**：scheduler.py 承担调度 + 业务执行 + 监控三职，1163 行难维护。

**机会与建议**
- 5.1 建统一数据访问层；5.7 建后台任务队列与两级缓存；5.9 拆巨型文件 + 版本化迁移框架。
- 架构上坚持"每个中版本独立可运行"：拆分只做职责搬移，不引入必须跨版本配合的破坏性变更。

### 3.3 软件设计视角

**现状与亮点**
- 纪律体系是最大亮点：令牌纪律（禁硬编码色值）、术语统一（"评股"→"评估"有测试守护）、依赖纪律（requirements.in → uv lock）、改动纪律（≤3 文件/次）。
- 前端组件化成熟：qc-x 组件约定、qcState provide/inject、__quantModules 工厂，V4.3 分包 + 懒加载打通。
- 安全设计到位：密钥掩码 + 查看口令、JWT 会话（jti/iat/aud）、deny-by-default、SSRF 白名单。

**问题与短板**
1. **前端 JS 仍偏"脚本化"**：20+ 平铺 JS 模块 + 全局命名空间（__quantComponents/__quantModules），缺少类型与模块边界强约束，跨模块数据流靠全局约定。
2. **异常处理不统一**：历史上有 except:pass 治理（V4.7.4 已清 39 处），但错误码/错误响应契约仍分散，前端靠字符串判断。
3. **缺少接口契约层**：前后端接口以手写 fetch + 字段拼装为主，无 OpenAPI 生成客户端/契约测试，改字段易漏前端。
4. **领域模型散**：持仓/评估/策略运行等概念在多处重复定义（views_aggregator / strategy_execution / data_parser），易漂移。

**机会与建议**
- 5.9 做模块边界固化 + 契约测试（OpenAPI → 前端类型）；5.8 的 API v3 一并建立稳定契约。
- 持续以测试守护设计决策（现有 test_ops_domain_functions_injected 已是好样板）。

### 3.4 测试视角

**现状与亮点**
- 资产丰厚：62 文件 / 1124 用例，覆盖数据源、美林时钟、回测、AI、安全、前端一致性、i18n、性能、e2e 视觉回归。
- 门禁分层合理：总覆盖 ≥40%（实测 54%）+ 核心模块 60-70% 分档门禁 + 锁文件防漂移 + 令牌/对比度/网格门禁 + 版本纪律。
- 测试隔离意识强：patch_data_dir 重定向 DB、test_isolation_sentinel 守护。

**问题与短板**
1. **可靠性测试薄弱**：缺故障注入（数据源挂掉、DB 损坏、文件缺失、并发写）的系统性测试——而这正是 V4.9 事故频发区。
2. **回测严谨性测试不足**：无成本敏感度、样本外、基准对齐、参数稳定性断言（现有 SENSITIVITY_SPREAD_RATIO 未被测试覆盖）。
3. **属性/契约测试几乎为零**：无 property-based、无 OpenAPI 契约测试、无前端-后端接口一致性测试。
4. **e2e 覆盖窄且 continue-on-error**：视觉回归仅 2 个截图类测试且不阻塞，移动冒烟链路有限。
5. **性能基准非门禁**：test_performance.py 存在但阈值宽松，退化难被发现。

**机会与建议**
- 5.0 建故障注入测试套件（reliability suite）；5.2 建回测严谨性门禁；5.9 补属性/契约测试并让性能基准进入 CI 门禁。

### 3.5 美工 / 视觉视角

**现状与亮点**
- 设计系统扎实：tokens.css 令牌体系 + 7 主题 + 4 图标体系 + 4px 间距网格门禁 + 动效令牌 + 圆角阴影令牌。
- WCAG 对比度双主题门禁（4.5/3.0）、暗色 dark-pro 深度打磨（V4.4-4.8 三连）、ECharts 暗色联动。
- 移动端 375px 一等公民 + PWA。

**问题与短板**
1. **信息密度与专业性不足**：核心页面（策略总览/日历）数据展示以表格/卡片为主，缺少"专业终端"式的密度与重点层次（数据密度可调、重点指标置顶）。
2. **图表深度不够**：ECharts 仅 K 线/曲线/热力图，缺组合仪表盘、分位数区间带、专业配色语义（涨跌色、风险色）。
3. **动效与微交互一致性**：已有动效令牌，但部分组件交互反馈（hover/点击/加载）不统一。
4. **可视化缺少"情绪/信号"表达**：专业用户希望一眼看到"机会/风险"信号，而非纯数据。

**机会与建议**
- 5.5 报表可视化 + 5.6 体验统一内嵌设计系统 2.0（信息密度、语义配色、图表规范）。
- 继续以视觉回归 + 令牌门禁守护新改动（现有门禁体系已足够支撑）。

### 3.6 程序开发（工程效率）视角

**现状与亮点**
- TDD 四步节奏 + Conventional Commits + 版本前缀，纪律性强。
- CI 链路完整：锁校验 → ruff → 全量测试+覆盖 → 模块门禁 → e2e；Docker 多架构自动发布。
- 构建管线已迁 Vite（dist 入库），首屏 577→367KB、懒加载分包。

**问题与短板**
1. **本地开发环境重**：改前端需重启后端 + 硬刷新（Vite 已缓解 dist 构建，但 dev 热更新体验一般）；本机多副本（dev/ops/archive）易混乱。
2. **CI 触发策略偏保守**：仅在 tag v*/手动触发时跑 CI，push 不触发——质量反馈滞后（优点是省 Action 分钟）。
3. **巨型文件拖慢开发**：在 ai_evaluator(1896 行) 内改动的认知负担与合并冲突概率高。
4. **缺少生成式工具**：无脚手架（新页面/新模块/新测试）、无代码生成、无 lint 自动修复门禁。

**机会与建议**
- 5.9 拆巨型文件 + 开发脚手架 + 本地一键开发脚本；考虑 push 触发快速 lint+单测、tag 触发全量（分级 CI）。
- 文档已在 v4.6 归档精简，继续保持"根目录 7 份当前文档"纪律。

### 3.7 运维视角

**现状与亮点**
- 双环境（dev/ops）隔离、GitHub 单一事实源、同步保留配置原则明确。
- 监控基础：Prometheus /metrics（请求/状态/延迟/数据源/调度/备份/磁盘）+ 飞书告警 + 健康面板。
- 一键备份/恢复、Docker 部署、upgrade.ps1 一键升级（含演练模式）。

**问题与短板**
1. **自愈能力不足**：V4.9 系列事故（日历不可用/日视图空/持仓读不到）依赖人工发现与修复，health_check 自愈只覆盖部分路径；缺数据新鲜度监控（数据"旧了"不报警）。
2. **无版本化迁移**：升级数据库结构靠 ad-hoc ALTER，多版本跳级升级风险高。
3. **无回滚演练**：upgrade.ps1 有 DryRun，但无"升级失败自动回滚"的实战演练与文档化 SLO。
4. **隧道运维**：cloudflared quick tunnel URL 随机、重启即变，公网可达性不稳定（对"便捷运维"是减分项）。
5. **监控告警入口单一**：仅飞书；告警无分级、无静默、无历史看板。

**机会与建议**
- 5.0 建"数据新鲜度 + 自愈闭环 + 故障演练"；5.9 建迁移框架 + 升级回滚 + 观测性 2.0（结构化日志/SLO）。
- 公网访问建议文档化两种方案（quick tunnel 临时 / 固定域名或内网穿透），并纳入部署文档。

### 3.8 用户视角

**现状与亮点**
- 移动端一等公民 + 手势 + PWA 离线可读 + 首屏加速，移动体验显著。
- 个性化：偏好持久化、最近查看/收藏、主题/语言记忆。
- 搜索：拼音/首字母/代码/名称模糊搜索。
- 安全上的"查看密钥需密码 + 掩码"在用户体验与安全间取得平衡。

**问题与短板**
1. **新手无引导**：初始化向导只配密钥，进入产品后无"任务流"（第一步：配置数据源→看日历→评估一只票→建组合），空态/错误态未体系化。
2. **错误恢复体验**：加载失败/数据缺失时的提示零散（部分为 toast/空白），无重试/降级解释。
3. **可发现性**：大量功能藏在二级菜单，命令面板（command-panel-core.js）存在但未成为核心入口，无全局快捷键体系。
4. **任务效率**：跨页面重复操作（如"评估 N 只票→加入组合"）链路长，无批量操作/快捷指令。

**机会与建议**
- 5.6 做引导 + 空态/错误态体系化 + 命令面板增强；5.4 的实时行情/通知让用户"被动接收信号"而非主动刷新。

### 3.9 横切维度：数据质量与量化严谨性

**现状与亮点**
- **PIT 防前视已内建**：strategy_sdk/base.py 契约"只允许请求 end<=当前评估日"，DataPortal 取数自动截断，有 FakePortal 断言测试——这是极好的地基。
- 去未来函数（K 线 limit 参数化、估值/资金流按日合并 ffill 不越界）已治理。
- PTrade 模板真实选股逻辑 + 对拍测试，策略可信度有保障。

**问题与短板**
1. **无数据质量门禁**：缺数/异常值/复权一致性/停牌处理无自动校验；数据"坏了"会静默传导到日历/回测。
2. **无数据字典**：字段口径、复权方式、因子定义散落代码，无单一事实源文档。
3. **无幸存者偏差治理**：历史回测未系统纳入退市股票。
4. **成本模型不完整**：仅佣金+滑点固定值，缺印花税（A股卖出 0.05%）与冲击成本。
5. **无基准对比**：回测无沪深300/中证500 等基准线，无法判断"超额收益"。
6. **无风险度量**：组合无 VaR/回撤/夏普/Beta/集中度指标。

**结论**：数据准确性（5.1）、回测严谨性（5.2）、风险度量（5.3）是"更专业/更准确"的三大硬骨头，也是 V5 与同类专业工具拉开差距的核心。

### 3.10 横切维度：安全

**现状与亮点**：v4.1 已做大幅加固（deny-by-default/SSRF/JWT 会话/限流/掩码），本机自托管场景下处于同类领先水平。
**后续方向**（P2，融入各版本而非单列）：CSP 强化、依赖漏洞扫描（CI 引入）、备份加密、权限细粒度化（5.8 RBAC 2.0）。

## 5. 评估结论与建议（按 7 目标映射）

> 目标 → 关键建议 → 落地版本

| 产品目标 | 核心建议 | 落地版本 |
|---|---|---|
| **更稳定** | 数据新鲜度监控 + 自愈闭环 + 故障注入测试 + 进程守护；启动自检 | **5.0** |
| **更准确** | 统一数据访问层 + 数据质量门禁 + PIT 治理 + 数据字典 + 幸存者偏差 | **5.1** |
| **更专业** | 回测 2.0（成本/基准/样本外/归因）+ 风险度量与风控规则 + 专业报表 | **5.2 / 5.3 / 5.5** |
| **更高效** | 事件通知中心 + 缓存层 + 异步任务队列 + 性能门禁 | **5.4 / 5.7** |
| **更好用** | 新手引导 + 空态/错误态体系化 + 命令面板/快捷键 + 可访问性 2.0 | **5.6** |
| **更美观** | 设计系统 2.0（信息密度/语义配色/图表规范）+ 视觉回归守护 | **5.5 / 5.6** |
| **更便捷** | RBAC 2.0 + API v3/SDK + 一键升级回滚 + 迁移框架 + 观测性 2.0 | **5.8 / 5.9** |

**总体结论**：V5 系列从「广度优先」转向「深度优先」。前四版（5.0-5.3）解决"可靠 + 准确 + 专业"的硬实力，中三版（5.4-5.6）提升"高效 + 好用 + 美观"，后三版（5.7-5.9）沉淀"性能 + 开放 + 工程化"。每个中版本都是一个可独立运行、可独立发布的完整版本。
