## 2. 技术方案要点

### 2.1 拆分约定

拆分按「视图 / 状态 / 取数」三段进行，落在与页面同名的目录下，例如 `components/system/` 内含 `index.js`（视图装配）、`state.js`（状态与计算）、`api.js`（接口取数）。

对外入口保持不变：页面组件仍以原来的注册名挂到全局组件表，`app-logic` 装配点不变。这样模板无需改动，路由与菜单不受影响。

单文件行数上限取 700 行，前端业务源码与后端模块同一口径。样式文件（`themes.css` 等）沿用既有决定不拆分，列入白名单并注明原因。

### 2.2 对拍机制

对拍分两类：

- 纯函数对拍：对同一输入调用拆分前后的实现，比较返回值与异常类型。适用于后端解析、计算、聚合类函数。
- 模块对拍：在 Node 环境下加载前端模块，比较关键导出函数的输出。适用于前端纯逻辑（表单记忆、撤销、请求守卫、状态域）。

对拍在拆分前先跑通一次并固化预期，拆分后必须逐项一致。差异报告输出具体字段与值，便于定位。

### 2.3 异常三档

| 档位 | 判定 | 处理 |
|---|---|---|
| 有意忽略 | 该异常在业务上无意义（如探测性调用、可选清理） | 保留忽略，必须补原因注释，进白名单 |
| 可降级 | 该步骤失败不影响主流程 | 记录警告日志，返回降级值或默认值 |
| 应暴露 | 该步骤失败会导致结果错误或数据不一致 | 记录错误日志，向上抛出或返回明确错误 |

门禁对新增静默异常零容忍；白名单条目需带注释，且总条目数有上限。

### 2.4 虚拟滚动

接入前先把行高固定为常量，避免动态高度带来的定位漂移。改造后逐页回归点击、悬停与选中态，确认行索引与数据索引一致。

### 2.5 备份校验接入调度

校验函数已是纯函数，接入方式为在备份任务完成后调用并把结果写入健康指标。校验失败触发通知，首期只告警不阻断后续任务。

## 4. 发布与运维计划

### 4.1 版本流程

1. 更新 APP_VERSION 与 README 版本历史（沿用 `scripts/bump_version.py`）
2. 合并前跑全量回归与门禁；前端改动重建 dist
3. 提交带 `6.3.N` 前缀与 `[skip ci]`
4. 推送 GitHub 与群辉，打 tag
5. 双端重启后 `curl /api/health` 冒烟，确认版本号一致

### 4.2 运维增强落点（6.3.2）

- 备份校验进入调度，结果写入健康指标并在系统状态页展示
- 数据过期与任务连续失败进入告警通道（站内 + 飞书）
- 日志轮转与磁盘阈值复核

### 4.3 回滚预案

每批次独立可发布，任一批次出现回归时回退该批次的提交即可，不影响既有功能。拆分批次不承载功能变更，因此回滚面清晰。

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 拆分引入行为回归 | 先建对拍再拆分；每步可回滚；视觉与功能门禁全绿方合入 |
| 拆分使体积膨胀 | 体积预算门禁；超出即调整拆分粒度 |
| 异常等级误判 | 白名单每条注明原因；门禁阻断未注明项 |
| 排期在拆分阶段膨胀 | 拆分批次不承载功能变更，每批独立可发布 |
| 虚拟滚动改造导致点击错位 | 行高固定化并纳入门禁；改造后逐页回归 |
| 备份校验告警误报 | 首期只告警不阻断，观察一轮后再定是否升级 |
