- **文档版本**：v1.0（正式版，待审批）

- **配套**：DEV&TEST-PLAN-v5.3.md（开发&测试计划，独立文档）
- **定位**：5.3 不是新功能主线，而是对 **5.0 ~ 5.2 全部已实现功能** 的系统性打磨——向着 **更好用、更实用、更美观、更便捷、更高效、更智能** 六个方向，以专业行业最佳实践为准绳，逐模块体检、逐项优化、逐条守护。

## 0. 定位与设计原则

### 0.1 一句话定位

5.3 = **全功能打磨版**：把 5.0.x（稳定与数据基座）、5.1.x（策略研究主线）、5.2.x（短线复盘主线）沉淀的全部能力，从「能用、好看、规范」再推一档到「好用、专业、顺手」——不新增一级功能线，只做体验、性能、工程、运维与智能增强的深水区打磨。

### 0.2 六维目标映射

| 目标 | 打磨方向 | 主要涉及版本 |
|---|---|---|
| **更好用** | 页面头/空错态/加载态全站统一、新手引导增强、无障碍收尾 | 5.3.1 |
| **更美观** | 设计系统深水区：巨型 CSS 拆分、语义配色、图表专业度、信息密度、动效一致 | 5.3.2 |
| **更便捷** | 命令面板/全局快捷键、全局搜索增强、跨页面跳转链路、批量操作 | 5.3.3 |
| **更高效** | 前端包体积/首屏性能、虚拟滚动、缓存失效中心、后端热点优化、性能门禁 | 5.3.4 |
| **更智能** | AI 评估归因、今日一屏信号化、评估分析深化、短线复盘闭环、报表模板化 | 5.3.5 |
| **更实用** | 运维发布链路补全：Docker 镜像、健康面板、数据新鲜度告警、升级回滚演练 | 5.3.6 |

### 0.3 打磨纪律（贯穿全部版本，用测试锁住）

1. **不改变数据口径**：打磨只动展示/交互/性能/工程结构，不动数据计算逻辑与字段口径；任何"顺带修口径"都必须单独评估。
2. **不破坏现有语义**：i18n key、API 契约、菜单层级、CSS 令牌名保持兼容；拆 CSS 只做搬移，不重命名不删类。
3. **每项打磨有测试守护**：先写失败测试 → 实现 → 跑绿 → commit（TDD 四步），守护测试命名带版本号（如 `test_*_v530`）。
4. **版本独立可发布**：每个小版本出口标准一致（全量测试绿 + 前端一致性门禁 + 双端冒烟 0 pageerror + tag + 文档同步）。
5. **零新增硬依赖**：除极个别经评估的运维工具外，不引入新第三方依赖；依赖变更走 requirements.in → uv compile 纪律。

### 0.4 边界（本版明确不做）

| 不做 | 原因 |
|---|---|
| 新增一级菜单 / 新功能主线 | 5.3 是打磨版，功能深度已由 5.1/5.2 覆盖；新方向另立版本 |
| 数据源三源热备重构 / 数据口径重定 | 触及正确性红线，风险大于收益 |
| 前端框架迁移（如换 Vue 2/React、引 TS 全量改造） | 零构建 SPA 是既有架构资产，TS 化只做新模块试点 |
| 大规模并发改造（换消息队列/多进程） | 个人/小团队自托管场景，异步任务队列已够用 |
| 生产密码轮换 / 云上公网架构迁移 | 依赖用户运维决策，本版仅文档化建议 |

## 1. 现状评估（7 视角 × 证据，2026-09-04 实测）

> 评估方法：代码/测试/文档资产实证盘点 + 运行服务健康核查 + 已知遗留问题清单核对。基线：v5.2.11，全量 **2776 用例 collected（3 e2e 除外）**、206 测试文件、CI 总覆盖门禁 ≥40%、核心模块 60–80% 分档门禁。

### 1.1 系统架构视角

**亮点**：分层清晰（backend/api/v1 + 领域包 ai_eval/shortterm/scheduler/data_sources）、零外部依赖可部署、三源热备、版本化迁移框架（_0001~_0004）、双环境隔离、Vite 构建 SPA（dist 入库，部署免 Node）。

**短板（打磨点）**：
- **A1｜Pydantic V2 弃用**：`backend/config.py:16` 仍用 class-based `Settings(BaseSettings)`（无 `model_config = SettingsConfigDict`），pytest 收集期即告警 `PydanticDeprecatedSince20`；Pydantic 2.x 最佳实践要求 `ConfigDict`。
- **A2｜依赖上界残留**：`requirements.in` 中 `pydantic<2.13.5` 是 v4.9.2 临时上界，5.3 应评估解除并重编译锁文件。
- **A3｜巨型文件**：`themes.css` 5058 行、`research-page.js` 1800 行、`system-page.js` 1641 行、`strategies-page.js` 1282 行、`db.py` 720 行——维护/评审/合并冲突成本高。
- **A4｜db.py 内 ad-hoc DDL**：`db.py` 仍含 4 处 `ALTER TABLE`，未纳入迁移框架（应走 `_0005` 迁移）。
- **A5｜审计日志无轮转**：`data/audit.log.*` 已积累 14 个文件，无保留策略。

### 1.2 软件设计视角

**亮点**：令牌纪律（禁硬编码色）、术语统一（"评股"→"评估"有测试守护）、依赖纪律（uv 锁文件防漂移）、前端组件化约定（qc-x / __quantModules / qcState）、安全设计（密钥掩码/JWT 会话/deny-by-default）。

**短板**：
- **D1｜异常处理不统一**：全后端 172 处 broad `except Exception:`（api/v1 尤多），错误码/响应契约分散，前端靠字符串判断。
- **D2｜契约层薄弱**：前后端以手写 fetch + 字段拼装为主，无 OpenAPI 生成客户端/契约测试闭环（已有 `test_contract_openapi.py` 但覆盖浅）。
- **D3｜领域模型散**：持仓/评估/策略概念在 views_aggregator / strategy_execution / data_parser 多处重复定义。

### 1.3 程序（代码质量）视角

**亮点**：零 TODO/FIXME、零裸 `except:pass`（历史已治理）、Conventional Commits + 版本前缀、前/后端一致性有守护测试（test_frontend_consistency 120 用例）。

**短板**：
- **C1｜巨型组件文件**：research-page/system-page/strategies-page 三组件 >1200 行，建议按子页拆模块（延续 V4.3 分包思路）。
- **C2｜测试隔离坑（已知未根治）**：`tests/test_today_snapshot.py` 顶层 import 污染真实 `data/`，全量跑前需停 dev 或接受污染（HANDOVER §5.3 记录）。
- **C3｜jobs_queue 偶发失败**：全量顺序敏感，单独跑通过，需定位根因。

### 1.4 测试视角

**亮点**：2776 用例 + 分层门禁（总 ≥40%、核心 60–80% 分档、锁文件防漂移、令牌/对比度/间距/版本纪律门禁）、故障注入套件（test_reliability_faults）、属性测试（test_property_based）、契约测试（test_contract_openapi）、升级回滚（test_upgrade_rollback ≥80%）。

**短板**：
- **T1｜e2e 仅信息性**：视觉回归 continue-on-error，不阻塞发布；baseline 截图仅 7 张，覆盖窄。
- **T2｜性能基准非门禁**：test_performance.py 存在但阈值宽松，退化难被发现。
- **T3｜Pydantic 弃用告警未被门禁捕获**：告警噪音污染测试输出，应清零并加守卫。

### 1.5 美工/视觉视角

**亮点**：设计令牌体系 + 7 主题 + 4 图标体系 + 4px 网格门禁 + WCAG 双主题对比度门禁 + dark-pro 深打磨 + ECharts 暗色联动。

**短板**：
- **G1｜themes.css 巨型单体**：5058 行承载全部主题/组件样式，主题间差异难审计、新样式易堆叠。
- **G2｜图表专业度不足**：ECharts 仅 K 线/曲线/热力图，缺组合仪表盘、分位数区间带、专业语义配色（机会/风险信号）。
- **G3｜信息密度单一**：已有信息密度选项（V5.0.6）但未全站生效；专业用户缺"紧凑密度 + 重点指标置顶"。
- **G4｜动效/微交互一致性**：部分组件 hover/点击/加载反馈不统一。

### 1.6 用户视角

**亮点**：移动端 375px 一等公民、PWA 离线、5 语 i18n、命令面板 Ctrl+K / 快捷键帮助 Ctrl+/、新手引导任务流、空错态体系化（5.2.6）、无障碍收尾（5.2.10）、全局搜索拼音/首字母。

**短板**：
- **U1｜功能可发现性**：6 菜单 35+ 子页，深度功能藏得深；命令面板存在但未成为核心入口。
- **U2｜跨页面链路长**：「评估 N 只 → 加入组合 → 导出」需多次跳转，缺批量操作/快捷指令。
- **U3｜复盘闭环前端**：短线复盘验证条件自设、盘中核验前端、追问聊天历史仍偏薄（5.2.4 展望项）。

### 1.7 运维视角

**亮点**：systemd 用户服务（dev/ops 双端口）、备份恢复一键化、健康面板、Prometheus /metrics、upgrade/rollback 脚本 + 演练模式、verify_chain.sh 九节点、qc-svc.sh 管理脚本。

**短板**：
- **O1｜Docker 镜像未推**：v5.2.3/v5.2.4 起 ghcr.io 未推（CI 或手动均未执行）。
- **O2｜公网隧道不稳定**：cloudflared quick tunnel URL 随机、重启即变。
- **O3｜健康面板缺数据新鲜度**：freshness.py 已实现 freshness 评估，但前端健康面板未透出"数据旧了"告警。
- **O4｜升级回滚演练未文档化**：脚本存在但无实战演练记录/SLO。
