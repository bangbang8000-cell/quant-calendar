## 1. 美术风格评估 ★★★★☆ (4/5)

### 1.1 做得好的
- **设计令牌体系完整**：tokens.css 三层（Raw/Semantic/Component），间距/圆角/字体/阴影/过渡全部令牌化，符合《ui-visual-design》规范。
- **7 套主题**（科技蓝/玫瑰红/活力金/经典白/经典红/经典金/暗色专业），主题切换过渡动画平滑，暗色专业（dark-pro）质量高。
- **红涨绿跌语义统一**（--color-up #E63946 / --color-down #2E7D32），金融语境正确，对比度 ≥4.5:1 已修复（v3.16）。
- **功能色语义一致**：success/warning/danger/info + badge 色系齐备，AI 品牌色（#6366f1 靛紫）独立。
- **视觉层次**：中性色占比高（bg-page #f8f9fa / bg-card #fff），卡片 12px 圆角 + 阴影体系统一。

### 1.2 问题与机会
| # | 问题 | 严重度 | 建议 |
|---|---|---|---|
| A1 | **7 主题色相过杂**（蓝/红/金/白/暗），部分主题（活力金/经典金）对比度不达标，非主色按钮 hover 态不一致 | 中 | 收敛为 4 主题（科技蓝/经典白/暗色专业/玫瑰红），其余下线；为每个主题补齐 hover/active/plain 全套按钮令牌 |
| A2 | **JS 中仍有 ~40 处硬编码色**（#6b7280/#43a047/#e5e7eb 等），违反"前端零硬编码色"约束 | 中 | 建色彩映射表，硬编码 hex → var(--token)，统一管理 |
| A3 | **ECharts 主题与 UI 主题脱节**（echarts-theme.js 独立于 data-theme） | 低 | 图表色板随 data-theme 联动（暗色主题用深色图表） |
| A4 | 图标系统用 emoji（🎛️🔢），风格不统一且跨平台渲染差异大 | 低 | 关键操作图标换 SVG 图标（已有 icons.js，扩展覆盖） |
| A5 | 暗色主题下部分第三方组件（el-date-picker 弹层、el-select 下拉）仍白底 | 低 | 补 el-popper 暗色覆盖 |

## 4. 运行效率评估 ★★★☆☆ (3.5/5)

### 4.1 现状
- **后端**：156 端点 + 速率限制(600/min/IP) + 多级缓存（kline/scan/factor/评估），scan 已并发化(10线程)+tushare优先，独立脚本 55s→秒级。
- **前端**：60/60 script 全 defer（不阻塞首屏），但**全量加载**导致总 JS ~500KB+ 首屏全下载。
- **数据管道**：fetch_tushare_daily/run_pipeline/财务拉取，有调度但无增量差异缓存优化。

### 4.2 问题与机会
| # | 问题 | 严重度 | 建议 |
|---|---|---|---|
| D1 | **前端首屏体积大**（63 script + 500KB JS + 8 页面组件全下载） | 高 | 按需加载 + 首屏关键路径瘦身 + gzip |
| D2 | **API 无响应压缩**（大 JSON 面板/评估结果） | 中 | gzip/brotli 中间件（FastAPI GZipMiddleware） |
| D3 | **数据源并发无全局协调**：scan/回测/AI 评估同时跑时可能并发撞源限流 | 中 | 数据源访问加全局并发闸（semaphore 池按源隔离） |
| D4 | **K线/因子缓存 TTL 固定**（300/600s），无失效推送 | 低 | 交易日变更时主动清缓存 |
| D5 | 前端**重复请求**：切页重复 fetch 同一数据，无请求去重/共享 | 中 | 前端 request 层加 Promise 去重 + SWR 式缓存 |
| D6 | ECharts 大图渲染未用 canvas 降级/节流 | 低 | 图表 resize 节流 + 大数据抽稀 |

## 6. 综合结论与优先级

### 6.1 五维雷达
```
可配置项 ★★★★ (4.0)
UI界面    ★★★★ (4.0)
操作逻辑  ★★★★ (4.0)
美术风格  ★★★★ (4.0)
运行效率  ★★★  (3.5)   ← 最大短板
```

### 6.2 核心短板（影响用户体验最直接）
1. **前端首屏加载重**（D1/B1）— 打开慢/卡顿的直接观感来源
2. **无统一请求层/错误反馈**（B2/D5）— 失败无提示，体验割裂
3. **策略参数方案缺失**（E1）— 调参工作流断裂

### 6.3 优先级排序（P0/P1/P2）
- **P0（体验修复，v3.21 必做）**：统一请求层+错误反馈(B2/D5)、首屏按需加载(D1/B1)、策略参数方案保存(E1)
- **P1（体验增强）**：高危操作确认(C1)、数据源一键检测(E2)、前端 gzip(D2)、操作审计(C3)
- **P2（打磨）**：主题收敛(A1)、JS 硬编码色清理(A2)、图表主题联动(A3/A4)、空态覆盖(B3)


## 7. 补充评估: 策略纳管 / 发布安全 / tushare pro 支撑 / 持仓等价性 (评审补充)

### 7.1 密钥安全现状 (发布前提, 已审计)
- **四大策略/模板/PTrade 导出代码 0 token** (策略 SDK 与模板不含任何 key)
- 山西证券 sxsc key (46a2...) 与 tushare key (ab2e...) 存于 **.env 的 SXSC_TUSHARE_TOKEN / TUSHARE_TOKEN 变量** (已变量化), 代码运行时从 config.settings 读取 → 部署方替换 .env 即换 key
- data/ .env datasource_config.json 均已 gitignore; git 已跟踪文件 0 token → **可安全 push GitHub**

### 7.2 tushare pro 支撑度评估 (四策略 + 持仓文件)
| 策略 | 所需字段 | tushare pro 接口 | 实测 | 结论 |
|---|---|---|---|---|
| 多因子 | close/pe/pb/volume/float_mv/moneyflow | daily/daily_basic/moneyflow | ✅ 全部可用 | 支持 |
| 行业轮动 | close | daily | ✅ | 支持 |
| 资金流 | close/main_net_inflow | daily/moneyflow | ✅ | 支持 |
| 指数增强 | close/pe/pb | daily/daily_basic | ✅ | 支持 |

**结论**: 常规 tushare pro 可完整支撑四大策略并生成持仓文件 (标准版 token 实测四接口全通)。
**注意**: ① moneyflow 属积分接口, 低积分 token 可能受限 → 程序降级(该因子空→回退量能), 文档注明; ② 全池 5544 只并发取数约 3 分钟, 建议收盘后(默认 20:00)执行。

### 7.3 持仓文件等价性 (程序 vs 既有 qresult)
- **既有 qresult**: 外部程序生成, 矩阵格式 (行=日期 628 天, 列=全 A 股 5535 列, 值=1 持有/空), 覆盖 2024-01~2026-08
- **程序能力**: generate_signals 生成 日期×股票 持仓矩阵 (值=权重 1/N), **与 qresult 同构** → 可导出等价格式 (程序自接管后替代外部生成)
- **差异**: 当前内置策略 universe 为 8 只小池, 需扩展至配置池/全池 5544 只 (约 3 分钟/策略) 实现等价覆盖
- **已知缺口**: multi_factor 的 float_mv 字段未在 data_portal 映射 (仅有 circ_mv) → turnover 因子退化为量能, 需补 float_mv=circ_mv 别名 (P0-8 前置修复)

### 7.4 无 key 预览 (部署体验)
- 部署方未配 key 时: 用内置历史持仓样例 (docs/reference_holdings/) 预览策略列表/持仓查看; 实时数据功能提示配置 key

### 7.5 用户补充决定 (已并入 PRD)
1. 发布方式: 直接 push GitHub, 不含运行数据文件 (pre-push 密钥门禁)
2. 四大策略 key: 确认已变量化 (.env SXSC_TUSHARE_TOKEN/TUSHARE_TOKEN)
3. tushare pro 支撑: 实测支持, 文档注明积分接口风险与降级
4. 持仓等价: 程序可生成与 qresult 等价矩阵, 需扩展 universe + float_mv 修复
5. 定时: 每日收盘后一次, 默认 20:00, 可自定义
6. 无 key 预览: 内置历史持仓样例
7. 纳管为主: 放研究页, 默认不可删, 可复制调参
