## 1. 版本定位与演进框架

### 1.1 为什么现在进入"打磨"

v6.3.6 与 v6.4.0 两轮已把四大结构性债还清：前后端拆分、`DETAIL_CONTENT_TOKEN` 层级收敛、`toast` 死代码清理、摘要卡/元素交叉验证、响应式拆分、性能门禁、AI 模型名入公开接口、技术债看板。v6.4.0 更把 8 条战略 FR 全部落地，含**数据新鲜度横幅**与**全局搜索**——方向是对的，但目前是"能力已在、体验未成"的状态。

本轮不追新功能，而是**把 v6.4 已交付的能力真正用起来、用对、用快**。判断依据来自基线实测（见 §2），其中四条最硬：

1. **数据不自动更新**：`scheduled_enabled=false`、`pull_enabled=false`、`stock_pool=[]`，数据止于 2026-10-20，距今日已 6 个自然日。
2. **调度几乎不跑业务作业**：调度历史 1,093 条中看门狗类（health/error/freshness）约 97.6%，业务作业仅 13 条（`daily_market_review` 4、`strategy_run` 3、`daily_report` 2、短线 4）。
3. **AI 能力被闲置**：`ai_usage.json` 全期仅 146 次调用、10 个活跃日。
4. **认知负荷偏高**：一级导航 7 个、二级页 38 个；首屏业务 JS 单体 1,005KB。

### 1.2 演进主线（一句话）

> **6.4.x 五连补丁把"日常可依赖"补齐，6.5.x 两版把信息架构与设计系统一次收敛到位。**

| 版本 | 主题 | 一句话目标 |
|---|---|---|
| 6.4.1 | 稳态与数据闭环 | 打开产品，数据是新的、结论是可信的、服务是在跑的 |
| 6.4.2 | 易用性与便捷性 | 新用户 3 分钟出第一个结论；老用户少点 30% 的点击 |
| 6.4.3 | 运行效率 | 首屏快一半，长列表不卡，热点接口有预算 |
| 6.4.4 | 智能化提效 | AI 结论可追溯、可解释、可降级，且真的有人用 |
| 6.4.5 | 测试与工程质量 | 门禁全绿、环境类失败归零，改代码不再提心吊胆 |
| 6.5.0 | 信息架构收敛 | 7→5 个入口、统一页面模板与详情页分层、旧深链 100% 兼容 |
| 6.5.1 | 设计系统与视觉收敛 | 一套令牌与标尺：字体自托管、弹窗四档、旧类清零、暗色三档、移动打底 |

### 1.3 设计原则（本轮的取舍准则）

1. **存量优先**：能用开关/配置/文案/布局解决的，不写新模块。
2. **先度量后优化**：每条性能与体验目标都先落基线脚本，禁止"感觉快了"。
3. **不骗用户**：数据陈旧、样本不足、AI 不可用时，**明示**而非静默降级或硬拦截。
4. **兼容不破坏**：IA 调整保留旧 URL 深链；导出格式只加列不改列。
5. **可回退**：每个版本一个 tag 与回滚点，回滚 ≤10 分钟（v6.4.0 已验证 39–56s）。

### 6.4.1 稳态与数据闭环

#### FR-641 数据刷新闭环（P0）

**现状证据**
- `data/data_refresh_config.json`：`scheduled_enabled=false`、`pull_enabled=false`、`stock_pool=[]`、`last_refresh=2026-10-20 20:09:32`
- `data/freshness.json` 最新数据日 `2026-10-20`；今日 `2026-10-26`
- `data/scheduler_history.json` 1,093 条：`health_check` 594 / `error_alert` 296 / `freshness_alert` 177（合计约 97.6%），业务作业 13 条

**要求**
1. 配置页"自动刷新"可开启；开启后按 `scheduled_time` 执行，每次执行写 `scheduler_history`；关闭后不再触发。
2. 失败重试 3 次（指数退避，上限 10 分钟）；连续 2 次失败产生告警（沿用现有 `error_alert` 通道），并在新鲜度面板可见。
3. 刷新成功后原子更新 `freshness.json`，并通知视图聚合层完成重载（沿用 v6.4 已修 `freshness → views_aggregator` 链路）。
4. **首次开启不执行全量拉取**：需在配置页二次确认，且首日仅拉取"最近 N 个交易日"（N 可配，默认 5）。
5. 每次刷新落一条结构化日志（开始/结束/耗时/写入行数/失败原因）。
6. `stock_pool` 为空时，配置页给出明确引导（"尚未配置数据池，自动刷新将无标的可拉取"），不得静默空跑。

**验收**
- 开启后连续 3 个交易日，每日 `scheduled_time ± 5min` 存在 `success=true` 记录。
- 模拟数据源不可达：2 次失败后告警出现，`freshness.json` 标记 stale，横幅出现。
- 关闭开关后 2 个周期内无新增刷新记录。
- `stock_pool=[]` 时配置页显示引导文案，不产生"成功但 0 行"的假成功记录。

#### FR-642 陈旧数据的决策护栏（P0）

**现状证据**：v6.4 已有全局横幅（`/api/freshness` + 前端横幅），但结论类页面与导出、AI 输出均无痕迹。

**要求**
1. 陈旧阈值统一为 **5 个交易日**（配置可调，默认 5），语义与 `backend/freshness.py` 的 `is_stale` 保持单一来源。
2. 结论类页面（策略总览 / 量化日历 / 智能评估总览）在陈旧时：顶部置灰条写明"数据截至 YYYY-MM-DD，已滞后 N 个交易日"，相关卡片右上角显示"数据截至 X"角标。
3. 导出（CSV / XLSX / 报表）在文件首行注释或元数据 sheet 写入：数据日期、生成时间、新鲜度状态。
4. AI 评估结果中，若输入数据陈旧，必须追加标注"输入数据截至 X，结论仅供参考"，且该标注不可被 UI 折叠隐藏。
5. **不阻断浏览**：只做提示与标注，不做硬拦截或强制弹窗。

**验收**
- 构造 30 天陈旧数据：三类页面角标出现、导出含日期与状态、AI 结果含标注。
- 正常数据（滞后 ≤1 交易日）：三者均不出现，无残留占位。

#### FR-643 服务常驻与自愈（P0）

**现状证据**：2026-10-26 检查 8000 / 8001 均未监听；此前部署依赖手工结束进程与手动启动。

**要求**
1. 提供 Windows 计划任务/服务化脚本：开机自启 + 崩溃重启（≤60s）+ 单实例保护（防双起端口冲突）。
2. `/api/health` 扩展返回：`version`、`uptime_seconds`、`data_freshness`、`last_refresh_status`、自检摘要。
3. 启动失败必须写入可处置原因：端口占用（含占用 PID）、依赖缺失（模块名）、数据目录不可写（路径）、数据库损坏（表名）。同时写入 `data/startup_check.json`。
4. 部署脚本发布后自动重启并等待健康（最长 90s），失败则保持旧版本运行（可回滚语义）。

**验收**
- `Stop-Process` 杀掉进程后 ≤60s 自动拉起，`/api/health` 返回 200。
- 占用 8000 后启动：日志与 `startup_check.json` 指向具体 PID 与处置建议。
- 发布脚本在健康检查失败时不留下半启动状态。

### 6.4.2 易用性与操作便捷性

#### FR-644 新手上手路径（P0）

**现状证据**：`frontend/js/onboarding-core.js` 已有引导骨架；空态曾为纯文本、无主行动；无示例数据。

**要求**
1. 首次登录 3 步引导：① 看"今日一屏"→ ② 打开一只标的详情 → ③ 用一句话问 AI。可跳过、可在帮助入口回看。
2. 空态统一为 `qc-state-panel` 四态组件，且**每个空态至少 1 个主行动按钮**（如"去配置数据池""刷新数据""添加自选"）。
3. 提供"示例组合"一键载入（只读、可一键删除，不影响真实数据）。
4. 埋点：引导开始/完成/跳过、空态按钮点击。

**验收**
- 全新账号从登录到"今日一屏"出现有效数据 ≤3 分钟、≤6 次点击（人工计时 3 次取中位）。
- 抽查 10 个空态页面，每页含 ≥1 个可点击主行动。
- 引导可回看；示例组合载入后可完整删除且真实数据不变。

#### FR-645 全局搜索与命令面板增强（P1）

**现状证据**：`frontend/js/command-panel-core.js` 已分组 `stock / menu / command`；未覆盖策略、AI 历史、数据字典。

**要求**
1. 搜索范围扩展至 6 类：股票（代码/名称/拼音首字母）、一二级页面、指令、策略（研究库）、AI 评估历史、数据字典字段。
2. 结果分组展示 + "最近访问"（本地存储，可清除）。
3. 全键盘可达：↑↓ 选择、Enter 打开、Esc 关闭、Tab 切组；中文输入法组合期不误触发。
4. `Ctrl/Cmd + K` 全局唤起；移动端有可见入口。
5. 无结果时给出建议（拼写近似、去筛选）。

**验收**
- 6 类实体各至少 1 条可命中；输入 3 字符首屏结果 ≤150ms（本地 1440 环境）。
- 纯键盘完成"搜索 → 打开二级页"全流程，无需鼠标。
- IME 输入过程中不出现误跳转。

#### FR-646 错误与降级文案体系（P1）

**现状证据**：错误态已有统一面板，但文案多为 HTTP 原文；数据源降级文案 v6.4 已部分治理。

**要求**
1. 建立错误码 → 人话映射表，至少覆盖：401/403/404/429/5xx/超时/离线/数据源不可达/文件缺失。
2. 每条文案两段式："发生了什么（一句）+ 你可以做什么（一句）"，行动必须可点（重试/切备用源/去配置/联系管理员）。

**验收**
