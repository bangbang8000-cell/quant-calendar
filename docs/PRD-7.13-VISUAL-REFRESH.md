# PRD-7.13：明暗双主题整体美术优化

> 状态：**待批准**（2026-11-21 提交）
> 基线：`APP_VERSION = 7.12.0` / git HEAD `2d937f3`
> 前置调研：`docs/EVAL-VISUAL-REFRESH-7.13.md`
> 编写规则：本 PRD 只描述「做什么」与验收口径，不描述「怎么做」，不含任务拆分与排期。
> **阶段门**：本 PRD 批准 → 编写《开发与测试计划》→ 用户再次批准 → 才允许编码与测试执行。

## 1. 背景与问题陈述

前端 token 基建与对比度门禁已达可维护水平，但美术表达落后于工程水平：

- **亮色**：米黄画布 `#eceae4` + 高饱和浅黄激活底 `#fcf3d9` + 2.86:1 容器描边 + alpha 0.05 的几乎不可见阴影 → 观感偏旧、线框化、层级靠线不靠影。
- **深色**：面层彩度仅 10–12%，四级近黑灰 `#11100e / #191815 / #282620 / #39362d`，实底品牌色被压到 `#907a37` → 用户反馈"灰蒙蒙、不美观"。
- **共性**：装饰线与控件边界同为高对比，缺少中间饱和度档；品牌色无高饱和焦点；图表定性色板为同色相明度阶梯，与组件语言不一致。

历史专项（`EVAL-UI-COLOR-SYSTEM`、`EVAL-UI-GLOBAL-v6.9.7`）的对比度类 P0 已修复；本轮针对**审美与层级表达**，不以"继续提高对比度"为目标。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 可测判据 |
|---|---|---|
| G1 | 深色不再灰蒙 | 7 色相 + 中性 × 2 模式的面层彩度进入目标区间；相邻面亮度比 ≥1.18；主屏有且仅有 1–2 处品牌强调点 |
| G2 | 亮色去旧、建立浮起感 | 画布饱和度 ≤10%；凸起面与卡片通过阴影区分（`--surface-raised` 与卡片同值时须有可见阴影）；装饰线弱化到 2.0±0.2:1 |
| G3 | 层级分明 | secondary 与 tertiary 明度差 ≥8 个百分点（两模式）；三级文字对比度 ≥4.5:1 |
| G4 | 强调色安全 | 品牌文字对**卡片与画布双基准**均 ≥4.8:1（跨 14 套配置） |
| G5 | 图表与界面同语 | 定性色板跨色相、涨跌文字走 `-text` 档、tooltip 随主题；A 股红涨绿跌语义不变 |
| G6 | 不破坏既有资产 | 全部既有门禁保持通过（除 `BORDER_MIN` 按 FR-2 显式调整），双源令牌数不增加 |

### 2.2 非目标

- 不改信息架构、导航结构、页面布局、字号阶梯标尺（已收敛 6 档）。
- 不做大范围组件重写、不引入新 UI 库、不引入外部设计系统。
- 不改涨跌语义（红涨绿跌固定）、不改主题模型（mode × hue + 中性档）。
- 不追求"大面积品牌色"；品牌面积维持 ≤10%（历史报告已确认过的方向）。
- **本轮不做开发、不做测试执行、不改任何前端源码**。

## 3. 用户与场景

- **主要用户**：量化研究员 / 交易员，长时间盯盘、高信息密度场景，依赖快速区分卡片层级与涨跌状态。
- **典型场景**：默认金色相亮色看盘（白天）、深色看盘（夜间）、切换蓝/绿/紫/中性色相、浮层选择与图表对比。
- **体验诉求**：长时间阅读不疲劳、层级一眼可辨、选中状态明确但不刺眼。

## 4. 需求清单

优先级 P0 = 必须；P1 = 强烈建议；P2 = 视评审取舍。

### FR-1（P0）深色面层染色与焦点重建
- 将深色四级面层（canvas/card/raised/sunken）与导航底色、悬浮底的**彩度**提升到候选区间（面层 18–20%，凹陷/画布 20%），保持色相联动与亮度阶梯。
- 引入**单点强调**机制：仅用于当前选中导航项、1 个关键数据、焦点环；不增加大面积实色块或新渐变。
- 验收：14 套配置下相邻面亮度比 ≥1.18；正文/次文/三级文对卡片 ≥4.5:1；中性色相档仍为纯灰。

### FR-2（P0）装饰线与控件边界分层
- 容器描边 `--qc-border` 的目标对比度由 ≥2.8:1 降为 **2.0±0.2:1**（明暗同口径），使描边退为装饰线。
- 控件边界 `--border-control` 保持 ≥3:1（WCAG 1.4.11），焦点环 `--qc-ring` 保持 ≥3:1；两者不得随装饰线一起弱化。
- 验收：`tests/test_dark_residue.py` 的 `BORDER_MIN` 显式调整并注明口径；`test_theme_contrast.py` 中控件边界与焦点环断言继续通过。

### FR-3（P0）品牌文字双基准求解
- 亮色 `--primary-text` / `--text-link` / `--btn-primary-text-color` 的求解基准由"仅白卡"改为"白卡与页面底色双取严"，目标 ≥4.8:1（留 0.3 余量）。
- 暗色 `--brand-soft-text` 在 soft 底色变化后须重新求解，保持 ≥4.5:1。
- 验收：14 套配置无低于 4.8:1 的上述令牌；不新增双源令牌。

### FR-4（P1）亮色画布去黄与浮起感
- 亮色画布、凹陷面、悬浮面的彩度降至 ≤10%（含 45/220/0/140/270/320 与中性档），消除"旧纸底"。
- 凸起面与卡片同值时，用**阴影分层**而非描边区分层级；阴影使用暖中性色、alpha ≤0.14，避免"脏边"。
- 验收：画布/白卡亮度比 ≥1.18；凸起面与卡片在视觉回归基线中可区分；无新增硬编码色。

### FR-5（P1）文字层级拉开
- 亮色 tertiary 明度由 37% 提至约 40%，深色 tertiary 由 62% 提至约 66%，secondary 保持不变，形成 ≥8 个百分点的明度差。
- 验收：`--text-tertiary` 对卡片、表头底均 ≥4.5:1；muted/表头文字不回退。

### FR-6（P1）图表与数据语言统一
- 定性色板改为**跨色相**色板（不再用同一色相 6 个明度档）；分类序列在深浅两模式均可区分。
- 涨跌填充档用于 K 线/色块，涨跌**文字**档用于涨跌幅文本；tooltip、网格线、轴线沿用主题 token。
- 验收：A 股红涨绿跌语义逐配置校验；图表色与 UI 面层色同族；`test_chart_tokens.py` / `test_chart_theme_unify_611.py` 保持通过。

### FR-7（P2）组件质感收敛
- 圆角只用 6/8/12/16 标尺；浮层三档阴影；结构层用 1px 顶部高光代替毛玻璃；毛玻璃仅用于浮层。
- 验收：既有 `test_glass_tokens_622.py`、`test_components_tokens.py`、`test_tokens_no_hardcode.py` 保持通过；不新增 `!important`。

### FR-8（P0）双目录同步与文档归档
- `quant-calendar-dev` 与 `quant-calendar-ops` 的前端 CSS/JS 保持一致；PRD 与调研报告归档在 dev/docs。
- 验收：实施阶段 `diff -rq` 两份 `frontend/css` 与 `frontend/js` 无差异。

## 5. 目标视觉规范（候选，实施时按求解器确定）

| 角色 | 深色 gold 目标 | 亮色 gold 目标 | 约束 |
|---|---|---|---|
| 画布 | `hsl(h,20,7)` ≈ `#15140e` | `hsl(h,10,91)` ≈ `#eae9e6` | 对白卡/面层比 ≥1.18 |
| 卡片 | `hsl(h,18,15)` ≈ `#2d2a1f` | `#ffffff` | 与 `--chart-bg` 同值 |
| 凸起 | `hsl(h,18,22)` ≈ `#423d2e` | 同卡片 + 阴影 | — |
| 装饰线 | `hsl(h,18,32)` ≈ `#605943`（2.06:1） | `hsl(h,12,70)` ≈ `#bcb7a9`（2.00:1） | 控件边界另走 3:1 |
| 三级文字 | `hsl(h,10,66)` ≈ `#b1ada0` | `hsl(h,10,40)` ≈ `#706b5c` | ≥4.5:1 |
| 强调 | 2px 品牌条 + 关键数字 | 浅底彩字 + 焦点环 | ≤10% 面积 |
| 中性档 | 纯灰，保持无彩 | 纯灰，保持无彩 | `_neutralizeTokens` 不回退 |

> 以上为**目标区间**而非硬编码值；最终值必须由 `themes.js` 运行期求解器按色相产出，并在 `tokens.css` / `themes.css` 保持同名同结构的静态兜底（明暗对称契约）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 降描边后密集表格控件与背景融合 | 控件边界 3:1 与 hover 面保留；视觉回归覆盖表格页 |
| 亮色阴影 alpha 过高产生"脏边" | 上限 0.14，使用暖中性色；截图基线比对 |
| 品牌文字余量不足破 AA | 双基准求解 + 14 套配置断言 |
| 双源漏改导致"改了不生效" | 三个 token 源文件同步；`test_color_tokens.py` 双源计数不增加 |
| dev/ops 不同步 | FR-8 纳入验收，`diff -rq` 校验 |
| 中性色相档被迫染色 | `_neutralizeTokens` 保持 S=0；中性档只靠明度分层 |
