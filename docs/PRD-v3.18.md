## 2. 战略背景与现状评估

### 2.1 一句话定位

**v3.17 把产品推到了"功能完备"：多因子体检、AI 复盘、回测落地、胜率追踪、异动扫描、开放 API 均已交付并发布。但运行时审计发现一批"代码完成、能力休眠"的半成品，且决策可信度与工程质量仍欠账。**

**v3.18 的目标是把已交付的能力真正激活、把决策结论做到可信、把工程地基再次加固**：
- **激活**：AI 复盘、事件提醒、实时行情等休眠能力接入真实数据源并持续产出；
- **可信**：胜率追踪、因子有效性、回测真实性、AI 事实护栏——让用户知道"这个结论为什么可信、有多可信"；
- **健康**：数据源自动切换自愈、测试隔离根治、覆盖率攻坚、巨型文件拆分。

### 2.2 七维度现状评估（基于 v3.17.7 全库审计 + 运行时验证）

#### 2.2.1 系统架构
- **优势**: FastAPI + SQLite（WAL/迁移）+ 三源热备数据源（sxsc→tushare→akshare 自动 fallback + retry_with_backoff + mock fallback）+ 自研 asyncio 调度器（数据刷新/备份/16:00 复盘/日报/周报/健康告警）+ 双环境物理分离（dev 8001 / ops 8000）+ Docker/CI + 一键升级脚本。
- **负债**: `ai_evaluator.py` ≈98KB/2600+ 行巨型单体；前端 `system-page.js` ≈83KB、`ai-page.js` ≈69KB、`app-logic.js` ≈69KB、`watchlist.js` ≈49KB；限流仍为单进程内存实现（`SimpleLimiter`，Redis 后端仅预留接口未实现）；同数据 SQLite 与 JSON 双写残留未完全收敛。

#### 2.2.2 软件设计
- **优势**: 「基础模块 + 领域模块 + 页面/对话框组件」分层成型；`window.__quantModules` 工厂 + `qcState` provide/inject；virtual-list/state-panel 等可复用组件与纯计算核心（可 node 单测）；v3.17.1 完成 app-logic 首次拆分（69KB 仍偏大）。
- **负债**: **一批"代码完整但未激活"的半成品**（详见 2.3.1 休眠能力盘点）：`event_alert.py` 默认 provider 为 `_UnavailableEventProvider`（`available=False`）；`realtime_quotes.py` 的 `_fetch_from_tushare` 为死代码；i18n 仅 2 个文件接入（其余硬编码中文）。

#### 2.2.3 程序
- **优势**: CSP nonce + sanitizeHtml + JWT/bcrypt + 审计日志 + 请求 trace_id 结构化日志；覆盖率门禁 + ruff + 锁文件校验 + 前端一致性 guard（内联样式/print/文件大小/deps 审计）入 CI；性能回归基线（首屏 569ms/5000 点渲染）已可量化守护。
- **负债**: 休眠能力无产出时**静默失败**（复盘归档 0 条但无告警）；数据源健康监控**只读不切换**；`[DEBUG]` 与 print 清理在 v3.17.1 后仍有少量回潮；部分历史日期字段类型不稳曾致 NoneType 崩溃（已修，需回归守护）。

#### 2.2.4 测试
- **优势**: 709 个 pytest 用例（61 个单测文件）+ e2e 冒烟/视觉回归/性能对比；覆盖率门禁（总 ≥20%、美林时钟 ≥70%）；一致性 guard 体系完善；v3.17.7 全量 724 用例健康度良好。
- **负债**: **`tests/conftest.py` 的 `EXTERNAL_DATA_DIR` 未隔离**——全量 pytest 会写真实 `data/users.json` + `app.db`，与运行中 dev/ops 服务互相污染（v3.13 已踩坑、v3.18 需根治）；总覆盖率 20% 门禁偏低；休眠功能无对应激活态测试。

#### 2.2.5 美工
- **优势**: 7 套主题 + 设计 Token（`tokens.css` 唯一权威）+ 对比度 ≥4.5:1 治理 + ECharts 主题联动 + 移动端一等公民布局（v3.17.2）。
- **负债**: `system-page.js`/`ai-page.js` 大组件内含样式耦合与重复模板；事件提醒/决策复盘等新页面 UI 未成型；复盘阅读入口低频（research 页很少被访问，与能力未激活互为因果）。

#### 2.2.6 用户
- **优势**: 三角色权限 + 多用户隔离（v3.17.13）+ 个性化偏好持久化（v3.17.10）+ 拼音检索 + 初始化向导/新手 tour。
- **负债**: 使用打点显示 **calendar > ai > strategies > system**，research（复盘/异动入口）几乎不用——复盘/事件能力未激活导致用户无感；决策可信度（胜率/因子有效性/回测真实性）**没有任何面向用户的呈现**；i18n 覆盖不足 2 个文件。

#### 2.2.7 运维
- **优势**: 每日自动备份（3:05）+ 部署前备份 + 恢复安全网 + 飞书健康/错误率告警 + 数据源健康监控 + `/metrics` Prometheus 导出 + 一键升级脚本（v3.17.12 双端演练成功）。
- **负债**: 数据源健康状态**未参与自动路由**（健康监控是"仪表盘"，不是"开关"）；调度任务产出无验证（16:00 复盘静默不产也无告警）；ops 与 dev 是两棵内容相同 hash 不同的树，发布对齐靠 `git reset --hard`（有备份分支兜底，流程已文档化）。

### 2.3 机会识别（v3.18 的"激活 + 可信 + 健康"来源）

|---|------|----------|------------|----------|

| D2 | **事件提醒** | `event_alert.py` 接口完整 | provider = `_UnavailableEventProvider`（`available=False`），注释"未来接入真实源" | 中 |
| D3 | **实时行情 WS** | `api/v1/market_ws.py` 端点存在 + `realtime_quotes.py` 完整 | `_fetch_from_tushare`（line 251）**为死代码**，无调用方 | 中 |

## 3. 功能需求

> 分级: **P0**（本版本必做）/ **P1**（本版本应做）/ **P2**（本版本争取或顺延）。每项含：现状 → 需求 → 验收。

### 主题一 · 实（数据闭环落地）

#### FR-3.18.1 — AI 每日复盘激活（P0）
**现状**: `market_review.py` 代码完整（数据卡强约束 + 站内归档 + 飞书推送 + 16:00 调度注册），但 `data/market_reviews/` 归档 0 条——从未真正产出过报告。
**需求**:
1. **复盘产出链路修复**：16:00 调度触发 → 三源数据卡（大盘三指数/领涨领跌板块/资金流向/情绪指标/明日关注）→ 生成报告 → 归档 + 飞书推送；连续 5 个交易日自动产出。
2. **产出验证与告警**：调度执行后校验归档产物存在且字段完整；连续失败 ≥2 次触发飞书告警（不再静默失败）。
3. **手动触发入口**：系统配置页"立即生成复盘"按钮（便于补齐历史与验收）。
4. **周报附胜率**（联动 FR-3.18.5）：周报追加"本周 AI 评估命中率"小节。
**验收**: 归档 ≥5 条真实报告；抽查 20 个数字断言来自数据源（非编造）；断网/源挂场景优雅降级不报错；连续失败有告警；手动触发可用。
**文件**: `backend/scheduler.py`, `backend/market_review.py`, `backend/report_generator.py`, `backend/api/v1/market.py`, `frontend/js/components/system-page.js`

#### FR-3.18.2 — 事件提醒接入真实数据源（P1）
**现状**: `event_alert.py` 默认 provider 为 `_UnavailableEventProvider`（`available=False`），事件提醒"代码就绪、源未接"。
**需求**:
1. **真实事件源**：自选/持仓关联事件——业绩预告、限售解禁、高送转/分红、龙虎榜、融资融券异动（tushare 公告/限售/分红/龙虎榜 + akshare 回退），按 `SOURCE_ORDER` 三源 fallback。
2. **订阅与提醒**：自选/持仓自动订阅；事件触发 → 站内（事件提醒中心）+ 飞书推送。
3. **数据不可达降级**：任一事件源不可达时该类型标注"数据不可达"，**不阻塞其他事件类型、不报错**。
4. **提醒去重与沉默期**：同一股票同一事件 24h 内不重复推送（防刷屏）。
**验收**: 可达场景事件匹配正确（人工抽样一致）；不可达场景优雅降级；去重生效；飞书推送成功。
**文件**: `backend/event_alert.py`, `backend/data_sources.py`, `backend/scheduler.py`, `frontend/js/watchlist.js`, `frontend/js/components/research-page.js`

#### FR-3.18.3 — 实时行情 WebSocket 激活（P1）
**现状**: `api/v1/market_ws.py` 端点已存在，`realtime_quotes.py` 的 `_fetch_from_tushare` 为死代码（无调用方）——实时报价"接口在、没接源"。
**需求**:
1. **源接入**：激活 tushare 实时行情/快照接入 + akshare 快照回退；自选/持仓股盘中报价推送。
2. **涨速/放量预警**（可选）：基于推送流计算涨速/量比预警（数据可达时落地）。
3. **优雅降级**：源不可达 → WS 推送"数据不可达"状态帧，前端显示明确占位，**连接不崩、页面不白屏**。
**验收**: 可达场景自选股实时价格刷新 ≤5s；不可达场景 WS 正常连接但标注不可达；前端降级占位正确。
**文件**: `backend/realtime_quotes.py`, `backend/api/v1/market_ws.py`, `frontend/js/watchlist.js`

#### FR-3.18.4 — 数据源健康自动切换与自愈（P0）
**现状**: `data_sources.py` 有 health monitor + retry_with_backoff + mock fallback，但健康状态**只读不路由**——主源故障时手动重启才恢复，用户侧无感。
**需求**:
1. **自动路由**：按健康状态在 `SOURCE_ORDER` 内自动选源；主源连续失败 ≥N 次切换备用源，恢复后回切（带冷却窗口避免抖动）。
2. **健康状态可观测**：健康面板展示每源"当前路由状态 / 延迟 / 连续失败次数 / 最近切换时间"；切换事件写审计日志 + 可选飞书。
3. **失败计数不误伤**：限流（429）与网络故障区分处理，429 不立即判定源不可用。
**验收**: mock 主源故障 → 自动切备用源且服务无感知；恢复后回切；面板状态正确；审计有切换记录。
**文件**: `backend/data_sources.py`, `backend/api/v1/system.py`, `frontend/js/components/system-page.js`

#### FR-3.18.5 — 周报附胜率追踪（P1）
**现状**: `report_generator.py` 周报模板无胜率；`eval_track.py` 命中率计算逻辑已有（总体/分模型/分评级/N 日窗口）。
**需求**: 周报追加"本周 AI 评估命中率"小节：本周评估数、命中率（5/10/20 日窗口）、分模型/分评级命中率；未满窗口标注"评估中"。
**验收**: 周报含胜率小节；数字与 `eval_track` 计算结果一致；未满窗口正确标注。
**文件**: `backend/report_generator.py`, `backend/eval_track.py`

### 主题二 · 智（决策可信度）

#### FR-3.18.6 — 胜率追踪产品化（决策复盘页）（P1）
**现状**: `eval_track.py` 计算逻辑可用但无面向用户页面（决策复盘功能"有数据、没 UI"）。
**需求**:
1. **决策复盘页**：AI 页新增"决策复盘"入口——日历式展示"当日评估 → 后续 N 日走势"对照（迷你 K 线 + 命中/未命中标注）。
2. **统计总览**：总体命中率/分模型/分评级/分评分区间，N 日窗口（5/10/20）可切换。
3. **风险说明栏**：注明"历史命中率不代表未来收益"，弱化过度自信。
**验收**: 复盘页按日期浏览；命中率与 `eval_track` 人工抽样一致；窗口切换正确；风险说明存在。
**文件**: `backend/api/v1/ai.py`(端点复用/扩展), `backend/eval_track.py`, `frontend/js/components/ai-page.js`, 新增 `frontend/js/components/dialogs/review-decision.js`

#### FR-3.18.7 — 因子有效性检验（IC/IR）（P1）
**现状**: v3.17.3 因子引擎输出"当前值 + 历史分位"，但不回答"这个因子对收益预测有没有用"。
**需求**:
1. **IC 计算**：对每个因子，计算其与未来 N 日收益的横截面 IC（Spearman）时间序列。
2. **有效性报告**：IC 均值、ICIR（IC 均值/IC 标准差）、胜率（IC>0 占比）；标注"有效/失效/不稳定"三档。
3. **展示**：因子面板加"有效性"tab（因子 IC 热力图/排序），供用户识别真正有用的因子。
**验收**: IC 计算与独立抽样一致；三档标注正确；因子面板展示完整。
**文件**: 新增 `backend/factor_ic.py`, `backend/api/v1/market.py`, `frontend/js/components/dialogs/stock-detail.js`

#### FR-3.18.8 — 回测真实性（P2）
**现状**: 回测工作台（v3.17.4）可跑漂亮曲线，但无过拟合防护——用户可能把参数调到"看着最美"。
**需求**:
1. **Out-of-Sample 标注**：回测报告标注样本内/样本外区间（默认后 20% 为样本外）。
2. **参数敏感性**：核心参数 ±10%/±20% 扰动，输出收益/回撤变化范围——越敏感越可疑。
3. **过拟合提示**：样本外收益显著低于样本内（如 <70%）或参数极度敏感时给出"可能过拟合"警示。
**验收**: 样本内外区间正确；敏感性分析输出区间；过拟合警示在触发条件出现时出现。
**文件**: `backend/backtest.py`, `frontend/js/backtest.js`

#### FR-3.18.9 — AI 事实护栏抽查（P1）
**现状**: prompt 强制"数字来自数据卡"，但**无系统级抽查**——幻觉若发生无人知晓。
**需求**:
1. **抽查任务**：调度器按日抽查 AI 回复中引用行情/估值/财务的数值，与本地数据源断言一致性，产出《事实护栏审计报告》。
2. **置信标注**：AI 回复未附数据卡时，前端显示"未经验证"弱化标识（不阻断，仅提示）。
3. **审计页**：系统配置页展示最近审计报告（抽查数/通过率/失败明细）。
**验收**: 抽查任务可手动触发且产出报告；通过率统计正确；失败明细可查。
**文件**: 新增 `backend/fact_check.py`, `backend/scheduler.py`, `backend/api/v1/ai.py`, `frontend/js/components/system-page.js`

#### FR-3.18.12 — 测试隔离根治（P0）
**现状**: `tests/conftest.py` 的 `EXTERNAL_DATA_DIR` 未隔离——全量 pytest 会写真实 `data/users.json` + `app.db`，与运行中 dev/ops 服务互相污染（v3.13 已踩坑：旧 'alice' 用户复活导致偶发失败；`test_today_snapshot.py` 顶层 import 绑定真实路径）。
**需求**:
1. **环境隔离**：所有测试路径（`DATA_FILE`/`DATA_DIR`/`DB_PATH`/`EXTERNAL_DATA_DIR`/日志目录）在 conftest 会话级 patch 到 `tmp_path`，杜绝写真实 `data/`。
2. **import 时序修复**：顶层 `from ... import` 绑死真实路径的模块（如 `test_today_snapshot.py`）改为在 patch 后 import 或显式注入路径。
3. **双实例并行安全**：dev/ops 同时跑全量测试不互相污染。
4. **污染哨兵**：新增测试断言"全量跑完后真实 `data/` 目录 mtime/内容不变"。
**验收**: 全量 pytest 前后真实 `data/` 零变化；运行中服务与测试并行无干扰；哨兵测试通过。
**文件**: `tests/conftest.py`, `tests/test_today_snapshot.py`, 相关受影响测试

#### FR-3.18.13 — 覆盖率攻坚（P1）
**现状**: 总门禁 ≥20%（偏低）；新模块强 TDD（≥70%），存量覆盖不足。
**需求**: 总覆盖率 **≥20% → ≥35%**（CI 门禁在 `pyproject.toml` 同步提升）；核心新模块（fact_check/factor_ic/决策复盘数据层）≥70%；存量采用"改哪测哪 + 按依赖热度优先补测"。
**验收**: CI 覆盖率门禁 35% 通过；新模块 ≥70%；覆盖率报告可读。
**文件**: `pyproject.toml`, 各测试文件

## 5. 用户与使用场景

### 5.1 目标用户
- **C1 量化研究型散户**: 决策复盘、因子有效性、回测真实性 → 3.18 的"智"。
- **C2 上班族看盘用户**: 自动复盘推送、事件提醒、实时行情 → 3.18 的"实"。
- **C3 多用户团队（自托管）**: 数据源自愈、测试隔离、闭环数据 API → 3.18 的"健/开"。

### 5.2 核心使用场景（User Story）
1. 作为 C2，我每天 16:30 收到 AI 复盘推送到飞书，晚上打开站内回看历史复盘。
2. 作为 C2，我自选的持仓股发布业绩预告/解禁，我收到事件提醒 + 飞书推送，点开即看。
3. 作为 C1，我打开"决策复盘"看过去 30 天 AI 评估的命中率，发现"强烈买入"评级命中率明显高于"中性"，据此调整使用习惯。
4. 作为 C1，我在多因子体检里看"因子有效性"tab，发现某因子 ICIR 长期为负——不再依赖该因子。
5. 作为 C3 管理员，我用 API Key 拉取每日复盘与胜率统计接入自己的看板；数据源故障时系统自动切换且告警通知我。

### 5.3 关键体验指标（北向指标）
- **激活态产出率**：复盘归档条数 / 应产天数（目标 ≥95% 且连续 5 日无空档）。
- **事件提醒到达率**：可达事件中已推送占比。
- **决策复盘使用率**：AI 页决策复盘入口点击率提升（打点）。
- **测试卫生**：全量 pytest 后真实 `data/` 零污染（哨兵常绿）。
