## 1. 定位与战略

**V4.0 完成"量化策略研发与运行平台"能力拼图后，4.1-4.5 转向全面优化与打磨。**

用户从六角度评估与迭代：**美观、适用、逻辑通畅、操作便捷、安全、效率**。
六维度映射到 V4.1-V4.5 五个版本（每版本 1-2 维度，便于验收与发版）。

### 1.1 版本主题总览（按风险与性价比定序）
| 版本 | 主题 | 聚焦维度 | 目标 | 定序理由 |
|---|---|---|---|---|
| V4.1 | 安全加固 | 安全 | 封锁 P0/P1 全量，消除公网暴露下的账户接管/SSRF/越权 | ops 公网 cloudflared 暴露 + 匿名改密 = 完整接管路径，**最紧急** |
| V4.2 | 逻辑通畅 | 逻辑通畅 | 功能断点/崩溃/竞态清零 + 三向护栏测试 | 3 个"按钮失效"功能 + WS 部署缺失，半小时复活，**性价比最高** |
| V4.3 | 效率性能 | 效率 | 年视图 O(n²) 冻结消除、同步重活异步化、首屏/缓存 | 年视图 16-21s 阻塞单 worker 全站，**最大可用性风险** |
| V4.4 | 体验筑基 | 美观 + 适用 | 令牌补全、dark 令牌层、对比度达标、主题收敛 | 体验欠账集中清偿 |
| V4.5 | 便捷与收尾 | 操作便捷 + 工程 | 入口归位、交互范式统一、巨型文件拆分起步、版本纪律 | 操作打磨 + 工程债收口 |

### 1.2 验收总纲（六维度金标准）
- 美观：正文对比度 ≥4.5:1 / 大字 ≥3:1；无未定义令牌；主题切换无样式失效
- 适用：所有页面空态/加载态/错误态不崩溃；信息架构贴合任务流
- 逻辑通畅：0 运行时崩溃；状态一致；注入链路有测试护栏
- 操作便捷：核心任务 ≤3 步；入口可达；配置在功能所在页面；"点了有反馈"
- 安全：P0 全封；P1 全封或明示豁免；新增端点 deny-by-default 门禁
- 效率：年视图 <100ms；冷 merrill <1s；首屏脚本 60→≤12；无全站冻结路径

## 4. V4.3 效率性能

### 4.1 现状基线（效率审计，详见 audit_quant_calendar_perf.md）
- **P0-1** /api/view/year 单次 16-21s：views_aggregator.py:321-330 O(n²) 全表扫描 + views.py:66-67 每请求重算 + 单 worker → 实测 20.9s 阻塞致全站请求排队 1.8-2s
- **P0-2** parser.reload() 同步重解析 2-2.5s（1360 万 CSV 单元格，scheduler 3 处同步调用）
- **P0-3** 美林时钟每日首次 13.09s（AKShare 顺序拉取 + 15s 超时×N，async 路由内同步）
- **P1-4** 首屏 60 脚本请求 + 2.5MB 解码体积（零构建 + 无 HTTP/2）
- **P1-5** 未登录即发 9-11 个业务请求（含必 401 的 ai/config）
- **P1-6** 系统页每次进入 ~12 请求 + 年视图 16s 冻结 + tushare/test
- **P2-7** 同 URL 重复请求（view/day 12s 内 3 次）
- **P2-8** /api/system/monitor 固定 205ms（0.2s sleep）+ 用量页 30s×5 轮询
- **P2-9** dashboard 60s TTL 全量重算 + 美林快照每请求写文件
- **P2-10** themes.css 209KB（7 主题重复声明）

### 4.2 需求
| # | FR | 说明 | 验收（量化） |
|---|---|---|---|
| 4.3.1 | 年视图 O(n²) 消除 | 预构建 code→首/末出现日期倒排索引 + 状态并入聚合缓存 + to_thread | 16-21s → **<100ms**；消除全站冻结 |
| 4.3.2 | 同步重活异步化 | parser.reload 迁 asyncio.to_thread + 双缓冲原子替换 + 每日首访预热（美林冷拉取） | reload 2.5s → 异步零感知；冷 merrill 13s → <1s |
| 4.3.3 | 首屏按页分包 | 构建/import map + 动态 import 按页加载组件 JS；uvicorn 开 HTTP/2 | 脚本 60 → **≤12**；WAN TTI 3-6s → 1.5-2.5s |
| 4.3.4 | 请求调度统一 | 未登录仅拉 health/themes；AI 配置走鉴权 apiFetch；系统页并入 qcCache；轮询加 visibilitychange | 首屏请求 -50%；系统页 -70%；后台流量 -60% |
| 4.3.5 | 后端降本 | dashboard TTL 60→300s；monitor CPU 采样缓存；美林快照节流 | 后端无效 CPU/写降 ~80% |

### 4.3 备注
- 4.3.1 为收益最大项（消除单 worker 下最大可用性风险）；4.3.3 是零构建架构最大体验杠杆（需评估构建层引入成本，可与用户确认是否接受"零构建"约束放松）
