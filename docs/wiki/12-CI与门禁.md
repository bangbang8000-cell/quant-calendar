## 流水线结构（`.github/workflows/ci.yml`）

触发条件：**tag `v*` / PR 到 master / 手动 workflow_dispatch**（普通 push 不跑）。

```
layer1-lint-contract        门禁第①层：锁文件一致性 + ruff + 版本纪律
        ↓
layer2-unit-tests           门禁第②层：全量 pytest + 覆盖率主护栏 + 一批模块级覆盖率门禁
        ↓
split-parity-gate  ├─ rbac-matrix-gate  ├─ pit-gate  ├─ performance-gate  ├─ bundle-size-gate
                             （5 个并行）

e2e-visual                  独立 job：起 dev server + Playwright 视觉回归
```

## 红了怎么查（三步）

```bash
# 1) 哪一次、哪个 job、哪一步
gh run list --workflow=ci.yml --limit 3
gh run view <run-id>
gh run view <run-id> --json jobs --jq '.jobs[]|select(.conclusion=="failure")|.steps[]|select(.conclusion=="failure")|.name'

# 2) 只看失败步骤的日志
gh run view <run-id> --log-failed | sed 's/^[^\t]*\t[^\t]*\t[0-9T:.Z-]* //' | tail -40

# 3) 本地复现（务必对齐 CI 的时区与工具版本）
TZ=UTC PYTHONPATH=<ws>/qc_ws_pkgs python3 -m pytest <该门禁的测试集> -q
```

**0 秒失败、无任何 job** → 不是代码问题，是 workflow 文件解析失败，先看下面「坑 1」。

## 八个坑与定论

### 坑 1：workflow 文件 YAML 非法（0s 失败，无 job）
症状：GitHub 提示 *"This run likely failed because of a workflow file issue"*。

两个真实原因（v6.5.8 引入）：
- 文件开头有 **UTF-8 BOM** → 首键变 `\ufeffname`
- 步骤名是未加引号的 plain scalar 且**内部含「: 」**：
  `- name: Lint — 失败修复命令: ruff check ...` → `mapping values are not allowed here`

> 定论：步骤名里带冒号必须加引号。本地可用 `python3 -c "import yaml;yaml.safe_load(open('.github/workflows/ci.yml'))"` 先校验。

### 坑 2：锁文件漂移 —— `uv pip compile` 会"沿用旧 pin"
症状：`diff` 显示一堆版本差异（akshare、fastapi…）。

- 本地执行 `uv pip compile -o requirements.lock` 时**输出文件已存在** → uv 会尊重旧版本，看起来"没漂移"
- CI 编译到**临时路径** → 解析「最新版」
- 定论：要复刻 CI 必须加 `--upgrade`

```bash
uv pip compile --upgrade --universal --python-version 3.11 requirements.in -o requirements.lock
uv pip compile --upgrade --universal --python-version 3.11 -c requirements.lock requirements.dev.in -o requirements-dev.lock
```

### 坑 3：uv 版本不同 → 注释差异也能让 diff 红
CI 锁 `uv==0.11.7`；本机 0.13.x 生成 `# via` 时会**重复一行** `#   -c requirements.lock`。

> 定论：**锁文件必须用与 CI 相同版本的 uv 生成**。本机可 `pip install --target=<ws>/.uv011 uv==0.11.7` 再 `PYTHONPATH=<ws>/.uv011 python3 -m uv ...`。

### 坑 4：Lint 步骤从未安装 ruff
`ruff check` 直接跑 → CI 镜像不带 → **exit 127**。定论：步骤前必须显式安装，且版本取自锁文件：

```yaml
- name: 安装 ruff（版本取自 dev 锁文件）
  run: |
    V=$(grep -oP '^ruff==\K[0-9.]+' requirements-dev.lock)
    uv pip install --system "ruff==${V}"
```

### 坑 5：覆盖率门禁的"测试集不含新模块"
症状：`_fuyao.py` 20%、`_correction.py` 0%、`api/v1/watchlist.py` 56% → 合计不过线。

原因不是代码没测，而是**门禁命令的测试集清单没跟着加**。同一个门禁在文件里可能出现**两处**（本次就有两处 data_sources、两处 merrill），必须都改。

> 定论：新增模块时，先搜 `grep -n "cov=<模块>" .github/workflows/ci.yml`，确认每处门禁的测试集都包含它的测试文件。

### 坑 6：CI 在 UTC，本机在 CST —— 时区相关 bug 只有 CI 能抓
本次抓到的真 bug：DWH 落库用 `CAST(to_timestamp(date_ms/1000) AS DATE)`，UTC 容器里日期**整体前移一天**，连带增量判定从 INCREMENTAL 误变 FULL。

> 定论：**本地复现必须 `TZ=UTC`**；涉及"毫秒时间戳 → 日期"的地方一律按 +08:00 固定折算，不依赖进程时区。

### 坑 7：测试写死了内部结构
`{r.path for r in APIRouter.routes}` 在 fastapi 0.162 / starlette 1.10 上取到空集 → 4 个"路由已注册"用例误红。

> 定论：路由断言走 **OpenAPI 契约**（`app.openapi()['paths']`），见 `tests/route_paths_helper.py`。

### 坑 8：体积门禁把「目标」当「fail 线」
PRD 目标（总 1800 / 入口 400 / EP 600 KB）从未达成（实测 2475 / 1085 / 907 KB，未做代码分割）。长期恒红 = 没有防护。

> 定论：拆两层 —— `DEFAULT_THRESHOLDS`（回归护栏 = 实测 + ~8%）负责 fail，`TARGET_THRESHOLDS`（PRD 目标）只在报告里展示差距。**瘦身是独立任务，不靠改阈值解决。**

## 门禁清单（本地怎么跑）

| 门禁 | 本地命令 |
|---|---|
| 锁文件一致性 | 坑 2 的两条 `uv pip compile --upgrade` + `diff` |
| ruff | `ruff check backend/ --select=E,F,W --ignore=E501` |
| 版本纪律 | `pytest tests/test_version_governance_610.py -q` |
| 全量测试 | `TZ=UTC pytest -m "not e2e" -q` |
| 覆盖率主护栏 ≥40% | 全量测试自带 `--cov` |
| 模块覆盖率 | `pytest <该门禁测试集> --cov=<模块> --cov-fail-under=N` |
| PIT 审计 | `pytest tests/test_pit_no_lookahead.py -q` |
| 体积 | `python3 scripts/report_bundle_size.py --gate` |
| 前端结构 | `pytest tests/test_frontend_consistency.py tests/test_frontend_setup_wiring.py -q` |
| e2e 视觉 | 起 dev server 后 `python3 tests/e2e/visual_regression.py --report --base-url http://127.0.0.1:8001/` |

## e2e 视觉回归的两个约定

1. **断言（硬失败）** vs **差异（信息性）**：场景状态断言不通过 → 拒绝产图并 exit 1；
   像素差异只写报告，除非加 `--strict`。
2. 场景 `expect.title` 跟随 `document.title` 口径 = `<一级成员名> - 量化日历`
   （6.5.0 起；成员名见 `MEMBER_LABELS`）。详情有两种形态：宽屏右栏分栏 `.detail-split-pane`、
   窄屏弹窗 `.kline-dialog`，断言要同时兼容。

## 已知欠债
