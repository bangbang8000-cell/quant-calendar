# 11 性能与缓存

> v7.3.2 起实施。起因：用户反馈「短线复盘每次点击后要重新刷新很久，感觉没做缓存」。

## 实测：慢在哪里（不是短线，是研究卡）

| 接口 | 修复前 | 修复后（命中） |
|---|---|---|
| `/api/research/backtest-lab` | **9.6–10.4 s/次** | 0.06 s |
| `/api/research/sentiment-pulse` | 0.8–1.1 s/次 | 0.004 s |
| `/api/research/lhb-topology?days=3` | 0.3–1.4 s/次 | 0.013 s |
| `/api/research/industry-strength?refresh=1` | **67–68 s/次** | 0.03 s（转后台） |
| 短线 7 个子页接口 | 0.01–0.18 s | 0.006–0.16 s（本来就不慢） |

结论：短线接口一直是毫秒级；拖慢体感的是 v7.1–v7.3 加进概览页的四张研究卡，
其中回测要在 110 万行 DuckDB 面板上跑 walkforward，而且**零缓存**。

## 三层缓存

### 1）服务端 TTL 缓存 + 单飞（`backend/ttl_cache.py`）

```python
ttl_cache.cached(key, ttl, producer)
```

- 命中直接返回；未命中计算并缓存；**异常不缓存**
- **单飞**：同一 key 并发请求只计算一次，其余等同一个结果（首屏多卡并发不重复算）
- 计算在锁外进行，长任务不阻塞其它 key
- 现状：

| 接口 | TTL | key 关键字段 |
|---|---|---|
| `backtest-lab` | 1800 s | lookback / top_k / start / frac / **库内最新日期** / 行数 |
| `sentiment-pulse` | 300 s | 交易日 |
| `lhb-topology` | 300 s | 天数 / end |

> key 里带「库内最新日期」是刻意的：数据一更新，结论自动失效，不会拿旧结论骗自己。

观测与强制失效（admin）：`GET /api/research/cache-stats`、`POST /api/research/cache-clear`。

### 2）重活转后台（`industry_strength.start_background_refresh`）

行业强度全量刷新要拉 320 个行业 × 84 根日 K（约 68 s）。现在：

- **有缓存** → 立即返回缓存 + `refreshing: true` + 说明文案，后台线程去刷新
- **无缓存** → 同步刷新一次
- 单飞：已有刷新在跑时不会叠加第二个

### 3）启动预热（`backend/warmup.py`）

进程启动后延迟 25 s（给数据源/调度让路），在**后台线程**里预计算：

1. 回测实验室（默认参数）→ 写进 TTL 缓存
2. 行业强度矩阵（缓存过旧时）→ 触发后台刷新

日志样例：

```
[warmup] 后台预热线程已启动（延迟 25s）
[warmup] 回测预热完成：面板 1099796 行，总收益 1.96
[warmup] 行业矩阵缓存仍新鲜，跳过
```

预热失败只记日志，绝不影响服务启动。

## 4）前端缓存（`shortterm/logic-cache.js`）

| 旧实现的问题 | 现在 |
|---|---|
| 缓存在 `setup()` 里 → 组件被 KeepAlive 重建/路由切换（如"市场复盘"走研究页组件）就丢 | 提到**模块级**（`window.__qcShorttermCache`） |
| 统一 60 s TTL | **分级**：研究类 10 分钟、行情类 60 秒 |
| 无并发去重：挂载时 `prefetchShortterm` 与 `loadCurrent` 双打同一批 URL | **in-flight 去重**，同 URL 并发共享一个 Promise |
| LRU 上限 50 | 120（研究类多 URL + 长 TTL 需要空间） |
| POST 生成复盘后直接写内部字典 | 通过域对象 `put()` 回填 |

## 改代码时的约定

1. **新增重接口先想缓存**：单次 >0.3 s 或含全市场遍历 → 用 `ttl_cache.cached`，key 必须含「数据版本」（日期/行数）。
2. **不要让请求等长任务**：>10 s 的操作改后台 + 返回 `refreshing`。
3. **前端重数据用研究类 TTL**：`/api/research/*`、`/api/dwh/*` 自动 10 分钟。
4. **测试里清缓存**：`tests/conftest.py` 已加 autouse fixture，新增用例不必自己清。

## 自检命令

```bash
# 两次耗时对比（第二次应为命中）
curl -s -o /dev/null -w "%{time_total}s\n" -H "Authorization: Bearer $TOK" \
  http://127.0.0.1:8000/api/research/backtest-lab?lookback=20&top_k=10

# 缓存统计（admin）
curl -s -H "Authorization: Bearer $ADMIN_TOK" http://127.0.0.1:8000/api/research/cache-stats
```

期望：`entries` 随浏览增长、`hits >> misses`；若 `misses` 持续增长而 `hits` 不涨，说明 key 里有每次都变的字段（常见错误：把毫秒时间戳放进 key）。
