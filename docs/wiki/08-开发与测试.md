# 08 开发与测试

## TDD 四步（本项目固定节奏）

1. **写失败测试**：先明确契约（输入/输出/降级语义），跑一次确认它红。
2. **最小实现**：只写到测试通过，不做"顺手加的优化"。
3. **重构**：拆分/命名/去重，测试保持绿。
4. **提交**：一个交付包一次提交，**≤3 个文件**，提交信息写清"为什么"。

## 提交信息规范

```
feat(7.3): B7.1 财务质量分位 — 六项指标 + 样本内分位 + 综合分

TDD: tests/test_fin_quality.py(9 例) 全绿。

- 三张表按 fiscal_year 归并...
- 分母为 0 → None（不填 0）
实测: 茅台 ROE 32.4% ...
```

前缀：`feat / fix / test / docs / refactor / chore`，括号里是版本线。

## 代码组织约定

| 约定 | 原因 |
|---|---|
| 单文件 ≤700 行 | 超了就拆域，不靠注释分区 |
| 数据模块返回 dict，**不抛异常** | 上游不可用是常态，异常留给真 bug |
| 能力自检放在调用点 | `if not manager.fuyao_capability_enabled('special'): return {...}` |
| 兜底必须有 reason | 前端要能显示"为什么没有" |
| 文案走 `disclosure_terms` | 口径错误比数据错误更危险 |

## 新增一个数据能力的完整清单

1. `backend/<模块>.py`：取数 + 归一 + 纯函数（可测）
2. `tests/test_<模块>.py`：正常路径 + 降级路径 + 边界（缺字段/空/非法参数）
3. `backend/api/v1/<路由>.py`：端点（异常转 `available=false`）
4. `tests/test_<路由>_api.py`：形状 + 降级 + 路由注册
5. 若涉及口径：`meta` 带公式 / `caliber` / `disclaimer`
6. 前端（可选）：卡片 + `logic-*.js` 状态与加载器 + 四态
7. 验收：`docs/ACCEPTANCE-vX.Y.Z.md`
