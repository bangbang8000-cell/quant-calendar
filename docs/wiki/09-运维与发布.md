# 09 运维与发布

## 双环境模型

| 环境 | 目录 | 端口 | 用途 |
|---|---|---|---|
| dev | `/home/evergreen/dsh-workspace/quant-calendar-dev` | 8001 | 开发、跑测试、试改动 |
| ops | `/home/evergreen/dsh-workspace/quant-calendar-ops` | 8000 | 只读部署，给用户用 |

两个目录的 `.env` 与 `data/` **严格独立**。同步方式：

```bash
cd ~/dsh-workspace/quant-calendar-ops
git fetch ~/dsh-workspace/quant-calendar-dev master
git reset --hard FETCH_HEAD
```

> ops 只做 `fetch + reset`，**不在 ops 里改代码**。

## 服务管理（systemd --user）

```bash
export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus

# 重启
dbus-send --session --print-reply --dest=org.freedesktop.systemd1 \
  /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager.RestartUnit \
  string:"quant-calendar-ops.service" string:"replace"

# 状态
systemctl --user status quant-calendar-ops.service
journalctl --user -u quant-calendar-ops.service -n 100 --no-pager
```

服务名：`quant-calendar-ops.service`（:8000）、`quant-calendar-dev.service`（:8001）。

## 版本策略

| 规则 | 说明 |
|---|---|
| 版本号单一来源 | `backend/main_new.py` 的 `APP_VERSION`，`bump_version.py` 同步 README / HANDOVER |
| tag | 发布时打 `vX.Y.Z` |
| Docker 镜像 | **只对关键版本（`x.y.0`）构建**，工作流门禁 `endsWith(ref_name, '.0')` |
| 镜像保留 | 最多 **10 个**版本轮动淘汰（`KEEP_VERSIONS: 10`），清理脚本 `scripts/docker_versions_prune.sh`（默认 dry-run） |
| `latest` 标签 | 只在 tag 构建时更新，防止普通构建把 latest 打回旧版本 |

## 数据维护

| 任务 | 命令 |
|---|---|
| DWH 增量/全量 | `POST /api/dwh/refresh?kind=daily-k`（admin）或 `get_backend().sync()` |
| DWH 状态 | `GET /api/dwh/status`（admin） |
| 备份位置 | `data/dwh/backup/`（保留 7 天，自动清理） |
| 复现用 Parquet | `data/dwh/archive/`（只留最新 1 份） |
| 短线池落库 | `POST /api/shortterm/capture`（调度或手动） |

```bash
# 恢复 DWH（备份文件可直接打开，无需还原工具）
cp data/dwh/backup/market_YYYYMMDD.duckdb data/dwh/market.duckdb
```

## 排障速查

| 现象 | 先看什么 |
|---|---|
| 页面数据为空 | 该端点的 `available` / `reason`；再看 `/api/market/fuyao/status` |
| 行情大面积降级 | `TUSHARE_TOKEN` 是否真实值；`/api/market/datasource/status` |
| 研究接口慢 | 是否在跑逐票（DWH 未建或 `dwh.enabled=false`） |
| 启动失败 | `journalctl --user -u ... -n 200`；常见是 `.env` 里有未声明的字段（Settings 严格模式） |
| 版本不一致 | 跑 `pytest tests/test_version_governance_610.py` |
