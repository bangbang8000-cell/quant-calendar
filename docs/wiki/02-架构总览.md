# 02 架构总览

## 一句话分层

```
前端（Vue 3 SPA, dist 入库）
        ↓ REST /api/*
服务层（FastAPI）—— T1/T2/T3 分层在这里生效
        ↓
数据层（四源热备 + 本地 DuckDB 面板）
```

## 数据分层（硬约束）

| 层 | 内容 | Fuyao 能否参与 |
|---|---|---|
| **T1 核心** | 交易日历、日线/分钟线、策略选股、回测底座、每日指标 | **禁止**（`T1_FORBIDDEN={'fuyao'}`，路由处过滤） |
| **T2 周边** | 涨停/炸板/跌停池、龙虎榜、竞价、热榜、异动、新闻、概念、财务 | 优先，本地源补齐，逐字段 `field_source` |
| **T3 加速** | 概念图谱、因子面板 | 仅加速，**永不是唯一路径** |

为什么 T1 要禁：核心行情一旦换源，用户看到的历史数据会在某天悄悄变形（除权、成交量口径、复权方式）。产品选择"核心口径只认稳定的三源"，把新源放在周边做增量。

## 后端模块地图

| 模块 | 职责 |
|---|---|
| `backend/main_new.py` | 入口、`APP_VERSION` 单一来源 |
| `backend/data_sources/` | 四源管理（`_manager.py`）、Fuyao 客户端（`_fuyao.py`） |
| `backend/data_tier.py` | T1/T2/T3 分层、路由过滤、字段仲裁 |
| `backend/dwh/` | DuckDB 面板：`adapter.py`（唯一允许 import vendor 处）+ `native.py` |
| `backend/shortterm/` | 短线复盘：三池、天梯、龙虎榜、情绪指标 |
| `backend/*.py` 研究模块 | 行业强度、导出、脉冲、拓扑、共振、财务、审计、回测 |
| `backend/api/v1/` | REST 路由（含 `research.py`、`dwh.py`、`shortterm_extras.py`） |
| `libs/marketdb/` | vendor 的官方 marketdb（DDL/视图/复权因子算法） |

## 前端结构

- **零构建部署**：`frontend/dist` 入库，后端直接 serve；改前端才需要 `npx vite build`。
- **拆分契约**：页面按域拆文件（`view-part1/2.js` + 逻辑域 `logic-*.js`），有"模板可重建"对拍门禁（拆文件不能改变渲染结果）。
- **令牌体系**：颜色/字号/间距全部走 `css/tokens.css`，有"未定义令牌/硬编码色值"门禁。

## 请求链路示例（短线三池）

```
GET /api/shortterm/pools
  → shortterm.fetchers.fetch_zt_pool(prefer='fuyao')
      → Fuyao limit-up-pool（成功则用其独有字段）
      → 本地三源补齐缺失字段
      → 合并 + field_source 溯源
  → store 落库（下次命中缓存）
  → 响应附 meta: source / include_st / stats
```

## 关键设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 面板换源风险 | T1 永不用新源 | 核心数据要稳定 |
| DWH 依赖 | vendor 官方包 + 自有 native 回退 | 复用官方语义，但保留退路 |
| 前端体积 | 预算门禁（1.60 MB） | 已到最后一次上调，再涨必须先拆懒加载 |
| 单文件行数 | ≤700 行 | 超了就拆，不靠"以后再说" |
