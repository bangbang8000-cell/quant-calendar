# 03 数据源与数据治理

## 四源热备

```
sxsc_tushare  →  tushare  →  akshare  →  fuyao
   （首选）        （主力）     （兜底）    （周边优先）
```

- 任一源失败自动切换，**失败原因**会写进响应（不静默）。
- T1 核心链路**剔除 fuyao**；T2 周边链路**优先 fuyao**。

## Fuyao（同花顺）能做什么、不能做什么

### 能（T2 周边优先源）

| 能力域 | 典型数据 | 实测 |
|---|---|---|
| `special` | 涨停池（含 ST）、炸板池、跌停池、连板天梯、涨停统计、龙虎榜、热榜、飙升榜、异动解读、竞价机会 | 涨停 52 家、龙虎榜 88 条、异动 473 条/日 |
| `news` | 个股分时新闻、市场快讯 | 单股 20 条、快讯 20 条 |
| `concept` | 指数目录（320 行业）、成分、个股所属概念 | 320/320 覆盖，100 只/批 |
| `fin` | 利润表 / 资产负债表 / 现金流量表（`period=annual\|quarter` 必填） | 可算六项财务指标 |
| `auction` | 竞价快照、竞价基准、竞价机会 | 支持 `period` 校验 |
| `dwh` | 全市场日 K dump、复权事件 dump、10 日增量 | 173.7 MiB / 1036 万行 |

### 不能 / 不用于

- **T1 核心**：日线分钟线的核心口径、交易日历、策略/回测底座。
- **全市场分位**：请求量过大（5500×3 次），财务分位只做**入参池内样本分位**。
- **盘口级成交**：日 K 无法还原撮合，文案里不许出现"盘口成交"。

## 三级开关

| 级别 | 开关 | 生效方式 |
|---|---|---|
| L1 | `sources.fuyao.enabled` | 热读，关闭后所有能力域视为不可用 |
| L2 | `sources.fuyao.capabilities.<域>` | 单域开关（prices/valuation/special/news/concept/dwh） |
| L3 | 代码里的 `fuyao_capability_enabled('special')` 等 | 调用点自检，不可用即降级 |

## 密钥治理

- `FUYAO_API_KEY` **只从环境变量读取**，任何 API 都不返回明文；系统页只显示掩码。
- 数据源配置接口显式剔除 `fuyao.token` 字段，禁止写入配置文件。
- 密钥查看需要 `SECRET_REVEAL_PASSWORD` 解锁。

## 口径纪律（重要）

项目内置**禁称词表**（`backend/disclosure_terms.py`），命中即拦截：

| 禁称 | 应该说 |
|---|---|
| 指数贡献 | 等权涨跌代理 |
| 全市场晋级率 | 样本内晋级率（不可外推） |
| 盘口成交 | 日线级近似成交 |
| 精确复权 | 复权（口径已标注） |
| 买入信号 / 推荐买入 / 必涨 | 数据观察 |

**导出物必须有四要素**：数据时间、来源 endpoint、计算口径、非投资建议。缺一即不合格。

> 真实案例：v7.1 开发时我在口径文案里写了「不是「指数贡献」」，被这条守护当场拦下，导出直接失败。它连"引用禁称来解释禁称"都不允许。

## 降级语义

所有能力关闭/失败都返回结构化原因，而不是空表：

```json
{"available": false, "reason": "capability_disabled"}
```

常见 reason：`capability_disabled`（开关关闭）、`not_configured`（未配 Key）、`fetch_failed` / `upstream`（上游失败）、`invalid_param`（参数错，属于我方 bug）、`no_codes`（调用方未传股票）。

空列表**可能代表上游降级**，相关接口会在 `note` 里写明，不能当作"该期间无数据"。
