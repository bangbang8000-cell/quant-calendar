## 2. 战略背景与现状评估

### 2.1 一句话定位

**v3.17 的目标是从"功能完备、体验良好"跃迁到"智能、实用、好用、高效"的卓越级量化工作台**：
让散户/专业用户在"看盘 → 选股 → 评估 → 决策 → 复盘"的完整闭环中，每一个环节都比 Excel + 搜索引擎 + 通用 Chat 更高效、更专业、更省心。

### 2.2 七维度现状评估（基于 v3.16.1 全库审计）

#### 2.2.1 系统架构
- **优势**: FastAPI + SQLite（WAL/迁移）+ 三源热备数据源（sxsc→tushare→akshare 自动 fallback）+ 自研 asyncio 调度器（9 任务）+ 双环境物理分离（dev 8001 / ops 8000）+ Docker/CI 完备。
- **负债**: `ai_evaluator.py` ≈ 84KB/2092 行、`app-logic.js` ≈ 110KB 巨型单体；限流为单进程内存实现（`SimpleLimiter`）；`REDIS_URL`/`DATABASE_URL` 为遗留配置（无 redis 依赖）；多源存储混杂（同数据 SQLite 与 JSON 双写/回退）。

#### 2.2.2 软件设计
- **优势**: 「基础模块 + 领域模块 + 页面/对话框组件」分层已成型；`window.__quantModules` 工厂 + `qcState` provide/inject；virtual-list/state-panel 等可复用组件与纯计算核心（可 node 单测）。
- **负债**: `qcState` 历史重复键（16.x 已部分收敛）；fetch 鉴权两套（index.html monkey-patch 与 `core.apiFetch`）；主题应用三套实现；`js/calendar.js`/`js/strategies.js` 空壳死代码；前端 767 处内联 `style=` 违反设计 Token 规范。

#### 2.2.3 程序
- **优势**: CSP nonce + sanitizeHtml + JWT/bcrypt + 审计日志 + 请求 trace_id 结构化日志；覆盖率门禁 + ruff + 锁文件校验入 CI。
- **负债**: 全后端 131 处 `print(`、大量 `except: pass` 式吞错；`[DEBUG]` 遗留 console.log；`sw.js` 缓存名仍为 `v3.8`（与当前版本脱节）；APP_VERSION 硬编码。

#### 2.2.4 测试
- **优势**: 351 个 pytest 用例（conftest 临时目录隔离）、e2e 视觉回归 + 发布冒烟、覆盖率门禁（总 ≥20%、美林时钟 ≥70%）。
- **负债**: 总覆盖率偏低（护栏 20%）；e2e 为 `continue-on-error` 不阻塞发布；前端组件级测试依赖 Playwright、无数据层/组合层隔离测试。

#### 2.2.5 美工
- **优势**: 7 套主题 + 设计 Token（`tokens.css` 唯一权威）+ 对比度 ≥4.5:1 治理 + 4 套图标系统 + ECharts 主题联动。
- **负债**: 内联样式泛滥导致视觉一致性难以维护；登录/列表/详情等页面信息密度与留白可再优化；移动端仅"降级适配"而非"一等公民"。

#### 2.2.6 用户
- **优势**: 三角色权限（admin/user/guest）+ 自选/评估历史按用户隔离 + 初始化向导 + 新手指引 tour + 键盘无障碍基线。
- **负债**: **聊天历史未按用户隔离**（硬编码 `username="default"`）；无 i18n（硬编码中文）；无个性化（布局/默认视图偏好）；移动端体验薄弱。

#### 2.2.7 运维
- **优势**: 每日自动备份 + 手动恢复（恢复前安全网）+ 飞书健康/错误率告警 + 数据源健康监控 + 备份保留 30 天。
- **负债**: 无可观测性外部导出（无 Prometheus/日志聚合）；指标仅内存累计；部署/升级仍需手工同步（无一键升级）。

### 2.3 金融/股市专业视角的机会识别（3.17 的"实用"来源）

结合量化投研与散户交易痛点，识别以下高价值机会（按对用户决策价值的综合排序）：

| # | 机会 | 用户痛点 | 数据可行性（Tushare/akshare 可覆盖） |
|---|------|----------|--------------------------------------|
| O1 | **回测可视化落地**（策略回测 → 收益曲线/回撤/夏普/胜率） | 选股策略"好不好"无数据支撑 | 后端回测 API 已就绪，仅缺前端 |
| O2 | **组合/持仓管理**（自选组合盈亏、模拟持仓、调仓记录） | 看对了股却赚不到钱，缺乏纪律 | 自选+行情历史已具备，增量小 |
| O3 | **盘中实时行情与异动预警**（WebSocket 推送、涨速/放量/涨停预警） | 收盘数据滞后，错过买卖点 | tushare 实时行情/akshare 快照可扩展 |
| O4 | **AI 市场复盘自动生成**（每日大盘/板块/情绪/资金复盘） | 每天看盘 2 小时 vs AI 3 分钟 | 指数+板块+资金流数据已具备 |
| O5 | **个股多因子体检**（技术+基本面+资金面+情绪面+事件面） | 单看技术指标会误判 | daily_basic(PE/PB/ROE)/moneyflow/公告 可扩 |
| O6 | **事件/公告驱动提醒**（业绩预告/解禁/分红/龙虎榜） | 踩雷风险 | tushare 公告/资金流/融资融券 |
| O7 | **异动扫描器**（全市场涨跌幅/量比/振幅/连板） | 机会发现慢 | 全市场日线已具备 |
| O8 | **决策复盘**（评估记录 vs 实际走势的"胜率追踪"） | 不知道 AI 评估准不准 | 评估历史+历史行情可联动 |

> **取舍原则**: 3.17 聚焦 O1/O2/O4/O5/O8（强化"决策与复盘"主线，投入可控、闭环完整）；O3/O6/O7 作为 3.17 的"盘中增强"子主题渐进落地（先离线事件/异动扫描，再 WebSocket 实时）。

## 3. 功能需求

> 分级: **P0**（本版本必做）/ **P1**（本版本应做）/ **P2**（本版本争取或顺延）。每项含：现状 → 需求 → 验收。

### 主题一 · 智（智能增强）

#### FR-3.17.1 — AI 问股升级为"智能投顾助手"（P0）
**现状**: `ask_stock.py` 单轮问答 + 技术面/基本面/策略面融合 + RAG 注入历史评估与自选状态；SSE 流式。
**需求**:
1. **多轮上下文**：同一会话内记忆前面轮次结论，支持追问"那回撤到哪个位置要止损？"。
2. **多股票对比**：一次输入多代码（如 "600519 与 000858 对比"），输出对比表格（估值/技术/资金/风险）。
3. **组合诊断**：输入自选/组合，AI 输出组合画像（行业集中度、风格暴露、相关性、风险点）。
4. **事实护栏**：AI 回答涉及行情/估值/财务数字时，强制从本地数据生成"数据卡"（数值+时间戳+来源），避免幻觉；来源不可得时明确标注。
**验收**: 多轮追问闭环可复现；多股对比输出结构化表格；组合诊断输入自选一键生成；抽查 20 个数值断言来自本地数据源。
**文件**: `backend/prompts/ask_stock.py`, `backend/agent_tools.py`, `frontend/js/ai-chat.js`

#### FR-3.17.2 — AI 每日市场复盘自动生成（P0）
**现状**: 已有日报/周报定时推送（飞书），但为模板化数据简报，无 AI 解读。
**需求**:
1. **AI 复盘报告**：每日收盘后由 AI 生成《市场复盘》：大盘三指数表现 → 领涨/领跌板块 → 资金流向（行业/个股）→ 情绪指标（涨跌家数/连板/成交额）→ 明日关注点。支持飞书/邮件推送 + 站内存档可回看。
2. **复盘模板化**：prompt 内置"数据→结论"结构，所有数字来自数据卡，禁止编造。
3. **胜率追踪联动**（见 FR-3.17.6）：每周复盘附带"本周 AI 评估命中率"。
**验收**: 调度器在收盘后产出可回看的复盘报告；数字均来自数据源；飞书推送成功；报告页可浏览历史复盘。
**文件**: `backend/scheduler.py`, 新增 `backend/market_review.py`, `backend/prompts/review_daily.txt`, `frontend/js/components/research-page.js`

#### FR-3.17.3 — 个股多因子体检（P0）
**现状**: 评估仅注入技术指标（RSI/MACD/MA/KDJ）+ 评分维度。
**需求**: 个股详情新增**多因子体检面板**（数据卡，非 AI 生成）：
1. **估值面**: PE/PB/PS/股息率 + 历史分位。
2. **基本面**: ROE/毛利率/净利率/营收与净利增速（近 3 期）。
3. **资金面**: 主力资金流向（近 5 日/20 日）、融资余额变化。
4. **情绪面**: 换手率/量比/20 日波动率/历史分位。
5. **技术面**: 现有 MA/RSI/MACD/KDJ 保留并加"位置分位"。
每个因子给出"偏低/中性/偏高"语义化标注 + 数据时间戳；供 AI 评估注入（增强 prompt），也直接展示给用户。
**验收**: 详情页六面板数据齐全（Tushare 可达场景）；分位标注正确；AI 评估 prompt 含新因子；数据缺失时有明确"无数据"占位。
**文件**: `backend/ai_indicators.py` 扩展或新增 `backend/factor_engine.py`, `backend/api/v1/market.py`, `frontend/js/components/dialogs/stock-detail.js`

### 主题二 · 实（量化实用闭环）

#### FR-3.17.4 — 回测可视化落地（P0）
**现状**: 后端回测 API 完整（单/多策略、指标、对比），前端无 UI（README 标注"前端 UI 已移除"）。
**需求**:
1. 策略总览新增**回测工作台**：选择策略/股票池/时间区间 → 收益曲线（净值 + 基准）、最大回撤区间标注、年度收益、夏普/胜率/盈亏比、交易明细。
2. **对比视图**：多策略或策略 vs 基准并排对比。
3. 回测参数可视化编辑（初始资金/区间/手续费率），结果可导出 CSV。
**验收**: 回测从发起→结果渲染≤5s（500 交易日）；曲线/回撤/指标齐全；导出 CSV 可用；与后端现有 API 字段一致。
**文件**: `frontend/js/components/strategies-page.js`, `frontend/js/backtest.js`(新), `backend/api/v1/backtest.py`(按需微调)

#### FR-3.17.5 — 组合/模拟持仓管理（P1）
**现状**: 只有自选股收藏 + 快捷评估，无"仓位/盈亏"概念。
**需求**:
1. **模拟持仓**：自选股可录入成本价/数量 → 显示浮动盈亏、收益率、持仓市值、组合当日/累计收益。
2. **组合视图**：按持仓聚合的收益曲线（近 1 周/月/3 月）、行业分布饼图、持仓集中度提示。
3. **调仓记录**：手动记录买入/卖出 → 组合收益率按资金加权计算。
4. 与 FR-3.17.6 联动：AI 诊断组合风险。
**验收**: 录入持仓后盈亏/收益实时计算正确（与行情一致）；组合收益曲线与行业分布正确；调仓记录影响收益率。
**文件**: `backend/api/v1/portfolio.py`(新), `backend/db.py`(新表), `frontend/js/watchlist.js` 或新增 `frontend/js/portfolio.js`

#### FR-3.17.6 — 评估胜率追踪（决策复盘闭环）（P1）
**现状**: 评估历史存原始结果，无"预测 vs 实际"对照。
**需求**:
1. **命中率统计**: 对每条评估记录，按 N 日（5/10/20）后的实际涨跌对照评级方向，统计总体命中率/分模型命中率/分评级命中率。
2. **决策复盘页**: 日历式展示"当日评估 → 后续走势"缩略图（迷你 K 线 + 标注）。
3. 数据说明栏：注明"历史命中率不代表未来收益"。
**验收**: 命中率计算与人工抽样一致；分模型/评级统计正确；复盘页按日期浏览。
**文件**: `backend/api/v1/ai.py`(新端点), `backend/eval_track.py`(新), `frontend/js/components/ai-page.js`

#### FR-3.17.7 — 盘中增强：异动扫描 + 事件提醒（P1，实时化 P2）
**现状**: 数据为日线收盘级；无盘中/事件维度。
**需求**:
1. **异动扫描器**（离线日线级，P1）: 全市场筛选当日涨停/跌停、量比>2、振幅>8%、连板≥2 的个股，按策略池/自选过滤，一键加入评估。
2. **事件提醒**（P1）: 自选/持仓股关联事件（业绩预告/解禁/高送转/龙虎榜/融资融券异动），站内 + 飞书提醒。
3. **实时行情 WebSocket**（P2，若 Tushare/akshare 可达则落地）: 自选/持仓股盘中报价推送、涨速/放量预警。
**验收**: 异动扫描结果与数据源一致可筛选；事件提醒在数据可达时触发；WebSocket 为可选里程碑。
**文件**: `backend/scan_engine.py`(新), `backend/event_alert.py`(新), `backend/api/v1/market.py`, `frontend/js/components/research-page.js`

### 主题三 · 快（体验卓越）

#### FR-3.17.8 — 移动端一等公民（P0）
**现状**: responsive.css + 底部 TabBar + 触摸/触觉反馈，但为"降级适配"。
**需求**:
1. 移动端三大高频任务可用：**看日历池 → 看个股体检 → 看 AI 评估**（含 AI 复盘阅读）。
2. 触屏手势：列表左滑=加入自选/删除，下拉刷新（数据源最新），长按=快捷评估。
3. PWA 补强：缓存名与版本联动、核心页面离线可读（日线缓存+评估历史）、安装引导。
4. 移动端首屏性能：日历列表虚拟滚动已就绪，补齐懒加载与骨架屏。
**验收**: 375px 视口三高频任务可完整操作；PWA 安装/离线可用；Lighthouse 移动性能 ≥ 70。
**文件**: `frontend/css/responsive.css`, `frontend/js/components/calendar-page.js`, `ai-page.js`, `stock-detail.js`, `sw.js`, `manifest.json`

#### FR-3.17.9 — 性能与加载体验（P1）
**现状**: 首屏依赖同步串行加载多个模块；大列表已接虚拟滚动。
**需求**:
1. **首屏关键路径**：日历池数据与静态资源并行加载，消除串行阻塞；评估历史/问股历史等懒加载。
2. **图表性能**：K 线大数据量下开启 ECharts 采样/降采样；复用 `_klineRegistry` 缓存避免重绘。
3. **骨架屏**：日历/自选/复盘页接入统一 loading 骨架（复用 qc-state-panel）。
**验收**: 首屏可交互时间较基线提升 ≥30%；5000+ 行情点图表渲染不掉帧；骨架屏三处接入。
**文件**: `frontend/index.html`, `frontend/js/app-logic.js`, `frontend/js/charts.js`, `frontend/js/components/state-panel.js`

#### FR-3.17.10 — 个性化与搜索（P2）
**现状**: 命令面板 Ctrl+K 三域检索已有；无布局/视图偏好记忆。
**需求**:
1. **个性化偏好**：默认视图（日历日/周/月）、默认主题、图表周期偏好，按用户持久化（data/users/<name>/preferences.json）。
2. **搜索增强**：支持股票拼音/首字母检索、策略名模糊检索、评估记录关键词检索（结果直达详情）。
3. **收藏夹直达**：首页"最近查看/收藏"快捷入口。
**验收**: 偏好切换后重启保持；拼音首字母检索可用；搜索结果可直达目标页。
**文件**: `frontend/js/components/command-panel.js`, `frontend/js/app-logic.js`, `backend/api/v1/user_config.py`

### 主题四 · 健（架构健康）

#### FR-3.17.11 — 前端架构收敛与内联样式治理（P0）
**现状**: `app-logic.js` ≈116KB；767 处内联 `style=`；fetch 鉴权两套；主题三套；空壳死代码。
**需求**:
1. 巨型文件拆分（目标单文件 JS ≤30KB 语义边界）：`app-logic.js` 按域拆分（watch/副作用编排、全局快捷键、qcState 组装），保持 `window.createAppLogic` 对外签名不变。
2. **内联样式治理**：767 处 `style=` 收敛到 CSS 类（≥60% 迁移），新增代码禁止内联（CI grep 拦截）。
3. fetch 鉴权统一走 `core.apiFetch`，移除 index.html monkey-patch 或委托。
4. 主题应用收敛单一 `applyTheme`（以 themes.js 为权威）；删除空壳 `calendar.js`/`strategies.js`。
5. 清理 `[DEBUG]` console.log 与 print 调用（后端 print 改 logging）。
**验收**: app-logic.js 拆分后各文件 ≤30KB；内联样式计数下降 ≥60%；鉴权/主题各单一实现（脚本断言）；后端 print 计数下降 ≥80%。
**文件**: `frontend/js/app-logic.js`(拆分), 各 page/dialog 组件, `frontend/js/core.js`, `themes.js`, `backend/*.py`

#### FR-3.17.12 — 可观测性与运维体验（P1）
**现状**: 指标仅内存累计；无日志聚合；无 Prometheus；部署/升级手工同步。
**需求**:
1. **指标导出**：`/api/system/metrics` 增加 Prometheus 文本格式（/metrics 端点），含请求量/延迟/错误率/数据源健康/调度器任务状态。
2. **健康面板升级**：系统配置 → status 增加调度器任务运行时间/最近成功时间、数据源延迟趋势、备份最近成功时间。
3. **一键升级**：运维文档 + 脚本化升级（`scripts/upgrade.ps1`：同步代码→保留 data/.env/.venv→重启→健康检查），替代手工 robocopy。
4. **告警完善**：调度器任务连续失败、备份失败、覆盖率门禁、磁盘剩余空间告警（飞书）。
**验收**: /metrics 可被 Prometheus 抓取且字段完整；健康面板显示任务/数据源/备份状态；升级脚本在 dev/ops 各演练一次成功。
**文件**: `backend/api/v1/system.py`, `backend/metrics.py`(新), `backend/scheduler.py`, `scripts/upgrade.ps1`(新), `frontend/js/components/system-page.js`

#### FR-3.17.13 — 多用户隔离与数据一致性收敛（P1）
**现状**: 聊天历史硬编码 `username="default"`（所有用户共享）；同数据 SQLite 与 JSON 双写。
**需求**:
1. **聊天历史按用户隔离**: `chat_history` 表与 RAG 上下文均按当前用户；历史数据迁移（default → 各用户归属或保留为共享只读存档）。
2. **存储收敛**: 用户/聊天/自选/评估统一走 SQLite 为主，JSON 仅作导出/兼容回退，消除双写不一致。
3. **限流可扩展**: `SimpleLimiter` 预留 Redis 后端接口（实现可选，先抽象接口 + 单机默认）。
**验收**: 两个用户互不可见对方聊天历史；同一数据读写不再出现 SQLite/JSON 不一致；限流接口可插拔（配置切换）。
**文件**: `backend/api/v1/chat.py`, `backend/db.py`, `backend/rate_limit.py`, `backend/user_manager.py`

#### FR-3.17.14 — 国际化与文案规范（P2）

**需求**:

2. 核心界面文案抽取到语言包；金融术语保持中文主语言精确性。
3. 文档/报告模板双语可选（复盘报告推送语言可选）。
**验收**: 切换 en 后核心页面可读；zh-CN 回归无缺词；默认语言不影响现有用户。
**文件**: 新增 `frontend/js/i18n.js` + `locales/zh-CN.js`/`en.js`, 各组件文案抽取

## 5. 用户与使用场景

### 5.1 目标用户
- **C1 量化研究型散户**: 关注策略池、回测、多因子、胜率追踪 → 3.17 的"实/智"。
- **C2 上班族看盘用户**: 移动端 + 复盘 + 异动提醒 + AI 摘要 → 3.17 的"快/智"。
- **C3 多用户团队（自托管）**: 数据隔离、运维、开放 API → 3.17 的"健/开"。

### 5.2 核心使用场景（User Story）
1. 作为 C1，我每晚查看 AI 复盘 + 当日评估命中率，调整次日策略池。
2. 作为 C1，我在策略总览一键回测"多因子策略近一年"，看到收益曲线与最大回撤。
3. 作为 C2，我在手机上看到异动预警，点开个股体检，长按加入自选并发起 AI 评估。
4. 作为 C1，我把持仓录入模拟组合，看组合收益曲线与行业集中度，AI 给出风险诊断。
5. 作为 C3 管理员，我给同事签发 API Key 拉取日历数据，并收到复盘 Webhook。

### 5.3 关键体验指标（北向指标）
- 日活路径完成率：看盘→选股→评估→复盘 闭环完成率（打点）。
- 评估胜率（FR-3.17.6 上线后）提升为正反馈指标。
- 移动端会话占比提升。
