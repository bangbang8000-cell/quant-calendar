## 1. 需求一：买卖信号更平民化简约化（信号 + 仓位 + 置信度，再详情）

### 1.1 需求解读
「直接给出买卖信号、仓位建议、置信度评估分三个值即可，然后再进行详情数据展示」= 一层渐进披露（progressive disclosure）的决策卡：主卡三值（方向/仓位/置信度），点击展开详情。这是 C 端产品正确的信息架构。

### 1.2 合理性评估

**产品视角（合理）**：降低认知门槛、一眼可决策，符合「平民化」定位。渐进披露与现有「评估」页的分层思路一致。

**量化视角（方向对，关键难点在置信度）**：
- 置信度不是拍脑袋打分，必须**可校准**：信号的历史胜率/准确率分桶 → 校准概率。项目已有基础：AI 评估历史 + /api/openapi/winrate 胜率统计 + factor_ic 体系，可支撑「按 score 分桶 → 历史兑现率 → 校准置信度」的闭环。
- 校准标准：Brier score / 可靠性图（reliability diagram）；目标不是置信度高，而是「置信度 0.7 的事件真的约 70% 兑现」。
- 方向信号需要**时间语义**：信号有效期（当日有效/持有 N 日）、触发条件（价格/形态）、失效条件。

**合规视角（红线，务必重视）**：对不特定公众提供「买入/卖出」具体指令，落入证券投资咨询业务范畴（《证券法》第 160 条、《证券、期货投资咨询管理暂行办法》），无牌照主体直接输出买卖指令有合规风险。现有产品用「评估/参考/风险提示」措辞是刻意的安全设计（全站统一「评估」术语、有测试守护 test_terminology_unified.py）——**平民化 ≠ 荐股化**：信号卡建议用「参考方向 + 参考仓位 + 置信度（模型一致度）」语义，配免责声明，勿改造成荐股定位。

### 1.3 现状对照（v5.3.15 已具备 vs 缺口）

**已具备（backend/prompts/evaluate_stock.txt 输出契约）**：
- 9 维度评分（0-100）→ total_score
- level 五档：强烈推荐/推荐/谨慎推荐/中性/观望（含颜色）
- position_advice：分持仓/空仓两种状态的 ≤25 字仓位建议（如「32.50附近建仓3成」）
- sniper_points：ideal_buy / stop_loss / take_profit 三个具体价格
- signal_attribution：技术/基本面/资金流贡献度 + 最强多/空因素
- data_quality_note：数据时效感知

**缺口**：
1. 无显式三态方向信号（买/持有/卖）——level 五档是「推荐强度」不是「方向」
2. 无置信度字段（total_score 是复合得分，不是校准概率）
3. 无信号时效（有效期/触发/失效条件）
4. 无简化展示层（三值卡 + 详情折叠；当前是完整评估报告）

**工作量估算**：输出契约扩展（方向/置信度/时效）2 天 + 置信度校准模块（胜率分桶 v1）2 天 + 简化信号卡 UI 2-3 天 + 测试/门禁 1-2 天 ≈ **1 周内可完成 5.4.0 主体**。

## 2. 需求二：数据计算频次更高（hour / 15min / 5min，理想 1min / 秒级）

### 2.1 需求解读
「不仅仅是 T+1 粒度，最好有 hour 粒度、quitter 粒度、five minute 粒度，如果可以 minute 和 second 粒度更好」。
注：**「quitter」应为「quarter」笔误 = 15 分钟（一刻钟）粒度**。需求本质是：计算与信号频率从日线提升到日内多档。

### 2.2 合理性评估（关键：区分「数据频率」与「信号频率」）

**作为信号频率——不合理，三个硬约束**：
1. **T+1 制度**：A股当日买入次日才能卖出，日内信号（分钟/秒级）无法同日兑现收益。纯日内策略在现货股票上不可落地（可转债/跨境ETF/股指期货才 T+0）。
2. **成本吞噬**：A股单边成本 ≈ 佣金 0.01-0.03% + 印花税 0.05%（卖出）+ 滑点 1-3 跳 ≈ 0.1%~0.15%；5 分钟 K 线的单根典型波动仅 0.1-0.3%——信号在低粒度上赚的钱大部分被成本吃掉。回测规范（quant-backtesting）要求把成本翻 3 倍仍盈利才算数。
3. **噪声与伪信号**：分钟级 IC 通常远低于日线级，多重检验下假信号暴增；分钟级因子衰减极快（分钟级 alpha 生命周期远短于日线级）。

**作为数据频率/盘中参考——合理**：更高频数据用于「盘中择时确认」「异动监控」「风控（盘中止损参考）」「行情展示」是明确有价值的，也是用户直觉所在（盘中想看到变化，而不是等收盘）。

### 2.3 可行性评估（数据源矩阵，A股分钟级）

| 粒度 | 数据源 | 历史深度 | 门槛 | 300 池年存储* | 全市场年存储* | 可行性 |
|------|--------|---------|------|--------------|--------------|--------|
| 60min（4根/日） | tushare pro stk_mins（积分≥2000）；akshare 东财分钟 | 数年可拉（积分够则全历史） | 中 | ~0.3M 行 / ~8MB | ~5M 行 / ~130MB | ★★★★ 先行 |
| 15min（16根/日） | 同上 | 同上 | 中 | ~1.2M 行 / ~30MB | ~21M 行 / ~500MB | ★★★★ 先行 |
| 5min（48根/日） | 同上 | 同上 | 中 | ~3.5M 行 / ~85MB | ~64M 行 / ~1.6GB | ★★★ 试点 |
| 1min（240根/日） | tushare pro（积分≥5000）；akshare 东财（历史深度受限） | 受限 | 高 | ~17.6M 行 / ~430MB | ~320M 行 / ~8GB | ★★ 仅展示 |
| tick/秒级 | 免费源仅实时快照（新浪/腾讯），**历史需 L2 付费** | 无免费历史 | 高 | — | — | ★ 仅实时展示，无回测数据 |

*估算口径：244 交易日/年，OHLCV+code+ts ≈ 20-25B/行 parquet 压缩。全市场 = 5530 只（scan_engine 实测收敛基准）。

**API 拉取成本**：全市场分钟数据 ≈ 5530 次/日/粒度 的行情调用（受 tushare 每分钟限额约束，拉全市场分钟级每日需数小时）；300 池只需 300 次/日/粒度 ≈ 分钟级完成。**需求 3 是需求 2 的经济性前提。**

**现有架构缺口（代码实证）**：
- strategy_sdk/data_portal.py：仅 daily 批量面板（5530 只 × 3 接口/日）
- /api/market/kline：仅 daily/weekly/monthly
- scan_engine：日线级异动扫描
- 回测引擎（strategy_sdk/backtest.py + backtest_oos）：日线事件驱动
- 已有日内能力：shortterm/intraday.py 6 时点快照（09:25/09:35/10:00/11:30/14:00/15:00，情绪级）；market_ws QUOTE_PUSH_INTERVAL=15s 实时报价推送（自选池）

**新增工作量**：分钟 bar 管道（拉取→parquet 存储→交易日历对齐→复权）3-5 天 + 分钟因子计算 2-3 天 + 分钟回测验证 3-5 天 + 盘中调度 1-2 天 + UI 2-3 天 ≈ **2 个点版本**。

### 2.4 分阶段建议
- **5.4.2**：60min/15min 数据管道 + 盘中参考信号（只展示、不输出交易指令；把现有 15s WS 报价推送用于盘中卡）
- **5.4.3**：5min 试点（限 300 池内），先做分钟级 IC/回测验证（成本翻 3 倍纪律），验证通过才升级为信号
- **明确不做**：1min/秒级策略信号（T+1 + 成本 + L2 数据费三重否决）；1min 仅用于 K 线展示

## 3. 需求三：300 只精品股集合（人工筛选，月/季更新）

### 3.1 需求解读
「5000 股没必要全搞，人工筛选出 300 只在这里做量化评估，其他一律不考虑；按月或季度更新集合数据」。与量化大佬交流所得——本质是 **investable universe（可投资域）收敛**，这是机构的标准实践。

### 3.2 合理性评估（★★★★★ 三个角度都成立）
1. **数据/算力收敛**：5530 → 300 ≈ **1/18**。分钟级数据从 GB 级降到百 MB 级、API 拉取从数小时降到分钟级、因子计算与 AI 评估（8+ 模型）成本同比例下降。与需求 2 形成闭环。
2. **质量提升**：天然剔除仙股/流动性差/财务风险标的，信号质量与回测可信度提升（小票的流动性幻觉和操纵噪声是回测最大的隐性污染源）。
3. **代码已有同向先例**：scan_engine 已将 pool=all 从「全市场 5530 只」收敛为「策略池→配置池」；数据门户按日全市场批拉——收敛方向已被验证。

### 3.3 陷阱与对策（量化严谨性核心，这部分决定了「合理」能否成立）

| 陷阱 | 说明 | 对策 |
|------|------|------|
| **幸存者偏差（最重）** | 用「现在精选的 300 只」回溯历史 = 系统性高估收益（当年不在池里的差股被剔除） | **池必须时点化（PIT）**：池成员带生效日期与版本，回测只用「当时在池」的股票。项目已有 PIT 纪律（V5.1 数据中台），可复用。**不做 PIT 的 300 池 = 回测全失真** |
| **人工筛选不可复现** | 「人拍脑袋选 300 只」不可审计、无法回测、易带风格漂移（只挑景气赛道 → 风格切换后团灭） | **客观规则初筛 + 人工微调**：流动性（日均成交额 > 5000 万，与 risk 模块既有下限一致）、市值下限、财务质量、剔除 ST/退市风险、行业覆盖均衡（30 行业左右）；规则写死并版本化，人工只做最后微调并记录理由 |
| **换池偏差（追涨杀跌）** | 月度换池若「剔除跌惨的、纳入涨疯的」= 动量追高系统偏差，等于把均值回归的收益让出去 | 换池依据**事前规则**（流动性骤降/ST/财务暴雷/行业再平衡），不以「近期涨跌」为由换池；**建议季度更新**（与财报季一致），月度太频繁且放大偏差 |
| **池内中性化失真** | 截面因子/IC 计算若只在 300 池内做，行业/市值中性化失真（截面样本不足） | **全市场日线数据保留**（5530×244×~8 字段 ≈ 1300 万行/年，几个 GB，成本低）用于 IC/中性化/基准；300 池只收敛「分钟级高频 + 精细计算」。「5000 股没必要全搞」对高频计算成立，对日线截面研究不成立 |
| **漏选/黑马** | 固化 300 只 = 池外机会永远错过，且池内股票「被选中」本身成动量因子 | 加**观察池**（候选 50-100 只，规则自动生成），月度审视一次 |
| **与现有「股票池」概念混淆** | 现有股票池 = 策略持仓池（新入/当前/出池，日/周/月/年视图，v5.3.13 评估修复）；300 精品池是**计算域**概念，两者并存不冲突：计算域=精品 300，展示域=策略持仓池 | 命名区分（如「精品池」vs「持仓池」），文档/UI 术语不混用 |

### 3.4 实现建议
- 数据结构：pool.json（version / effective_date / rules / members[{code, name, added_at, reason, removed_at}]）——版本化 + 时点可回溯，天然支持 PIT 回测
- 管理页：池成员 CRUD、增删原因记录、版本对比（v1 vs v2 差异）、观察池列表
- 数据管道：分钟级批拉只对池内；日线全市场保留（中性化/基准用）
- 更新节奏：季度 + 规则驱动 + 人工确认；每次更新生成池快照（供回测 PIT 引用）
- 工作量：数据结构 + 规则初筛脚本 2-3 天 + 管理页 2-3 天 + PIT 接入回测 2 天 ≈ 1 个点版本

## 6. 附录：量化估算

### 6.1 数据量
- 行数公式：股票数 × 每日根数 × 244 交易日/年
- 5min 全市场：5530 × 48 × 244 ≈ **6,480 万行/年**（≈1.6GB parquet）；5min 300 池：≈ **350 万行/年**（≈85MB）
- 1min 300 池：≈ **1,760 万行/年**（≈430MB）；全市场 1min ≈ 3.2 亿行/年（≈8GB，明确不做）
- API 调用：分钟批拉 300 池 = 300 次/日/粒度（分钟级完成）；全市场 = 5530 次/日/粒度（数小时，受限额约束）

### 6.2 置信度校准（v1 → v2）
- v1（快）：历史 AI 评估按 total_score 分桶（如 80+ / 70-79 / 60-69 / 60 以下）→ 统计各桶后续 N 日实际上涨概率 → 桶概率 = 置信度
- v2（稳）：规则信号用同法；对预测分布做可靠性图 + Brier score 校验，校准不达标（Brier 高于基准）则置信度降级显示「低」
- 数据来源：AI 评估历史记录 + /api/openapi/winrate + 行情兑现（现有体系可直接计算）

### 6.3 术语
- PIT = Point-in-Time（时点化）：任何回测/统计只用当时可得信息与当时池成员
