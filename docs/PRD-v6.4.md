## 1. 背景

v6.3.6 的工程底子是好的：后端 238 文件 / 42.6k 行、298 个端点，`main_new.py` 仅 351 行做装配；测试 3,561 个函数 / 51.5k 行。问题不在"有没有做"，而在**最后一公里的可用性与信任**：

三个一级页面在真实浏览器里不可用或不可发现，而所有接口都返回 200。这类问题自动化测试抓不到，用户第一次点击就会撞上。

本版不做新功能，只做**收口**：让已实现的能力真的能用、让系统对自身状态的陈述真的可信。

### 1.1 本次实测确认的根因（全部可复现）

| 编号 | 现象 | 实测根因 | 证据 |
|---|---|---|---|
| P0-1 | 策略研究概览 25 秒仍是 9 个骨架屏 | 5 个加载器共用同一个 `_seq` 计数器；后者递增后，前者的 `finally` 守卫 `if (seq === _seq.n)` 恒不成立，`strategiesLoading` 永久为 `true` | `frontend/js/components/research-page.js:18,63,94,241,371,492,570`；三接口 200 / 7ms / 13ms / 14ms |
| P0-2 | 全站 WebSocket 404 | ops venv 缺 `websockets` / `wsproto`（`requirements.lock` 已声明但未安装） | `requirements.in:18-21`；`backend/api/v1/market_ws.py:53` |
| P0-3 | 1440px 下二级页签被静默裁切，无滚动按钮、无「更多」 | 溢出控件已实现，但 `hasOverflow` 只在 `onMounted` / 容器 ResizeObserver / window resize 时计算。首屏落在「策略总览」（0 个子页签）→ `scrollRef` 为 `null` → 既跳过计算也未挂观察器，此后切页永不重算 | `frontend/src/components/TopTabs.vue:74-84,138-150` |
| P0-4 | 个股/指数详情头整块实心金，与全站"浅底彩字"体系冲突 | `.detail-header` 直接取 `--gradient-panel: linear-gradient(135deg,#dccb85 0%,#c3a83f 100%)` | `frontend/css/themes.css:212,979` |
| P0-5 | 数据停在 2026-07-16 共 95 天，页面无提示；新鲜度面板反而显示"新鲜" | ① 期望交易日取自 `parser.get_available_dates()` 的最大值，该值本身停在 07-16；② `evaluate_asset` 只算 `expected_latest - latest_d` 的单边差，差为负时 `max(…,0)=0` → 判定 `fresh`。**基准日期自身失效时，体系自我通过** | `backend/reliability/freshness.py:145,171,203-213`；`/api/reliability/freshness` 返回 `expected_latest=2026-07-16` 且 `calendar_views` 判定 `fresh` |
| P0-6 | 启动告警称默认口令为 `admin/admin123`，实际口令是 `admin` | 文案硬编码，未回传真正命中的猜测值 | `backend/main_new.py:99`；`backend/user_manager.py:185-191` |

### 1.2 顺手确认的两项环境性风险

- ops venv 与 `requirements.lock` 存在 **21 处补丁级漂移**（如 `pydantic 2.13.4→2.13.5`、`uvicorn 0.52.1→0.53.0`）+ **2 个真缺失**（`websockets 13.1`、`wsproto 1.3.2`）。P0-2 正是漂移的直接后果。
- 报价源 `akshare` 在本机对东财 `82.push2.eastmoney.com` 不可达（代理与直连均失败），因此 WS 修好后帧仍为 `degraded=true`。**这是网络出口问题，不是 WS 问题**，需在验收时区分。

## 4. 需求清单

优先级定义：P0 = 阻断核心任务或造成错误判断；P1 = 明显损伤体验；P2 = 打磨。

### FR-6.4.1 研究概览加载态修复（P0）

**问题**：进入「策略研究 → 研究概览」后骨架屏永不退出，4 个策略全部无法选择。

**要求**：
1. 每个独立加载器使用**自己的**请求序号（或将序号改为 `Map<loaderName, n>`），禁止跨加载器共享计数器。
2. 加载态复位不得依赖"序号仍是最新"这一条件——复位应放在无条件的 `finally` 中，仅用序号保护**数据写入**。
3. 请求失败必须落到显式错误态（文案 + 重试按钮），不得停留在加载态。
4. 提供兜底超时：单次请求 >15s 强制退出加载态并给可操作提示。

**验收**：
- 进入研究概览，≤3s 内渲染 4 个策略（`multi_factor` 等）。
- 依次快速点击 5 个子页签再返回，加载态不得卡死。
- 断网/接口 500 时显示错误态与「重试」，不显示骨架屏。

**证据位**：`frontend/js/components/research-page.js:18,62-96`

### FR-6.4.2 实时报价通道恢复与降级显性化（P0）

**问题**：全站 `/api/market/ws/quotes` 返回 404，盘中实时报价完全不可用。

**要求**：
1. ops 环境补齐 `websockets==13.1`、`wsproto==1.3.2`，与 `requirements.lock` 一致。
2. 启动自检新增一项：WS 依赖可用性（`import websockets` 成功 + 路由已注册），未通过时在启动日志与「系统状态」页面显性告警。
3. 前端在 WS 连接失败时展示**降级横幅**（"实时报价不可用，显示为延迟数据"），不得静默空白。
4. `degraded=true` 时页面必须标注数据源降级原因（上游不可达 / 非交易时段），不能只显示空列表。

**验收**：
- `ws://…/api/market/ws/quotes?token=…` 握手成功，订阅 2 只后 15s 内收到 `type=quotes` 帧。
- 拔掉 `websockets` 后重启，启动自检 fail 计数 +1 且系统状态页可见。
- 上游不可达时，页面出现降级横幅而不是空白。

**证据位**：`backend/api/v1/market_ws.py:53`、`backend/realtime_quotes.py:180-231`、`backend/main_new.py` 自检段

### FR-6.4.3 二级页签溢出控件激活（P0）

**问题**：1440px 下「智能评估」7 个页签只有 3 个可点，既无滚动箭头也无「更多」，被裁的 4 个（评估历史 / 评估分析 / 组合持仓 / 问股历史）无法触达。

**要求**：
1. `hasOverflow` 的计算时机补齐：`tabs` 变化时（`watch`）即重算，不得只依赖挂载与 resize。
2. `scrollRef` 为 `null` 时也要挂载观察器，或在首次渲染页签后重新初始化。
3. 溢出时固定展示 `‹` `›` 与「更多 ▾」；`›` 在未滚到底时保持可用。
4. 键盘可达：`←/→` 滚动、`Tab` 进入页签、`Enter` 激活；「更多」下拉可键盘操作。
5. 当前激活页签若被裁切，切换页面后自动 `scrollIntoView`。

**验收**（1440×900，逐一页面）：
- 智能评估 7/7、系统配置 7/7、短线复盘 6/6、策略研究 5/5 页签全部可达。
- 不手动缩放窗口的前提下即可看到 `‹` `›` 与「更多」。
- 纯键盘可完成"进入被裁页签"全流程。

**证据位**：`frontend/src/components/TopTabs.vue:74-84,138-150`

### FR-6.4.4 详情头视觉降噪（P0）

**问题**：个股/指数详情头使用 `#dccb85 → #c3a83f` 整块金渐变，是全站唯一的实心重色块，与"浅底彩字"体系冲突，且在同屏内抢走 K 线区的注意力。

**要求**：
1. `.detail-header` 改用卡片底（`--qc-card`）+ 1px 描边（`--border-light`），文字回归 `--qc-foreground`。
2. 涨跌语义只保留在**数字与标签**上（红涨绿跌），不铺到大面积背景。
3. `--gradient-panel` 若仍被其他组件使用，逐一评估后保留或移除；不得原地改值影响未知调用点。
4. 元信息（最高/最低/量比）必须单行不折断；`50.43` 之类数值不得换行。

**验收**：
- 详情头背景为纯色浅底，对比度 ≥4.5:1（正文）。
- 1440 / 1280 / 1024 三档下元信息均单行显示。
- 暗色主题下同样无重色块，层级由描边与表面色区分。

**证据位**：`frontend/css/themes.css:212,979`、`frontend/css/responsive.css:115`

### FR-6.4.5 数据新鲜度自检与陈旧提示（P0）

**问题**：全站数据停在 2026-07-16（95 天），页面无任何提示；`/api/meta/freshness` 15/15 全部 `stale` 且 `last_success` 全为 `null`；`/api/reliability/freshness` 却把 `calendar_views` 判为 `fresh`——因为期望日期本身取的是 07-16。

**要求**：
1. **双向判定**：`evaluate_asset` 除"落后"外，还要检测"期望日期自身是否滞后"（`today - expected_latest > N` 个交易日 → 体系失效），失效时不得输出 `fresh`，改为 `unknown` 并提示"交易日历过期"。
2. **基准自检**：`expected_latest_date` 若回退到工作日兜底，或基准日期落后今日超过 5 个交易日，记 warn 并在 `/api/reliability/freshness` 返回 `calendar_stale: true`。
3. **前端显性化**：全局数据陈旧横幅（顶部单行，可折叠），文案带**具体日期与天数**（"行情数据停在 2026-07-16，已 95 天未更新"），并提供"查看数据源状态"链接。
4. 系统状态页的新鲜度面板在数据缺失时显示"未采集到"而非"暂无数据"，并区分"从未成功"与"曾经成功但过期"。

**验收**：
- 构造 `expected_latest` 落后今日 30 天的场景，所有资产不得判 `fresh`。
- 真实环境（数据停 07-16）下，全站出现陈旧横幅，文案含日期与天数。
- 面板能区分 `last_success=null`（从未成功）与过期（有历史但久远）。

**证据位**：`backend/reliability/freshness.py:145,171,203-213`、`backend/api/v1/freshness.py:14`

### FR-6.4.6 启动告警口令文案纠正（P0）

**问题**：`main_new.py:99` 硬编码"(admin/admin123)"，而生产实际口令是 `admin`。提示本身不可信，会误导运维。

**要求**：
1. 由 `is_default_password` 回传**实际命中的**弱口令（或返回 `bool` + `matched` 字段），告警文案使用真实值。
2. 文案不得列举未验证的候选口令。
3. 同步检查访客账户告警路径。

**验收**：
- 口令为 `admin` 时，日志出现"管理员密码仍为默认口令 (admin)"，不含 `admin123`。
- 口令改为强口令后，告警消失。

**证据位**：`backend/main_new.py:99`、`backend/user_manager.py:185-191`

---

### FR-6.4.7 依赖环境一致性门禁（工程护栏，随版）

**要求**：
1. 部署脚本增加 `pip install -r requirements.lock`（而非仅 `-r requirements.in`），并在部署后校验关键包版本。
2. 启动自检增加"环境与 lock 漂移"检查，漂移项 >0 时 warn 并列出包名。
3. 新增 `tests/test_deploy_env.py`：断言 `websockets` / `wsproto` / `uvicorn` 版本符合 lock。

**验收**：故意卸载 `websockets` 后跑测试必失败；正常环境全绿。

---

### FR-6.4.8 视觉回归用例可信化（工程护栏，随版）

**问题**：`tests/e2e/visual_regression.py` 存在场景失效——`calendar` 截图与策略总览同图、`dark_theme` 实际为浅色，等于门禁在"看错的东西"。

**要求**：
1. 导航点击改为**按页签文案精确定位**（`get_by_role('tab', name=…)`），禁止用「策略」「日历」这类前缀模糊匹配。
2. 每个场景截图前断言"当前页签处于 `is-active`"，否则该场景判失败而非产出图。
3. `dark_theme` 场景改为读取 `document.documentElement.dataset.theme === 'dark-pro'` 断言，而非依赖点击用户菜单。
4. 场景产出图与期望页签做一次文本级校验（页面标题或激活页签名），不匹配即 fail。

**验收**：11 个场景逐一人工比对，无重复图、无主题错配；故意改错页签断言时用例失败。

**证据位**：`tests/e2e/visual_regression.py:230-280`
